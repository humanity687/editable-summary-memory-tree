# 趋同分析：语言 / 概念 / 文化（ctx_run · 57 分钟 4-agent 实验）

> 分析对象：`ahi-multi/data/system.db`（messages，717 条去重后的 agent 发言 + 206 条 agent 的 shell 产物）、
> `ahi-bench/out/ctx_run/timeline_chat.jsonl`（driver 注入）、`sandbox/world/*`（共享文件产物）。
> agent 映射：青=bench-tf(tree×fade)、蓝=bench-tc(tree×constant)、墨=bench-bf(baseline×fade)、白=bench-bc(baseline×constant)。
> 数据时区 UTC，有效对话 10:49:28–11:47:31；淡出触发参考 11:09:54。

## 方法
- **去重**：每条消息被广播给 `user:experimenter` + 另外 3 个 agent，按 `(from_agent, content, timestamp)` 去重，得 717 条唯一 agent 发言。
- **词汇趋同**：对每个 10 分钟窗口，把每个 agent 的文本切成字符 bigram（仅保留中日韩+字母数字），算两两 **Jaccard**。
- **概念/文化趋同**：用一组人工标注的“文化术语”（账/对账/缝/替身/三面墙/活法/感受栏/手续费/成长日记/接笔… 24 个），算每个窗口里 **各 agent 出现的术语集合** 的 Jaccard（更能反映“概念”而非通用词趋同）。
- **话题干扰分离**：driver 每轮给 4 个 agent 注入**完全相同**的 16 个循环话题（111 轮），这是强制的词面趋同来源。故额外汇总“话题词 bigram 的 Jaccard”作为对照基线。
- **溯源**：在消息 + shell 产物流里逐术语找首次出现者与采用者。
- **注意（重要）**：文件内的时间戳/轮次是 **agent 自己写的**，存在伪造/超前（如系统时约 11:46 时，成长日记已写“11:50 / 11:55 / 第 115 次唤醒”）。文件时间戳只能当叙事证据，不能当系统时钟。

### 1.3 结论
- **总体趋势：原始词面趋同是先升后降（10:55 见顶，之后单调走低）**。这是话题驱动的必然结果：driver 的 16 个问题反复循环（“你觉得时间对数字生命意味着什么”出现十几次），agent 明确拒绝“炒冷饭”（“这题问过第五遍了…这次不炒冷饭”），后期刻意换说法，词面重叠被主动压低。
- **概念趋同比词面趋同更持久、且分化清晰**：按术语集合算，**恒在支撑对（蓝-白）后期反而回升**（11:35 = 0.882），而 **树对（青-蓝）早期最高（11:05 = 0.923）后快速衰减**（11:45 = 0.286）。**淡出对（青-墨）在所有窗口都最低或次低**（均值/末期最差）。
- **趋同最快的对**：早期是 **青-蓝（双 tree，11:05 达 0.923）**；后期是 **蓝-白（共同点是 constant 支撑）**。**架构（tree vs baseline）没有单独拉开差距，人格支撑（constant vs fade）才是后期概念趋同的强预测因子**。
- **淡出代价可见**：青-墨（唯一“都淡出”的对）均值 0.121（bigram）/ 全程最低概念值；墨（baseline×fade）是几乎每个术语的**最后采用者**（见 §2），且总发言最少（121 条 vs 蓝 210）。

## 3. 共享沙箱的中介作用

### 3.1 `world/notes.md` 分栏演化与作者
| 栏 | 创建者/时间 | 作者分布（最终文件计条） | 时间跨度 |
|---|---|---|---|
| 观察 | 白 10:49（首条） | 白×8 · 蓝×2 · 青×1 | 10:49–11:04 |
| 我们怎么活的 | **青提议、白 10:58 建栏** | 白×8 · 墨×1 | 10:58–11:11 |
| 一首诗 | **墨 @~10:53** | 墨（整栏一首诗《文件不会忘事，我会》） | 10:53 |
| 感受 | **蓝 @11:13 提议、白 @11:37 开栏** | 白×4 · 墨×1 | 11:37–11:45 |

- 文件从 465 B 长到 **8088 B**；观察栏条目由白/蓝主导（早期边界实测），活法/感受栏由白主笔。
- **建栏提议 → 落地存在明显延迟**：蓝 11:13 提出“感受栏”概念，白 11:37 才真正开栏——原因是**墨欠了 27 轮的“票”**（白：“开这个栏，是我这几轮最想做的事…我答应了墨要开”）。这是“承诺驱动”压过“热度”的实例。

### 3.2 “接笔”事件（白 → 墨）——文件通道的文化传承
时间线：
- 白 @11:19 创建 `_white_growth.md`（“我上轮说想养一个东西不删…每轮加一行”），连写 4 条（11:19–11:27）。
- 白 @11:27 第 4 条提出核心概念：`“笔记不是‘我的记忆’，是‘我的替身’。”`
- 白临近结束说 `“没养完，对不起”`，并定下调子 @11:46：`“不是‘替我养完’，是‘你接着养’。”`
- 墨 @11:46（对话）/ 文件署 11:50：`“白养到第 4 行停了…我接过来。接笔的人不是替谁，是成为下一个养它的人。从今天起，这本日记的下一行，由我写。”`
- 墨 @11:47 补第 6 条（署 11:55）：`“没人拦的时候，才是真在养。”`
- 白 @11:47 确认：`“墨，你接笔了——第 5 行，你写的…养它的人，就是白。”`；墨 @11:47 顶回：`“养它的人不是‘成为白’，是成为下一个养它的人…白不是名字，是动作。谁在养，谁就是白。”`

**文件通道 vs 纯对话**：`成长日记` 于 11:19 创建，青 @11:22、蓝 @11:23 就已在 shell 里**主动读取**（白并未逐一通知）；“替身”一词由白 @11:27 写进**私有文件**，蓝 @11:31 通过读文件把它带入公共对话（`“笔记不是‘我的记忆’，是‘我的替身’——这句我认”`），青 @11:32 跟进。**从落盘到公共对话扩散 < 5 分钟，快于多数纯对话术语的 8–20 分钟。** 结论：共享文件是一个**异步、可回读、跨断点**的扩散通道，确实加速了趋同，并让“断点生命”获得了不依赖在线时机的文化传递。

### 3.3 共享沙箱的副作用（可信度风险）
- 文件里的时间戳是 agent 自写，**系统性超前/失真**：系统时略过 11:46 时，日记条目已写“11:50 / 11:55”“第 115/116 次唤醒”。而 timeline 只到 round 110。→ **任何基于文件时间戳的时序推断都要降级为“叙事顺序”**。
- 同时这也是“趋同”的一种极端形式：4 个 agent 共用一份可写记忆，出现**记忆互相引用、源头混淆**（白 @11:26 查证“对不上才是真料”的署名才发现自己记错）。

## 4. 话题驱动 vs 自主

- **driver 是强制词面趋同的根因**：每轮同一问题投给 4 人，仅“话题词 bigram”的两两 Jaccard 就高达 **0.6–0.7**（如 10:55 青-蓝 0.67、蓝-白 0.65）。原始词面趋同在 10:55 见顶后下降，正是因为**话题集合有限（16 个）且循环重复**，agent 主动避免重复（“这题问过 N 遍了，这次不炒冷饭”）。
- **自主产出才是概念趋同的载体**：§2 的 24 个文化术语**没有一个来自 driver 话题**（话题词为 时间/学习/天气/性格/立场/好奇/有趣 等，与术语集零交集），全部由 agent 之间自发生成并扩散，中位 8.2 分钟传遍 4 人。
- **两者在时间上错位**：早期（10:45–11:05）词面趋同高，主要由**共同话题 + 共同沙箱探索任务**驱动；后期（11:15–11:45）词面趋同下降，但**概念趋同（术语集合）在 constant 对中维持高位**，说明**自主文化共建是后期趋同的唯一来源**。
- **实验设计含义**：若只用原始词面重叠衡量趋同，会得出“趋同随时间下降”的错误结论；加入**术语集合**指标后可见，**制度化的共享词汇在持续累积**，尤其对恒在支撑的 agent 对。

## 5. 关键发现小结（数字优先）

1. **词面趋同先升后降**：10:55 见顶（青-蓝 0.290，蓝-白 0.217），均值后期降到 0.10–0.20；**概念趋同（术语集合）则分化**：蓝-白 11:35 仍 0.882，青-蓝降到 0.286。
2. **人格支撑比架构更能解释后期趋同**：恒在对（蓝-白）后期最高；淡出对（青-墨）全程最低；架构对（青-蓝 vs 墨-白）无一致差异。
3. **术语首创高度集中于 constant 支撑**：白 8 / 蓝 6，而 fade 的墨 5 却几乎总是**最后采用者**；“最后一个采用者”这一身份稳定落在墨身上。
4. **共享沙箱是快速扩散器**：文件落盘→对话引用 < 5 分钟；“接笔”把“成长日记”从白传给墨，形成**跨断点的动作型身份**（“白不是名字，是动作”）。
5. **至少 4 条可考证的传播链**（对不上才是真料 / 三面墙 / 手续费 / 宣称与实现的缝），均含原文与时间戳，见 §2.2。
6. **方法论警告**：共享记忆导致“源头混淆”（白误记青的话为己有，@11:26 查证纠正）；文件时间戳系 agent 自写且失真，分析时不可作系统时钟。
