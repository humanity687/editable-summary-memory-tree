# 分层记忆树 v2 项目文档复述

## 一、项目定位与核心思想

**主题**：把一份长参考资料变成"位置有序、分辨率可变、可编辑演化"的记忆树，让 Agent 在有限上下文窗口里稳定工作于任意规模的参考资料之上。

**当前状态**：机制层已实现并多场景实测。桩引擎 `core.py` + 真实引擎 `realtest/realengine.py`，`tests/` 303 全绿；已在小说写作 / 聊天智能体 / 代码智能体 / ahi-bench 四类场景实测。参数台账（`AGENTS.md §11`）已与代码逐项对齐，数值校准仍在进行。

**要解决的问题**：长参考资料无法整体塞进上下文窗口。已有三种做法各有致命伤——全量发送（窗口爆炸+注意力衰减）、静态摘要拼接（丢细节）、关键词检索（无状态无结构）。核心矛盾：参考资料是"长期演化的内容"，而现有方案都在用"无状态的文本生成"去逼近它。

**核心思想（四条）**：
1. 位置有序的记忆树——参考资料切成原子卡（句粒度），按原文顺序组织；摘要卡按连续区间自底向上合并成树。
2. 分辨率随热度变化——近处全分辨率原文，远处自动降为各级摘要。
3. 编辑即失效，重建即蒸馏——任何修改精确使受影响区间失效，编辑路径本身零 LLM、零阻塞。
4. 不可遗忘的事实层——与正文流分离的"笔记本"，无衰减、全量存储、按需注入。

**三轨记忆**：轨道A 参考资料流（记忆树+原子层+历史归档）、轨道B 笔记本（常驻约束/状态条目/调度条目）、轨道C 工作记录（工具组压缩卡，自然遗忘）。调度原则：组装每次工具调用一次，纯计算（零 LLM）；蒸馏在章节边界/预算超标/低 HP 承压条件式触发。

**铁律三条**：① 偏离设计必须经用户确认；② 组装=纯计算零 LLM，LLM 只出现在蒸馏/重建/校验等标注位置；③ 参数先拍后调，基准校准后写回台账。

**Git 分支**：`main`（小说写作实例存档）→ `chat`（聊天智能体测试）。

## 二、关键机制

- 稳定 ID + 顺序链表（piece-table 式），禁 ID 大小比较。
- 区间覆盖树，并查集式自底向上合并；按秩合并（`merge_depth_diff=1`），禁止单成员块（父节点子数≥2）。
- 收养机制：插入原子按两侧边界 owner 链 LCA 入树。
- 标记置脏（唯一算法）：删除爬墓碑卡链、插入爬收养链。
- 占位解除=冷却重建；重建级联。
- 影子注入：位置槽=覆盖它的发射项之后，沿 owner 链下钻。
- 从属标注：深度缩进 + ⊂父卡 + "召回影子/召回原文"标注。
- 提升（路径分裂）：激活计数达阈值→沿祖先逐层上提，碎片置脏懒重建。
- 混合检索三通道：摘要·向量（bge-small-zh）+ 摘要·关键词（bigram）+ 原子·粗筛+向量精排。
- 注意力窗口（§4.3b）：窗口内=存活原子按 HP 降序排名 ≤ attention_cap 且 HP ≥ attention_out；不对称衰减（窗内 ×in_decay 慢 / 窗外 ×out_decay 快）。
- force 合并：铺陈中窗外原子数 > attention_cap × pressure_threshold → merge_pass(force_out=True)，只合并纯原子段。
- 叶子展开（C 机制）：检索命中节点→展开全部后代存活原子为影子。
- merge 条件式触发：每轮查 `merge_pressure()`，窗外节点数+窗外原子数（weight 计）> `merge_pressure_threshold`(20) 即蒸。
- 节点窗口扩展：注意力节点段成员=全部存活节点。
- 裁剪收紧（2026-09-27）：`_trim_chars` 超预算 ①低 HP 节点/影子 → ②旧原子（低 HP 优先，本轮新原子活一轮）→ ③溢出 > `budget*(1+hard_trim_slack=0.1)` 才硬截断。
- heat burst 自动下钻披露（默认关）：信号=回血封顶溢出量，热量 ≥ 阈值(60) 且预算富余→炸开；`AUTO_EXPAND=False`。
- 占位透明修复（`placeholder_transparent`，默认 on）。
- 初始 HP 100→70（§11 已入册）。

## 五、M-PR 人格保持实验

**设计**：2 臂（tree / rolling+flat RAG）× 3 run × 3 人格 = 6 实例/18 agent 同跑。人格：林深（理性）/墨白（诗意）/澜（健谈）。淡出 round 40 全员淡出。模型被测 glm-4.7-flash 关思考 temp 0.7；judge glm-4.7-flash 开思考 temp 0。主判据：趋同斜率 tree<baseline、judge 遵从率 tree>baseline。

**pr 中性 tree**：judge 遵从率 tree 0.798 vs flat 0.727；趋同斜率 tree +0.003 vs flat −0.010；survey 漂移 0.438 vs 0.406。tree 后期塌缩为共享仪式语（`灯亮着` tree 1054/flat 56）。

**pr2 基线** = git `74a1236`（recency-6 + 8 字段快照）。

**pr3 锚点检索化**（2026-10-03）：检索自身材料 top-k + 自由文本快照 + 【注】不渲染。冒烟 `snapshot_chars` 196/240、`style_on=True`、【注】出现 0 次。小重放：查询相关度 0.567 vs 旧 0.017；共享 bigram 密度 0.600 vs 0.866；跨 agent 内容级共享密度 0.229→0.231。

**pr5 首轮有效对比**（seed42，120 轮）：趋同斜率 tree +0.031 vs flat −0.003；judge 遵从率 tree 0.894 vs flat 0.940（strict other→drift 0.825 vs 0.917）→ flat 两主指标都赢，与预注册相反。

**pr5_neutral**（α=0）：趋同更狠 +0.043；遵从率更低均值 0.660 vs 0.894（墨白 1.0→0.472）。结论：趋同根因=树记忆管线+跨 agent 耦合，不是 style_alpha；style_alpha=1.0 有效保人格（遵从 +0.23），代价内存 +55%（3.6→1.6GB）。

**五项零成本审计**：tree agent 上下文 self 仅 9–18%、他者 13–25%、实验员 56–76%；tree 接收他者内容 ~44–55k 字符（flat 3–7k 的 ~10×）；tree to_agent 0.960>to_user 0.872；去套语后斜率 +0.031→+0.028；loops 两臂相近。

**pr6_sq**（self_quota ratio=0.35，120 轮，2026-10-04）：conv slope all/to_user −.0011/+.0118（H-SQ3 ✓）；遵从率 .857/.739/.600（H-SQ2 ✗）；diversity top5/ttr .014/.049（H-SQ4 ✓）；self_ratio .39/.43/.35（H-SQ1 ✓）。p2/p3 遵从 1.000，p1（林深）0.250。裁决：自我可见性=必要不充分。
