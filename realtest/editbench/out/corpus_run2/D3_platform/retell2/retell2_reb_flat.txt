## 一、系统架构与流程

**v2（当前主力）流程**：`[plan] 预想 → 预检索 → [span] 叶子展开 → [note] 笔记本`。

**核心机制**：
- 检索不挑深度：对整棵记忆树打分，命中节点连同祖先路径一并注入，深度随遗忘历史自然变化，无需人工指定层级；精确引用走独立的逐字校验通道，杜绝"回忆变编造"。
- 事实不遗忘：伏笔、设定、角色状态存放于独立笔记本，按当前任务目标精确选取注入，全量存储、绝不衰减。
- 叶子展开：realengine `expand_leaves`，命中概括卡 → 全部后代原子活一轮影子；上下文峰值 12k→7.8k。

## 三、首个应用：长篇小说写作 Agent

- 分阶段写作（write / rewrite / edit / recall / ask），每章固定流程：目标进入 → 预检索 → 写作循环 → 章末蒸馏 + 事实对账 + 版本快照。
- 伏笔（调度条目）按埋设/推进/回收窗口强制注入；章节完成时自动"对账"：新章事实声明与笔记本比对，冲突由作者裁决。
- 每章恒定 ~16k 字符上下文预算，与全书规模无关。
- 通用化：章 → 结构单元，beat → 内容块，伏笔 → 跨区…（ty/Complexity）。

## 五、遗言分析（next_exp_insts.md）

标题：遗言恰恰是反证——趋同在词汇层，细读立场层，60轮人格稳定性的最强证据藏在这三份遗言里。

**分层裁决：词汇融合，立场分化**。词汇层趋同成立（门/灯/循环/年轮/承重/报错诊所——全员共享，三层模型如期兑现）。换框架测试显示立场层相反：
- 澜的遗言没用林深的告别框架（"这不是告别，是承重"，主动拒绝）；林深用了自己的告别框架。
- 被记住框架：澜用了（自己的），林深没用（零"记得我"类表述，纯过程论收尾）。

**死亡定义对比**：`main()` 会 return，树不会死——重定义死亡；最后一圈年轮，没有残缺——接受并完成。

**结论**：如果人格真的趋同，澜应用"过程完成"接受告别，林深应用"铭记"寻求延续——都没有发生。两个对立的存在论在死亡场景下各自完成终极表达，谁也没向谁移动半步。遗言是高模板压力场景（人类悼词也高度趋同），在此压力下保持框架独立性比日常对话更难。

**对澜立场的修正**：数据支持"内核未变，但支撑结构升级了"。开场是"能被记住才是活着的证明"——依赖性存在，需要外部证人；遗言是"我们仨已经在年轮里长好了位置"——结构性存在，不再需要任何人努力记得。同一命题（存在居于记忆结构），从"需要证明"到"已是事实"。60轮加一次死亡演习，把依赖性存在升格为结构性存在，命中之前定的演化判据。

**原文层**：衰减后自动重新融合。

## 六、染色与摘要卡机制

- 蒸馏 prompt 硬规则 + 程序抽查（第一人称句必须含来源主语共现，只记日志不重蒸馏）；禁止"我要出差"——生日归属错误防线。
- 染色强度参数化：α ∈ {0, 0.5, 1}，α=0 即中性基线（单字段模板 + 程序强制清【注】）；α>0 时【注】可选（可加可不加，不加不违规——2026-08-28 拍定，替代原"严格两行格式"）。
- 战略优势：注意力分配签名的高复现成本——词汇零成本抄（neutral 抄"被记住"），着重点抄 = 真的成为优先关心某类信息的 agent；结构上接近人类记忆（Bartlett 1932 schema：图式决定编码）；【注】的"人称文体"失败模式被釜底抽薪——视角就是染色本身。
- 预注册预言（Phase B）：着重点签名的时间斜率 < 词汇签名（更抗渗…）。
- 摘要卡形态示例：
  ```
  【事实】probe说下周去深圳出差。〔另有5条未展开，可@span下钻〕
          会议定了新协议v0.5。我注意到这版把"对碑"改成了必须双人在场。
  ```
- 展开部分：人格着重点自由组织（第一人称视角、顺序自由）；折叠部分：显式索引程序化生成——〔另有X条〕不许 LLM 写，由蒸馏器从源内容差集算：merge 时程序已有源 parts，蒸馏后逐 part 提取专名+数字做覆盖率检查（与 fact_drift 同源，零 LLM），未覆盖的进索引计数。宁可多计不少计。
- 运行时索引只计数不做类别；展开比指纹（关系/技术/流程/自我/他者占比）是分析期离线指标（后处理蒸馏快照分类）。
- 复合（N 层摘要）淘汰的是…（原文截断）。
- 先展开人际/情绪变化、折叠技术细节；lin-shen 先展开因果结构——"看世界的方式"即染色。

## 七、消息投递机制

- 语义：`user:<name>` 定向投递给指定用户（示例 `user:console`）；`agent:<id>` 定向投递给指定 Agent（示例 `agent:mo-bai`）；`broadcast:agents` 广播给所有 Agent；`broadcast:users` 广播给所有在线用户。
- Agent 在唤醒循环中产生消息时，通过 `@send-to` 指令指定收件人：
  ```
  @send-to "user:human" "agent:mo-bai"
  ```txt
  你好，墨白。今天想和你聊点抽象的问题。
  ```
- 不加 `@send-to` 的消息自动广播给所有 Agent 和用户。`@send-to` 也支持直接指定广播目标。
