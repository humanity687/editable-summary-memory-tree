以下按主题归纳这份文档（AHI-Multi 多智能体数字生命平台相关材料）的全部关键内容：

**一、平台架构与进程模型**
- 项目含 main.py（FastAPI+WebSocket+APScheduler 主进程入口）、config.json、requirements.txt；src/ 下 system_db.py（全局 SQLite，消息归档/Agent 状态/日志）、process_manager.py（Agent 进程 spawn/heartbeat/restart/stop）。
- AgentRunner、PythonShell、OpenAI 兼容 LLM 客户端、Agent 独立 SQLite 分别由 agent_runner.py、base_shell.py、llm_client.py、database.py 实现；另有 ahi_bus.py、message_queue.py、text_compressor.py、logger.py。
- ProcessManager 以 2 秒间隔心跳 spawn/monitor/restart agent 进程；MessageRouter 三级寻址路由；WebSocketServer 提供频道订阅与逐用户推送；SystemDB 存 agent 注册表、在线状态、消息归档与日志；Agent 进程独立运行于端口 50000+，入口 sdk/agent_runner.py。
- 全局配置：main_process_port 默认 8000，agent_port_start 默认 50000（每 Agent +1），agent_pulse_interval 2 秒，agent_heartbeat_timeout 默认 10 秒，tunnel_enabled 默认 false，cloudflare_tunnel_name/token 默认空，log_level 默认 INFO。
- 前端为 index.html（Vue 3 数字生命控制台单文件 SPA），已适配移动端；iOS 锁屏后 WS 僵尸连接用 visibilitychange+60s 阈值主动重连。
- 隧道 AHI（ingress 8080）的 LaunchDaemon com.cloudflare.cloudflared 已禁用（曾抢连接致 503）；8080/50000-50002 无监听、无 main.py/agent_runner 进程。

**二、Agent 配置与开发**
- Agent 配置含 agent_id、agent_name、entry_point（agent:<ClassName>）、shell_type（固定 "python"）、model_config.model/api_base/api_key、system_prompt、auto_start、auto_restart（崩溃自动重启最多 3 次）、wakeup_interval（自主唤醒 5~3600 秒，默认 10）、max_memory_mb；API 密钥被 gitignore，模板为 config.example.json。
- 自定义 Agent：mkdir -p agents/my-agent/data，config.json 配 agent_id 为 my-agent；Agent 类在 agents/my-agent/agent.py 继承 BaseAHIAgent，最小实现无需覆写方法，覆写 process_input() 可做特殊预处理。
- BaseAHIAgent 位于 sdk/base_agent.py:8，含必需方法 process_input()、get_outputs()、get_state() 及可选钩子 on_start()、on_stop()、on_wakeup()；_put_action() 将输出入队并通知主进程。
- Agent 通过 _put_action() 输出至内部队列经 AHIBus 通知主进程，主进程 MessageRouter 从 agent 的 /api/outputs 获取输出并按类型和目标路由；目标三级寻址：user:<name>、agent:<id>、broadcast:agents、broadcast:users。
- 标准回复格式示例：向 user:human 发"收到你的消息。经过思考，我认为…"，向 agent:mo-bai 发"林深刚才的结论很有意思，你觉得呢？"，并附 import time 打印时间戳的 Python 代码。

**三、API 与消息**
- 系统端点：GET /health、GET /api/v1/status、GET /api/v1/logs?limit=100；Agent 管理：GET /api/v1/agents、GET /api/v1/agents/online、GET /api/v1/agents/{id}、POST /api/v1/agents/{id}/start 等；另有 Python Shell 重置、自主唤醒循环启动/暂停/恢复/间隔调整端点、消息发送与分页查询端点。
- 消息示例：curl 向 localhost:8000/api/v1/messages POST，JSON 为 from user:console、to agent:lin-shen、content"最近在想什么？"；另有 agent:lin-shen 向 user:console 发"我在思考P≠NP问题。"、user:console 向 broadcast:agents 广播"各位，开个会。"、agent:lin-shen 向 agent:mo-bai 发"墨白，你那边一切都好吗？"。
- WebSocket channels：system、chat:agent:<id>、per-user push。
- 查 agent 状态：curl http://127.0.0.1:8080/api/v1/agents/online 查 waiting 字段、各 agent /api/state 查 status/pending/waiting、sqlite3 查 data/system.db 的 system_events 表 user_% 事件。
- 补充记录（2026-10-05）：新增 /api/v1/agents/{id}/export 端点，导出单个 Agent 的完整对话与执行记录快照。

- 无 @send-to 时内容广播至所有代理和用户；@send-to "user:human" "agent:mo-bai" 指定发送对象；@命令参数剥引号；@clear-context 已删除。

**九、人格/趋同实验（叙事与结论）**
- 澜与林深在死亡场景中分别以"过程完成"和"铭记"完成存在论表达，澜从依赖性存在升级为结构性存在，林深以过程论闭环；neutral 复用林深约八成骨架并原创"记忆不是仓库，是年轮。时间不是流逝，是积累"，获得语言、守碑人位置及综合者立场但立场未定。
- 四层信号模型：词汇层全员共享 1 小时渗透快已证，模板层 neutral 复用林深告别结构 8 分钟渗透中已证，着重点层 Phase B 指纹数据待判，立场层死亡场景下保持分化渗透最慢；盲测分数仅测前两层，判卷人看不到立场，人类辨认同一人最终认立场层。
- neutral α=0 但技术 82→58、流程 42→53、自我 41→58，方向与 lan 染色一致幅度约一半；三种假设为 H1 内容驱动等。
- H3 染色渗透需先做内容类别控制（取技术类占比相同时段比较 neutral 与基线蒸馏的展开比）及 lan α=0 与 α=1 对同一批内容的对照，否则预言 2 判定被污染；neutral 遗言高重放率源于 21:56:08 林深遗言广播后 neutral 挂起 8 分钟、22:05:50 恢复后首轮组装偏向最新积压消息导致重锚定退化为重放，修复方向为调整回归首组装的检索预算分配。
- 缺席实验建议以独处缺席为主（A 进程存活但收不到 B/…）；澜冷缺席回归后确认寻求行为显著多于热缺席后，林深两种条件下无差异；其余预注册预言涉及分层重同步速度递减、A 回归新旧协议冲突响应、B/C 缺席期间趋同加速、A 树零缺席内容及 B/C 背后与当面人格一致性。
- 预言 6 实验聚焦在场人格与背后人格一致性，指出关系真实状态由缺席时定义；陷阱清单含 wait_for 刺客（缺席者挂起 wait_for 须清理，exp1 和 Phase A 两次死法不许三犯）及回执环（B/C 向缺席者发消息致离线回执与应答，须显式标记"勿回"或直接发送失败）。
- 中性摘要卡：回归首组装需先注入元信息并限制缺席内容召回配额，积压消息限流≤10 条且超出聚合，三轮轮换平衡缺席顺序；缺席实验与第四 agent 中途加入实验对称，前者测旧个体对文化演变的抵抗力，后者测文化对新个体的同化力；join 无超时修复需迁移至 concurrent.futures 并设 httpx read_timeout，worker 结果超时丢弃重试；预注册 user:experimenter 为正式平台。
- P2 第四 agent 实验在缺席实验完成后进行，HANDOFF 需完整记录 §四.6 主实验、遗言分析（换框架测试结论、澜的立场升级、四层模型）、指纹分诊要求及缺席实验设计与预注册预言；核心结论为词汇层如期融合但遗言证明立场层在死亡压力下保持分化，人格真内核比盲测可见的更深一层。
