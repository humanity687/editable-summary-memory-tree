这是一份关于**通用“参考资料”上下文管理机制**的设计文档，长篇小说写作是其第一个应用实例。

## 主题与核心思想
解决长参考资料无法整体塞进有限上下文窗口的问题。现有做法失效：全量发送会爆炸、静态摘要丢细节、关键词检索无状态演化。核心思想四条：①**位置有序的记忆树**——参考资料切成原子卡（句），稳定 ID + 顺序链表维护顺序，摘要卡按连续区间自底向上合并成树，树任一节点 = 某连续区间的概括；②**分辨率随热度变化**——近处（当前工作区）全分辨率原文，远处降为各级摘要，只保留专有名词、因果链、关键原句，越老越粗但越稳定；③**区间失效 + 懒重建**——编辑覆盖区间精确失效旧内容，脏卡立即排除出查询，重建推迟到蒸馏时机（零 LLM 即时编辑路径）；④**不可遗忘的事实层**——正文流分离的“笔记本”，无衰减、全量存储、按需注入，负责跨区引用（伏笔）与硬约束。

## 通用化映射
小说语境→通用语境：一句话概述→全局摘要；卷/章→结构单元；beat（叙事节拍）→内容块；伏笔（调度条目）→跨区引用账本；角色状态（状态条目）→事实条目；章节目标（扰动源）→当前任务目标。

## 架构
三轨记忆（当前=进程内 + gzip/JSONL 快照；SQLite 为规划目标）：轨道A 小说内容（参考流）＝记忆树 + 原子层 + 归档（版本谱系）；轨道B 笔记本（事实层）＝常驻约束/状态条目/调度条目；轨道C 讨论内容（工作记录）＝工具组压缩卡，自然遗忘。

## 关键设计原则
- **简洁**：机制数量少、语义单一，一机制服务多类对象（如注意力窗口同时服务原子与节点）。
- **涌现**：目标特性从机制交互中自然出现（层级沉淀、热区消退、优先级分化），写死特判前先问能否由既有机制参数化表达。
- **判据**：硬规则是最后手段，优先调参数或推广既有机制，其次才引入新机制，最后才写死特判。
- 反面教材（2026-08-29）：节点不受注意力保护→统一快衰减→9 轮归零→无限上并→99% 历史压进 1-5 个大节点（组装退化成“两段式”）。教训：对象类别间衰减待遇不对称会杀死层级涌现。
- **策展定律**（2026-10-04，M-PR 三次重复）。

## 关键条目与参数
- **self_quota**（2026-10-04，默认关的实验操控）：组装层“自我可见性地板”，保证 `source=="ai"` 原话（不含 persona/tool/他人）占组装预算 ≥ `self_quota_ratio`（cap `self_quota_max`），trim 后补足，位置序注入（kind=`self_quota`，复用 core `_shadow_slot`，渲染成正常自身发言段 `▸〔名字〕`，非“召回”标）。
- **anchor_frac / sq_onset_agent**：0.4 / per-agent(18/5/15)。分层 SQ v2（`PERSONA_RETENTION §10.3.2`）：锚定切片（`created_round < onset` 的 alive 自产原话）占 self 配额比例 / 各 agent 首染 onset（审计①定，clean=round<onset）。
- 已跑 pr6_sq（tree-s42，120 轮）：H-SQ1/3/4 达标，H-SQ2 未达标（回声风险实体化），测“自我模仿→人格保持”因果，非 tree 修复。
- 参数台账（§11 默认值）：m_cap 80 / expand_char_cap 3000 / max_hp 150 / merge_pressure_threshold 20 / max_pending_per_loop 3 / force_cooldown_rounds 8 / max_code_per_loop 4 / distill_parallel 4 / snapshot_every_rounds 20。

## 清单与任务行规则
清单只列“谁发了什么”（已回复信道剔除），任务行只陈述“本轮有无待回复”。禁止正性行动邀请（如“可继续未完成事项”）——它与“看到自己发过、无回合状态”叠加是重复发送的自然吸引子（实测 41 对重复：29 同轮双发 + 8 跨轮重发）。未完成事项应经检索随扰动源自然浮现，不靠空轮指令；行为约束一律只写在协议文本。

## 人格与解耦
澜：健谈、外向，喜欢交流，享受对话本身，主动延伸推进话题；极高探索欲；重视记忆，认为“被记住”是存在感来源，珍惜每次对话，主动确认复述重要细节；风格轻松直接带活泼幽默；相信时间会证明长期记忆的价值。解耦动作（写死进 provision）：删除墨白原文中“与林深共生/林深是你的同伴”等互指（三份人格必须彼此独立）；删除澜原文中的 tree 工具行（`@recall`/`@note`/`@span`…），工具说明统一放 §4 public 提示词；两臂共用同一 3 份 persona_block（人格是控制变量，非自变量）。

## 两臂定义与实现文件
两臂：分层树（tree）与 flat_rag（rolling + bge flat RAG，400 字 chunk / top_k=6 + 每轮 auto-preretrieve + persona 淡出入滚动历史与索引）。实现文件：`provision.py` instances 模式（architecture: flat_rag、per-agent persona、2 臂 × N run × 3 agent、独立沙箱根、写 `manifest.json`）；`config/persona_retention.json`（3 persona + 分臂工具说明 + §6 pinned + judge `pro/thinking` + 臂级 `style_alpha/snapshot_every_rounds`）；`pr_score.py`（趋同斜率 + judge 遵从率，并行 `pro+thinking`）。

## 流程
初始化：详细参考资料按句切分为初始原子卡 + 笔记本条目，落卡后进入正式创作。每章流程：目标进入（章节目标写入扰动源，含本章出场实体列表→驱动轨道B选取）→预检索（章目标→全树 top-k + 逐字通道注入组装流）→分阶段写作循环（write_stage 段落流粒度写入每句原子卡；rewrite/edit 走 §4.6 编辑路径；recall 工具兜底检索；ask 用户反馈→protected 卡）→章末（merge pass 蒸馏+脏重建；事实校验对账轨道B；版本快照 commit）。

## 实现要点
`realengine._summarize` 把当前内容与 children 传给 `style_provider(content, children)`（兼容 1/0 参旧式 provider）；`lan/neutral._style_guide(content, children)` 组锚点 + 累积查询缓冲；`_refresh_snapshot` 自由文本重生成，零 LLM 检索。`retrieve_style_samples`/`expand_self_atoms` 返回文本经 `anchor_clean` 剥掉〔来源/早期/索引〕脚手架标注。纵向对比：`pr`（中性 tree）、`pr2`（recency-6 版）数据保留，检索化版换命名空间重跑对比。

## 测试与基准（§8）
属性测试：①断言（assert）；②铺陈不变量——任意时刻无重叠、无缝隙、按位置序；③编辑边界穷举——书首插入、书尾追加、整块替换、整块删除、跨多节点编辑、区间内含早先中插的编辑、编辑后立即查询（盲区声明）；④区间覆盖——脏节点 span 重建前后一致性；⑤回滚对称性——任意编辑序列+回滚=原状态（内容级断言）。
基准（三组对比：全量发送/摘要拼接/本设计）：①长程一致性（延迟回忆）——固定大纲写 N 章（建议 20）→续写第 N+1 章→检测对第 1 章伏笔/角色引用正确率；②状态一致性——注入事实变更（角色改名/死亡/改名恢复）→检测状态卡更新与后续章节一致性；③token 计量——每章消耗 vs 基线；④人类找茬——读者读 10 章找连续性 bug。

## 评分（score.py，全确定性 + 单点 LLM judge）
机械 gate（任一失败→该 run 作废）：G1 隔离无泄漏——①缺席窗口内留守者收到“你发给 agent:X 未送达”回执数（句首锚定，回执尾部“可用地址”列表含缺席者名不算）；②窗口内 system→缺席者 的非回归通知消息数。

## 纪律
改什么、为什么、影响什么，获明确同意后才可改动本文档并同步代码，禁止擅自修改设计、禁止绕过设计写临时方案。写代码前必须能完整复述设计（§1~§10），不确定先读本文件。组装=纯计算（零 LLM），LLM 只允许出现在明确标注位置：merge 蒸馏、脏节点重建、章末事实校验、初始化对话、检索摘要生成（如启用）。所有参数“先拍后调”，先用 §11 默认值实现，再用 §8 基准校准，结果写回 §11 参数台账并在日志可观测。正确性依赖的边界条件（标记完备性、铺陈不变量、区间覆盖）必须有属性测试，不允许只有 happy path。本项目是通用“参考资料”上下文管理机制，实现时“章/beat/伏笔”字样可替换为通用词（结构单元/内容块/跨区引用）。
