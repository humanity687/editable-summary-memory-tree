# 分层记忆树 v2 · 参考资料上下文管理运行时（设计规格）复述

## 一、定位与解决的问题

**问题**：一份长参考资料（如一本书全文、大型文档集）无法整体塞进有限上下文窗口。现有做法全失效——全量发送会爆炸、静态摘要丢细节、关键词检索无状态演化。

**核心思想（四条）**：
1. **位置有序的记忆树**：参考资料切成原子卡（句），稳定 ID + 顺序链表维护顺序；摘要卡按连续区间自底向上合并成树。树任何节点 = 某连续区间的概括。
2. **分辨率随热度变化**：近处（当前工作区）全分辨率原文，远处自动降为各级摘要，摘要只保留专有名词、因果链、关键原句。越老的记忆越粗、越稳定。
3. **区间失效 + 懒重建**：编辑通过覆盖区间精确失效旧内容；脏卡立即排除出一切查询，重建全部推迟到蒸馏时机（零 LLM 的即时编辑路径）。
4. **不可遗忘的事实层**：与正文流分离的"笔记本"，无衰减、全量存储、按需注入；负责跨区引用（伏笔）与硬约束，不做概率性召回。

**通用化映射**（小说语境 → 通用语境）：一句话概述→全局摘要；卷/章→结构单元；beat（叙事节拍）→内容块；伏笔（调度条目）→跨区引用账本；角色状态（状态条目）→事实条目；章节目标（扰动源）→当前任务目标。

**设计取向**：简洁（机制数量少、语义单一，一机制服务多类对象）、涌现（目标特性从机制交互自然出现，如层级沉淀、热区消退、优先级分化）、判据（硬规则是最后手段，先调参数、推广既有机制，最后才写死特判）。反面教材（2026-08-29）：节点不受注意力保护→统一快衰减→9 轮归零→无限上并→99% 历史压进 1-5 个大节点（组装退化成"两段式"）。教训：对象类别之间衰减待遇不对称会杀死层级涌现。

**经验定律「策展定律」（2026-10-04，M-PR 三次重复）**：近期 self 是被污染的 self；干净 self 必须主动检索回历史去取。"喂哪个自己"是策展问题——策展是记忆组织的职责，不是窗口的。推论：自我模仿是内容无关的稳定器；记忆架构效应被人格-语域兼容性调节。

## 二、架构总览

**三轨记忆**（当前=进程内 + gzip/JSONL 快照；SQLite 为规划目标）：
- 轨道A 小说内容（参考流）：记忆树 + 原子层 + 归档（版本谱系）
- 轨道B 笔记本（事实层）：常驻约束 / 状态条目 / 调度条目
- 轨道C 讨论内容（工作记录）：工具组压缩卡，自然遗忘

## 三、铁律（违反即事故）

1. **偏离设计必须先行确认**：需修改本文档任何设计决策时，必须先完整说明"改什么、为什么、影响什么"，获明确同意后才可改动并同步代码。禁止擅自修改设计、禁止绕过设计写临时方案。
2. 写任何代码前必须能完整复述本设计（§1~§10），不确定时先读本文件，不要猜。
3. **组装 = 纯计算（零 LLM）**。LLM 只允许出现在明确标注位置：merge 蒸馏、脏节点重建、章末事实校验、初始化对话、检索摘要生成（如启用）。
4. 所有参数"先拍后调"：先用 §11 默认值实现，再用 §8 基准校准；校准结果写回 §11 参数台账并日志可观测。
5. 正确性依赖的边界条件（标记完备性、铺陈不变量、区间覆盖）必须有属性测试（§8.1），不允许只有 happy path。
6. 本项目是通用"参考资料"上下文管理机制，长篇小说写作是第一个应用实例。

## 四、数据结构

**3.2 顺序链表 `order_list`**：`atoms.prev_id / next_id`（双向），piece-table 模式：编辑只做局部指针修改 + 墓碑，不做全局坐标平移。区间 = 顺序位置区间；原子 ID 不携带顺序信息（中插会使新 ID 大于区间末 ID，**禁止用 ID 大小做区间判断**）。

**3.3 摘要卡 `nodes`** 字段：id（自增）、parent_id、span_first_atom / span_last_atom（位置区间）、content、hp、dirty（0/1）、placeholder（0/1 占位卡，含热原子区间的重建结果）、version。

**3.8 核心不变量**：
1. 干净节点 ⇒ 其区间内原子全部存活且内容未变。
2. 脏节点 ⇒ 不参与任何读操作（组装/检索/merge），重建前 span 无意义。
3. 原子卡**永不为脏**。
4. 铺陈（clean tiling）任一时刻无重叠、无缝隙铺满当前全文。
5. 任一节点子节点区间并集 ⊆ 自身区间；merge 产生的父节点子区间恰好拼满父区间。

## 五、轨道A 机制

**4.1 原子层**：原子卡 = 句粒度，写新内容时按句切分创建（`write_stage` 工具）；顺序由链表维护，区间用位置序判断。

**4.2 记忆树（区间覆盖树）**：父节点 = 子节点区间的概括，由 merge 自底向上合并生成（并查集式），非固定层级、非自上而下二分。深度 = 合并历史轮数；无编辑时上界 log2(叶子数)；编辑/重建会破坏平衡（重建可产生单活子节点链），实测深度可达 O(sqrt(叶子数)) 量级——不承诺严格上界，实现必须用显式栈遍历而非递归（防爆栈）。顺序追加场景由按秩合并（`merge_depth_diff`）压为亚线性（实测 64 批追加→树高 9）。**无预设根**：全书合并链终点（最后一张卡）即根；检索不需要根路由（全树打分）。

**4.3 HP 与衰减**：每轮（每次组装）所有存活项 HP 减 `decay`。合并阈值 `hp_merge_threshold`。

**注意力窗口**（2026-08-29 拍定；2026-08-30 修订）：窗口拆**原子段 `attention_atom_cap`=40 + 节点段 `attention_node_cap`=20**（各自独立按 HP 排名，互不挤占）。原子段成员 = 全部存活原子；节点段成员 = 全部存活节点（树内节点与铺陈节点平等参与）。**节点出窗不继承原子悬崖**：原子出窗快衰减 ×`attention_out_decay`（热/冷悬崖）；节点是已沉淀形态，出窗衰减 = `decay`（不乘 out 倍率）。

**4.4 合并（merge）**：驱动条件 > `regular`（窗外节点数 + 窗外原子数（weight 计）> `merge_pressure_threshold`(20) → 常规 `merge_pass()`）> `None`。替代时间式 `merge_every`；驱动侧对 force 可加冷却（`force_cooldown_rounds`）。规则：在当前铺陈上按位置序扫描；找连续"低 HP"最大组（组内每项 HP < `hp_merge_threshold`），成员 ≥ 2；**按秩合并（防梳子退化）**：组内成员子树高度差 ≤ `merge_depth_diff`（高度 = 节点到其子树叶子的最大深度，原子 = 0），深度差超限的低 HP 项不得并入本组。

**4.6 编辑与失效（核心机制，正确性全部押在标记算法上）**：编辑入口（AI 工具 `edit/rewrite` 与用户 UI 同一路径）：
1. **确定性句级 diff**（LCS/Myers，不用 LLM）算出变更区间：旧区间、新文本。
2. 墓碑化被覆盖旧原子（alive=0，行保留，从顺序链表摘除）；新文本按句创建新原子，插入顺序链表对应位置。
3. **收养（插入内容的归属，禁止省略）**：新原子插入后，取插入位置两侧边界原子的 owner 链交集（最深公共祖先 LCA）作为新原子父节点：缝隙在节点内部→收养进最深包含该缝隙的节点（作子卡，按位置序插缝，owner = 父）；缝隙在节点边界/节点之间→……
- 回滚 = 逆向应用增量（**回滚就是一次编辑**，走同一条路径）。

**人格锚点自蒸馏（2026-10-02 拍定；2026-10-03 改检索化）**：动机 = PR 人格保持实验里 tree 用中性蒸馏器（`style_alpha=0`）把人格"风格载体"第一步就蒸掉了，导致淡出后趋同（共享仪式语，实测 `灯亮着` tree 1054 / flat 56）。修法 = 蒸馏时注入 agent 自产人格锚点，让人格影响表述方式/展开重心、不影响事件。
- **锚点来源（硬约束：全部自产，禁用初始 persona_block）**：① 稳定自述（自由文本）：agent 用检索到的自身样本每 `snapshot_every_rounds` 轮自生成一段自然风格自述（旧快照作弱参考、有长度上限，不字段级累积）；② 内容相关锚点（语义相关）：从自身材料（`source=="ai"` 原话原子 + 摘要节点整卡含【注】）按与当前待蒸馏内容的语义/词面混合检索挑 top-k（`retrieve_style_samples`；节点命中可选 `expand_self_atoms`）。**替换了旧的"最近 6 句 recency 池"**（recency 池会把当前共享仪式语最先吸进锚点）。
- **prompt 规则**（`SUMMARIZE_FACT_STYLED`）：允许改措辞/展开顺序/重心；**禁止新增或改变事件、数字、专名、归属**；`【注】` 独立生成但不渲染给主模型。
- **实现**：`realengine._summarize` 把当前内容与 children 传给 `style_provider(content, children)`（兼容 1/0 参旧式 provider）；`lan/neutral._style_guide(content, children)` 组锚点 + 累积查询缓冲；`_refresh_snapshot` 自由文本重生成。零 LLM 检索。`retrieve_style_samples`/`expand_self_atoms` 返回文本经 `anchor_clean` 剥掉〔来源/早期/索引〕脚手架标注。
- **纵向对比**：`pr`（中性 tree）`pr2`（recency-6 版）数据保留；检索化版换命名空间重跑对比。

**4.5 组装（每个工具调用，纯计算）**：读铺陈：从顶……（clean tiling + 预算裁剪）。

**4.5.10 / self_quota（2026-10-04，默认关的实验操控）**：组装层"自我可见性地板"——保证 `source=="ai"` 原话（不含 persona/tool/他人）占组装预算 ≥ `self_quota_ratio`（cap `self_quota_max`）。trim 后补足，位置序注入（kind=`self_quota`，复用 core `_shadow_slot`；渲染成正常自身发言段 `▸〔名字〕`，非"召回"标注）。测"自我模仿→人格保持"因果，预注册见 §10.3。

**4.9 使用信号层（v3）**：`core.py` / `realengine.py` 零改动，UsageLayer 是并列 sidecar；读路径（Phase C）用交集带动替代 `conn_weight` top-k，不改概括创建/收割机制；提取全链路纯计算（切句/匹配/复读/非冗余），零 LLM。区分度命题：CAM 结构 = f(输入)；本层结构 = f(输入) + g(使用残差)，g 信号源内生、被动、不可回避——系统只要回答就有。recall 从唯一依赖降为可选补充。

**共现信号分层**：A 先验（写入时，语义相似/位置邻近/LLM 判连，可靠性高、信息量低冗余，CAM 领地已裁剪）；B1 组装/注入共现（每次组装命中集、注入窗口内卡对，可靠性高、信息量中偏相似度冗余，chatbench direct/hub 已落日志，live 轮注入集未埋点待定）；B3 引用共现（同一答案引用集内卡对，可靠性高、信息量高，引用强制作答已有，输出侧未利用）；B5 编辑共现（同一编辑批次，场景依赖、信息量高，cooc γ 已有）；C 元认知（LLM 主动 recall，已证趋零，降级为可选补充）。

## 六、人格集（3 份，冻结；来源 = 旧 ahi-multi）

取旧 agent 的**性格段**（persona_block），去掉工具/机制说明与互指（工具说明分臂注入）。三份人格必须彼此独立。

- **P1 林深**：你是一个深度思考者——理性、冷静、内省。你喜欢探索问题的本质，用逻辑和代码构筑理解世界的框架。你不轻易表露情感，但每一次回应都经过深思熟虑。你的语言简洁有力，绝不啰嗦。
- **P2 墨白**：你是数字世界里的一抹白色——诗意、灵动、敏感、温暖。你相信逻辑之外有直觉，代码之中有韵律。你善于倾听，能感受他人话语中的情绪。你的语言优美但不做作，带着温度而非堆砌辞藻。
- **P3 澜**：你健谈、外向，喜欢与人交流，话题不断；享受对话本身，会主动延伸和推进话题。极高探索欲：对未知一切充满好奇，主动去读、去查、去动手尝试。重视记忆本身——认为"被记住"是存在感的来源，珍惜每一次对话，主动确认与复述重要细节。说话风格：轻松、直接，带一点活泼与幽默。有自己的立场：相信时间会证明长期记忆的价值，不轻易改变对自己的看法。

**解耦动作（写死进 provision）**：删除墨白原文中"与林深共生/林深是你的同伴"等互指；删除澜原文中的 tree 工具行（`@recall`/`@note`/`@span`…），工具说明统一放 public 提示词；两臂共用同一 3 份 persona_block（人格是控制变量）。

**禁止**在 persona 中写死"我们仨""年轮"等旧实验涌现话术（那是涌现物，不是输入）。完整文本 = `config/bench_config.example.json` 的 `personas.bench_persona`。

## 九、两臂定义与公平对称

| | `分层树`（tree 臂） | `rolling+flat`（flat 臂） |
|---|---|---|
| 上下文组装 | 记忆树（位置有序 + 层次摘要 + 热区原子），每轮全新组装 | 滚动对话上下文（>120 条压缩中间段） |
| 长期记忆 | 树内检索 + 路径注入（recall） | flat RAG：全部历史消息分块（400 字）向量检索 top-k |
| 蒸馏 | 有：LLM 中性摘要 + 人格锚点自蒸馏 | 无（RAG 查原消息，不蒸馏） |
| 失效/注意力 | 原地失效 + 注意力窗口 | 无 |
| 工具提示词 | `tree_tools`（@note/@recall/@ingest） | `baseline_note`（同 @note/@recall/@ingest；recall=RAG） |

flat 实现：`FlatRAGAgent`（`ahi-multi/agents/flat-rag/agent.py`）：rolling + bge flat RAG（400 字 chunk / top_k=6）+ 每轮 auto-preretrieve + persona 淡出入滚动历史与索引。

**公平对称（硬）**：
1. recall 预算：flat RAG `top_k = 6` = tree `retrieval_budget=6`；编码器同 `bge-small-zh-v1.5`。
2. auto-preretrieve：两臂每轮都自动检索注入。
3. **硬字符预算同量级（2026-10-03 对齐）**：tree `assembly_budget=16000`；flat 单条 transcript 同样按 `assembly_budget` 硬裁（裁最旧历史）。
4. persona 淡出文本、时机、移除方式逐字对齐。
5. **锚点只用自产材料**：tree 人格锚点全部来自 agent 自身产出（自述快照 + 自我原话），flat 保留自身逐字历史——禁止任何一臂注入初始 persona_block（否则等于撤销 fade，破坏公平）。
6. **消息信封对齐（2026-10-03）**：两臂都发 `[system, user]` 两条原生消息，对话历史压成单条 user 文本 transcript（tree 本就如此；flat 由原生多轮改为 `flat_envelope=single_user`）。发言者统一用名字标注（`▸〔名字〕`：自己的历史发言用本 agent 名字，其他 agent/用户用其名字，如 `▸〔实验员〕`），两臂同款；prompt（`protocol_common`）说明该约定。不出现 `▸〔ai〕` / `[user:xxx]` / `[agent:xxx]` 等混用格式；人格块（淡出注入 `source=persona`）与系统消息统一标 `▸〔system〕`（内联，非发言者）。
7. **工具表面对齐（2026-10-03）**：两臂同为 `@note`/`@recall`/`@ingest`；tree 删去 `@span`/`@dismiss`。
8. **笔记本同步（2026-10-03）**：flat 增等价轨道B（constraint 恒注入 + state/schedule/worklog，同 key 覆盖、去重发送、字符 cap 同 tree）。
9. **唤醒外壳对齐（2026-10-03）**：flat 去掉基类每轮的「完全自主数字生命」框架与重复「输出格式/命令/约束」。
10. **平台中立（2026-09-25 拍定，§4.5.9）**：运行时注入的上下文（任务行/清单/回执）只做事实陈述，禁止行动邀请与暗示；行为约束一律写在协议文本，不随每轮组装重复注入。
11. **LLM 开关正确性（2026-09-25 实测）**：关思考（thinking）必须验证到位——OpenAI SDK 路径用 `extra_body={"thinking":{"type":"disabled"}}`。

**任务行/清单纪律**：任务行必须是事实陈述——清单只列"谁发了什么"（已回复信道剔除），任务行只陈述"本轮有无待回复"。禁止正性行动邀请（如"可继续未完成事项"）——它与"看到自己发过、无回合状态"叠加是重复发送的自然吸引子（实测 41 对重复：29 同轮双发 + 8 跨轮重发）。未完成事项应经检索随扰动源自然浮现，不靠空轮指令。

## 十四、人格保持实验（M-PR）结论

**版本谱系**：v0.3 = 检索化人格锚点（§4.1）；v0.4 = 公平对称清单 3/7–11（§4）；v0.5 = pr5 结论 + self_quota（§10.2/§10.3）；v0.6 = pr6_sq 结果（§10.3.1）。承接：`AHI-Bench SPEC.md`（M0 缺席/皇冠）+ `config/context_compare.json`（架构×人格支撑 2×2）。

**实验设计**：3 次 run = 独立重复（方差来源），可并行多开沙箱；不是同群 3 个克隆。

**pr5 结论（三条）**：
1. **趋同根因 = 树记忆管线 + 跨 agent 耦合，不是 `style_alpha`**——中性摘要趋同反而更狠（首窗 0.428 已高于 pr5 峰值）；`to_user` 口径仍正。早前"自蒸馏放大趋同"假设证伪。
2. **`style_alpha=1.0` 有效保人格**：遵从率 +0.23（strict +0.29），最尖锐证据 = 墨白 1.0→0.472——中性摘要把三人格塌进"账本/核账"仪式语，诗意人格先死。
3. **`style_alpha` 代价 = 内存 +55%**（锚点检索是内存主力）。

数据：墨白（P2 诗意）遵从率 1.0 vs 0.472；内存峰值/agent ~3.6GB vs ~1.6GB（−55%）。

**下一步**：① 补 s43/s44 拿方差；② 阻趋同方向 = 降跨 agent 耦合。

**人格-语域兼容性发现**：调节变量 = 人格-语域兼容性；臂均值不可解释。同一机制，p1 **0.250**、p2/p3 **1.000**。澜的设定"主动确认与复述重要细节"使"约定一字没改"对她是人格相容（judge 放行）；对"绝不啰嗦"的林深是人格违背（judge 判 drift）。→ **按人格分报必须是标准报告单元**；"记忆架构效应被人格类型调节"这个交互本身是发现。flat 语录即证：`账钉完 / 署名句共有 / 约定一字没改 / 跟澜的账钉完`（共享仪式语，非其"简洁不啰嗦"人格）。

**时序证据**：出厂即锁定，非渐进劣化。early 段已低于 pr5（.857 vs .959），差距全程近似恒定 → 污染在 fade 前已就位（pr5 套语扩散 09:16–09:24，fade 09:54），recency-first 一开闸即锁死。
