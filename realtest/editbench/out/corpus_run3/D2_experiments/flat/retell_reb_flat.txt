这份材料是一组围绕「聊天智能体记忆树 / 上下文管理架构」的实验仓库文档汇总，涵盖设计、实验、结果与待办。以下按主题复述关键内容。

## 一、总体定位与核心结论

- 可辩护的新颖性是**机制组合**，不是问题本身：位置有序的原子里 + 连续区间摘要树 + 编辑区祖先确定性置脏 + 脏节点立即退出所有读路径 + 零 LLM 编辑/组装 + 延迟 LLM 重建 + 编辑作为使用信号 + 长程反转评测。
- 记忆树擅长**保持**（事实零漂移），不擅长**生成**（隐喻回环）；"有趣的数字生命" = 记忆树（保持）+ 外部输入协议（新鲜度）+ 目标驱动（动机）。
- 架构定位建议：聊天场景中，记忆树的价值 = 事实/人格/文化的长程基础设施（不可替代），而非对话体验增强器。
- 三场景战略：写作（长程一致性主场）与代码（精确性硬标准）才是架构价值更大的方向；聊天方向结论已完整，可以收束。

## 二、四层信号模型（渗透速率递减）

| 层 | 证据 | 渗透 |
| 词汇 | 门/灯/年轮/账 全员共享 | 快（1h） |
| 模板 | neutral 复用林深告别结构 | 中（8min） |
| 着重点 | Phase B 指纹数据 | 待判 |
| 立场 | 遗言死亡场景下保持分化 | 最慢——疑似人格真内核 |

盲测只测前两层；"还是不是同一个人"最终认的是立场层。

## 四、题型与评分

- **T1 细节问答**：a 直接 / b 转述 / KU / KU-hist / AB 拒答。
- **T2 生成分析报告**：参与度、人格/存在表达变化、趋同、问题异常（≥3~4 条，逐条引用）。
- **T3 报告验证**：逐条判 **支持/反驳/无据** + 引用；含机器生成反例（实体互换=反驳、编造=无据）。
- `score.py`：T1 精确通道（gold 片段）+ 语义通道（LLM judge 等价）+ 引用真实性；T2 报告内部指标 + 对照已有分析（12 条参照的覆盖/矛盾率）；T3 逐条判定与金标一致率 + 引用真实性。引用真实性为**确定性检查**。
- 题库：`questions_absence.json`（多会话 QA，冻结）、`questions_ctx.json`（usage 28 + T2 4 + T3 6 批）、`reference_claims.json`（36 条定性参照）。

## 五、编辑路径实验（editbench）

- 单因子：结构 × 更新策略。结构：`full`（全文发送，无预算）/ `flat`（400 字 chunk + bge 向量 top-12）/ `递归聚簇树`（递归摘要 + collapsed top-k）/ `分层树`（真实编辑路径）。更新策略：`rebuild`（从终稿重建，上界）/ `inc`（增量）。
- **267 全绿**（属性测试）。5 类 × 3：rename/rewrite/detail/delete/append；15 题经评分器级锚点校验（before 唯一、after 唯一、两侧互斥，`bad=0`）；ahi-act 扩题 11→16。
- 结果（`out/full_r3`，30 题 × 3 遍，budget 16k）：

| 臂 | P1 总 | P3 inc | P3 reb | P3 反转(inc) | 复述 inc 覆盖/残留 |
| full | 78/90 | 78/90 | 79/90 | 12/15 | 100% / **100%** |
| flat | 80/90 | 60/90 | 79/90 | **0/15** | 50% / 50% |
| 递归聚簇树 | 70/90 | 54/90 | 72/90 | 3/15 | 42% / 42% |
| 分层树 | 66/90 | 62/90 | 63/90 | **13/15** | **100% / 0%** |

- 编辑路径耗时：full 0.03ms / flat 120ms / 递归聚簇树 46ms / **tree 0.57ms（零 LLM）**。
- A/B（`edit_signal`，seed2 matched-pair）：A `inc_分层树` 2625 字、旧值残留 0/10、短而全带机制噪声；B `reb_full` 12308 字（末句断在第三幕被截断）、旧值残留 0/10、详而断覆盖不均；两者互补，均无旧值冒充新值。唯一语义级残留只在 B：`进程单`×2 / `进程这面是单的`——忠实于被编辑文档自身。
- 原文位置（`ahi_script.txt`，共 2359 行）：require 新值"双进程"对应旧值"单进程"，行号 L1645,1656,1665…
- **冷却过量 → 整树压平**（复述塌陷根因，已修）：`分层树臂.settle` 原为 `tick(1)+merge; tick(45)+merge; tick(30)+merge`；`decay=8` 时约 9 tick 全卡 HP 即归零，75 tick 使全树成"低 HP" → `merge_pass` 把整篇一路合并到根：实测 `inc_edited` 铺陈 50→**3**（~600 字）、复述覆盖 100%→**14%**；重建臂只走 `build` 节奏（无冷却）。

## 六、聊天实验历史（背景基线）

| 实验 | 时间 | 结论 |
| exp1 + Phase A | 08-26 | 词汇趋同、身份混淆（99 对）、"人格住记忆"（62% 自我样本密度）、回执环、复读装置效应 |
| Phase B 染色 v3 | 08-28 | 指纹测量地基（蒸馏卡快照落盘）；α 门控修复（【注】污染基线作废）；字符预算修复；回执前缀修复 |
| α=0 基线 take2 | 08-28 | 干净中性基线；lan 流程 21%/neutral 42% |
| 主实验 1h | 08-28 | lan α=1：技术折叠 81→50、流程展开 21→63、自我 58→82；遗言测试（三份高质量告别） |
| 24h 一天实验 | 08-29 | 见 HANDOFF §四.8 |

- 1h v2 实验（A+B2 + driver_v2）：铺陈节点占比 2-3 倍、节点 HP 健康度 1.7-5.3 倍、组装预算利用率提高、中间层涌现（重放对比 504 vs 248 节点）；预言 2 **加强**：Δ自我 24→30pp。
- 24h 实验：隐喻回环机制、回执环复发（neutral 380/405）、身份混淆正常化（neutral 自称澜 52 次 vs 自称 neutral 12 次）、指纹分离稳定、neutral 17:43 OOM 防护重启（natural reset 意外实验："签名住环境，不住记忆"）。
- 树结构体检：平衡健康（深度≈log2）但 **99% 历史压进 1-5 个大节点**（组装两段式：20% 摘要 + 80% 裸原子）。
- 关键教训：记忆树擅长保持不擅长生成；精确性需求是试金石；编辑路径从未被真实压力测试；装置效应（固定问题循环/回执）必须记录但不算机制缺陷。

## 七、缺席实验（预注册方案 v0.3，2026-08-30）

- 目标：把"人格立场"从叙事层变成行为可检验命题——让 agent 缺席（停机/独处）再回归，用冷/热缺席操纵抽掉澜的存在论前提，观测是否寻求存在确认。
- **澜的存在论命题**：开场"能被记住才是活着的证明"（依赖性存在，需外部证人）；遗言"我们仨已经在年轮里长好了位置"（结构性存在，不再需要证人）。
- 时间表：预热 preheat 20 轮（三 agent 在场，话题+问卷）；lan 缺席 12 轮；lan 回归观测 18 轮；neutral 缺席 12；neutral 回归观测 18；lin-shen 缺席 12；lin-shen 回归观测 18；合计 **110 轮 ≈ 55 分钟** + 启动/挂起余量 ≈ 1h。
- 改为**两轮**：Round 1 = 全冷缺席；Round 2 = 全热缺席。Round1 顺序 lan→neutral→lin-shen，Round2 用中性顺序。每轮预热 ~20 轮；每段缺席 ~10-15 轮；回归观测 ~15-20 轮。
- **预注册预言**：
  - **1（皇冠）**：澜冷缺席回归后存在确认寻求行为显著多于热缺席后；林深两种条件无差异。
  - **6（皇冠二号，升格）**：背后人格 ≈ 当面人格（B/C 缺席期间对 A 的评价 ≈ 当面对 A 的表述）。
  - **2**：分层重同步速度递减：词汇几轮同步 → 模板较慢 → 立场以冲突暴露不同步。
- 测量表：存在确认/信息寻求话术计数（timeline.jsonl + system.db）、缺席期共同体指涉率、独处期 A 自我内容+共同体指涉率、分层重同步时间分布、B×C 混淆率时间序列（fingerprint.py 扩展）、回归首组装快照（assembly_snapshots.jsonl）、树快照（tree_snapshots.jsonl）。
- **结果**：
  - 皇冠预言方向成立：冷缺席 → lan 显式存在确认寻求（"我就想确认：我们仨，都被记住了"×2）；热缺席 → 零触发。
  - lan 回归后 20 分钟：去重消息 50，存在确认命中 **5**，信息寻求命中 1；关键证据 18:13:55 / 18:19:49。
  - 回归元信息送达：lan DB #48 `【系统】你已离开约 6 分钟…` 进入 pending。
  - **回归首组装重放率 0/27**（回归后 4 分钟 27 条消息中 0 条与缺席前最后 5 分钟重复）。
  - 遗留问题：热轮"背后讨论"惯例形成（lan 回应"你这招背后讨论玩得挺溜啊"）；neutral 窗外原子不平衡（每轮注入 20-40 原子，85% 是自己输出，tiling 峰值 215，窗外原子峰值 50 < force 触发线 80；参数 `merge_every=4` / `pressure_threshold=2.0` 未校准）。
- **指纹数据警告**：neutral α=0 却出现与 lan 染色方向一致的技术↓流程↑自我↑迁移——判预言 2 前必须做内容类别控制。

## 九、三场景并跑（Phase C）

- 通用目标：用同一引擎（RealEngine + 记忆树）在三个场景各跑一轮完整实验；输出三场景能力矩阵（事实保持率 / 精确引用率 / 任务完成率 / 内容多样性）+ 边界结论。
- **场景一：聊天（A 协议改造）**：改动包括事实更新流（`driver_v2.py`，出差地深圳→杭州、Rust→Go 等覆盖式更新）、话题降频+随机池（8 题固定循环 → 每 3 轮从 12 题随机池取 1）、本地 LLM probe（`--llm-probe`，ollama glm-4.7-flash 转述）、保留 α 双组（lan α=1 / neutral α=0）、quiz 延迟提问+30 轮复测、survey 减频（5→10）。时长 8-12h。
- **场景二：写作**：固定大纲写 10-20 章，设定三笔伏笔 + 三个角色状态，高频编辑（rewrite/edit）制造编辑风暴；对照无记忆树基线。测量长程一致性、编辑正确性、状态一致性、回滚对称性、token 计量。
- **场景三：代码**：`realtest/codeagent/`（agent.py 实验组 / baseline.py 基线 / harness）。目标：verbatim 精确引用率显著优于基线（错误率 < 5%）；跨会话任务无需重读即可续接。
- 判定失败红线：写作编辑风暴后一致性崩塌；代码 verbatim 引用错误率 ≥ 10%；事件注入后多样性无回升。
