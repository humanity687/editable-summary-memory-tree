# 分层记忆树 v2 · 参考资料上下文管理运行时 —— 全文档复述

## 一、主题与定位

**核心主题**：把一份长参考资料变成"位置有序、分辨率可变、可编辑演化"的**记忆树**，让 Agent 在有限上下文窗口里稳定工作于任意规模的参考资料之上。

**当前状态**：机制层已实现并多场景实测。桩引擎 `core.py` + 真实引擎 `realtest/realengine.py`，`tests/` **303 全绿**（2026-10-04）；已在小说写作 / 聊天智能体 / 代码智能体 / ahi-bench 四类场景实测。参数台账（`AGENTS.md §11`）已与代码逐项对齐，数值校准仍在进行。

**核心思想四条**：
1. 位置有序的记忆树——参考资料切成原子卡（句粒度），摘要卡按连续区间自底向上合并成树。
2. 分辨率随热度变化——近处全分辨率原文，远处降为各级摘要。
3. 编辑即失效，重建即蒸馏——编辑路径本身零 LLM、零阻塞。
4. 不可遗忘的事实层——"笔记本"：无衰减、全量存储、按需注入。

**三轨记忆**：轨道A 参考资料流（记忆树+原子层+历史归档）；轨道B 笔记本（常驻约束/状态条目/调度条目）；轨道C 工作记录（工具组压缩卡，自然遗忘）。

**调度原则**：组装 = 每次工具调用一次、纯计算（零 LLM）；蒸馏 = 章节边界/预算超标/低 HP 承压条件式触发。

**铁律三条**：① 偏离设计必须经用户确认；② 组装 = 纯计算零 LLM；③ 参数先拍后调，基准校准后写回台账。

**Git 分支**：`main`（小说写作实例存档）→ `chat`（聊天智能体测试，本阶段工作分支）。

## 二、要解决的问题与已有做法缺陷

| 做法 | 问题 |
|---|---|
| 全量发送 | 窗口爆炸，"塞得下"≠"记得住"（注意力衰减） |
| 静态摘要拼接 | 丢细节，无法承载状态演化 |
| 关键词检索 | 无状态、无结构，片段孤立无上下文 |

**核心矛盾**：参考资料是"长期演化的内容"，现有方案都用"无状态的文本生成"去逼近它。

## 三、关键机制（含参数）

- **近热远粗的上下文**：上下文 = 全局概述层 + 召回路径 + 最近工作区全文原文，预算恒定。
- **区间失效**：任何编辑通过位置区间精确失效旧内容，改动区域从"摘要层"剥落为"原文层"，衰减后自动重新融合。
- **检索不挑深度**：对整棵记忆树打分，命中节点连同祖先路径注入；精确引用走独立逐字校验通道。
- **事实不遗忘**：伏笔、设定、角色状态存于独立笔记本，全量存储、绝不衰减。
- **注意力窗口（§4.3b）**：窗口内=存活原子按 HP 降序排名 ≤ `attention_cap` 且 HP ≥ `attention_out`；不对称衰减（窗内 ×`in_decay` 慢 / 窗外 ×`out_decay` 快）。**注意：`attention_node_cap` 已重命名为 `attention_node_budget`**（20→60 待 sweep）。
- **force 合并**：铺陈中窗外原子数 > `attention_cap × pressure_threshold`(2.0) → `merge_pass(force_out=True)`，只合并纯原子段。
- **merge 条件式触发**：每轮查 `merge_pressure()`，窗外节点数+窗外原子数(weight 计) > `merge_pressure_threshold`(20) 即蒸。
- **叶子展开（C 机制）**：检索命中节点 → 展开全部后代存活原子为影子，上限 `EXPAND_ATOM_CAP`/`CHAR_CAP`；`[span]` 手动回调同语义（SPAN 40/1500）。
- **裁剪收紧**：超预算 ①低 HP 节点/影子 → ②旧原子（低 HP 优先，本轮新原子活一轮）→ ③溢出 > `budget*(1+hard_trim_slack=0.1)` 才硬截断。
- **heat burst / auto_expand（默认关）**：信号 = 回血封顶溢出量（节点全额 + 直接父半权）；热量 ≥ `expand_heat_threshold`(60) 且预算富余（使用率 < `expand_ratio`=0.85）→ 炸开节点。`AUTO_EXPAND=False` 默认关。
- **find_similar_threshold 已重命名为 `find_dup_threshold`**，值 = **0.8**（唯一校准完成的参数，逐字重复检测器；原文回原文 max_j=0.895，转述 max_j≤0.29）。
- **初始 HP**：`initial_hp` 100→**70**（§11 已入册）；父 HP = 70 + 1.0×组均 ≈ 80–95，封顶 `max_hp` 150。
- **按秩合并**：`merge_depth_diff=1`；禁止单成员块（子数 ≥2）；父节点创建时子数 ≥2。
- **冷却窗口**：`tick(1)+merge; tick(_COOL_TICKS=4)+merge`（env `EDITBENCH_COOL_TICKS`）。
- **self_quota 实验操控（默认关）**：参数 `self_quota_ratio`(0)/`self_quota_max`(0.5)/`self_quota_min_len`(8)；`pr6_sq` 用 ratio=0.35。
- **占位透明**：`placeholder_transparent`（默认 on），渲染递归展开子卡，注意力/merge/召回 boost/shadow 全部跳过占位卡。
- **内存上限**：`max_memory_mb` 2048→4096→**5120**；`tree_save_every=10`；`restore_on_start=true`。
- **组装预算**：`assembly_budget` 10000→**16000**；`--tree-budget 7000`（实测校准）；`retrieval_budget` 6→20。

**注意**：`ABSENCE_INBOX_CAP` 已由 10 改为 **12**（原文 + 超出聚合为 1 条）。

## 四、核心设计决策（为什么是现在这样）

1. 稳定 ID + 顺序链表（piece-table 式）：编辑不做全局坐标平移；禁 ID 大小比较。
2. 区间覆盖树，并查集式自底向上合并：父 = 子区间概括；无预设根；深度 = 合并历史。
3. 按秩合并（`merge_depth_diff=1`）：实测 64 批 → 高 9。
4. 禁止单成员块（父节点子数 ≥2）。
5. 收养机制：插入原子按两侧边界 owner 链 LCA 入树；缝隙在边界/首尾 → 不收养。
6. 标记置脏（唯一算法）：删除爬墓碑卡链、插入爬收养链。
7. 占位解除 = 冷却重建。
8. 重建级联。
9. 影子注入（召回进组装）：位置槽 = 覆盖它的发射项之后，沿 owner 链下钻 O(深度)。
10. 从属标注（硬要求）：深度缩进 + ⊂父卡 + "召回影子/召回原文"标注。
11. 提升（路径分裂）：激活计数达阈值 → 节点沿祖先逐层上提。
12. 混合检索三通道：摘要·向量（bge-small-zh）+ 摘要·关键词（bigram）+ 原子·粗筛+向量精排。
13. 回滚：undo 逆向走编辑路径；多原子块恢复用末原子锚点。
14. 注意力窗口（§4.3b）。
15. force 合并。
16. 叶子展开。
17. run2 协议：`[plan]` → `[recall]`/`[span]` → 正文 → `[note state]`。
18. 冷却窗口（bench_qa 专用）：修复复述崩溃（1.5%→30.8%）。
19. merge 条件式触发（2026-08-30）：tiling 峰值 215→143、谷底 127→25。
20. 节点窗口扩展（2026-08-30）：注意力节点段成员 = 全部存活节点。

## 十、注意事项（架构审查结论）

1. 轨道B 未进机制层（core.py 桩引擎没有 notebook）。
2. `span_atoms`/`expand_leaves` 遍历已统一（唯一入口 `core.Engine.node_atoms`）。
3. `attention_out` 三职责耦合（加速衰减线/force 合并线/计数口径）。
4. force 合并成本：蒸馏 0.5→2.9 次/轮。
5. 注意力排序 O(n log n)/tick 未在 30 万句压力规模验证。
6. 参数台账已与代码逐项对齐，但数值多为先拍值，仅 `find_dup_threshold=0.8` 校准完成。
7. 窗外滞留现象（pressure_threshold=2.0 下窗外原子可能滞留铺陈 80 个左右）。
8. 模型选择：glm-4.7-flash 会挂起，改用 glm-4.7-flash 正常。
9. 向量模型离线加载（`HF_HUB_OFFLINE=1` + `local_files_only=True`）。
10. span 工具从未被模型主动使用。
11. 长上下文漂移是当前最大质量瓶颈。
12. 共现层带动选择瓶颈。
13. 评测口径易被答案风格污染。
14. compare.py 两处协议修复未重跑。
15. 评分任务易被杀。
16. 组装 per 工具调用成本教训（组装纯计算 ~1ms/次；行动派 agent 单轮 90-130s）。
17. 平台中立原则（任务行/待回复清单必须是事实陈述）。
18. judge 关思考两处坑（`extra_body` 嵌套被忽略）。
19. events 文件跨 run 追加（已缓解）。
20. agent 挂载点必须改 provision 源文件。
21. score.py 两处时间戳边界（已修，SPEC v0.2）。
