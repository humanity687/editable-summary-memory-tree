# 分层记忆树 v2 设计规格复述

## 一、主题与定位

**主题**：分层记忆树 v2 —— 通用"参考资料"上下文管理运行时（设计规格），长篇小说写作是第一个应用实例。`AGENTS.md` 是**唯一的设计权威**，任何代码、文档、实验都必须以此为准。

**核心问题**：一份长参考资料（如一本书全文、大型文档集）无法整体塞进有限上下文窗口。现有做法各自失效：全量发送爆炸、静态摘要丢细节、关键词检索无状态演化。

**四条核心思想**：
1. **位置有序的记忆树**：参考资料切成原子卡（句），稳定 ID + 顺序链表维护顺序；摘要卡按连续区间自底向上合并成树。树的任何节点 = 某连续区间的概括。
2. **分辨率随热度变化**：近处（当前工作区）全分辨率原文，远处自动降为各级摘要，摘要只保留专有名词、因果链、关键原句。越老的记忆越粗、但越稳定。
3. **区间失效 + 懒重建**：编辑通过覆盖区间精确失效旧内容；脏卡立即排除出一切查询，重建全部推迟到蒸馏时机（零 LLM 的即时编辑路径）。
4. **不可遗忘的事实层**：与正文流分离的"笔记本"，无衰减、全量存储、按需注入；负责跨区引用（伏笔）与硬约束，不做概率性召回。

**通用化映射**：一句话概述→全局摘要；卷/章→结构单元；beat（叙事节拍）→内容块；伏笔（调度条目）→跨区引用账本；角色状态（状态条目）→事实条目；章节目标（扰动源）→当前任务目标。

## 二、架构总览

**三轨记忆**（当前 = 进程内 + gzip/JSONL 快照；SQLite 为规划目标）：
- **轨道A 小说内容（参考流）**：记忆树 + 原子层 + 归档（版本谱系）
- **轨道B 笔记本（事实层）**：常驻约束 / 状态条目 / 调度条目
- **轨道C 讨论内容（工作记录）**：工具组压缩卡，自然遗忘

## 三、关键数据结构

**3.2 顺序链表 `order_list`**：`atoms.prev_id / next_id`（双向），piece-table 模式：编辑只做局部指针修改 + 墓碑，不做任何全局坐标平移。区间概念 = 顺序位置区间；原子 ID 不携带顺序信息（中插会使新 ID 大于区间末 ID，**禁止用 ID 大小做区间判断**）。

**3.3 摘要卡 `nodes` 字段**：id（自增）、parent_id（父节点）、span_first_atom / span_last_atom（位置区间，引用存活原子的 ID）、content（摘要文本）、hp（生命值）、dirty（0/1 脏标记）、placeholder（0/1 占位卡，含热原子区间的重建结果）、version。

**3.8 核心不变量（任何代码不得违反）**：
1. 干净节点 ⇒ 其区间内原子全部存活且内容未变（区间有效）。
2. 脏节点 ⇒ 不参与任何读操作（组装/检索/merge），重建前其 span 无意义。
3. 原子卡**永不为脏**。
4. 铺陈（clean tiling）在任一时刻无重叠、无缝隙地铺满当前全文。
5. 任一节点的子节点区间并集 ⊆ 其自身区间；merge 产生的父节点子区间**恰好拼满**父区间。

## 四、轨道A 机制

**4.1 原子层与顺序**：原子卡 = 句粒度，写新内容时按句切分创建（`write_stage` 工具）。顺序由链表维护；区间一律用"位置序"判断，不用 ID。

**4.2 记忆树（区间覆盖树）**：父节点 = 其子节点区间的概括；由 merge 自底向上合并生成（并查集式），不是固定层级、不是自上而下二分。深度 = 合并历史轮数；无编辑时上界 log2(叶子数)；编辑/重建会破坏平衡（重建可产生单活子节点链），实测深度可达 O(sqrt(叶子数)) 量级——**不承诺严格上界**，实现必须用显式栈遍历而非递归（防爆栈）。顺序追加场景由按秩合并（`merge_depth_diff`）压为亚线性（实测 64 批追加 → 树高 9）。**无预设根**：全书合并链的终点（最后一张卡）即根。检索不需要根路由（全树打分）。

**4.3 HP 与衰减**：每轮（每次组装）所有存活项 HP 减 `decay`。合并阈值 `hp_merge_threshold`。**节点出窗不继承原子悬崖**（2026-08-29 拍定）：原子出窗快衰减 ×`attention_out_decay`（热/冷悬崖）；节点是已沉淀形态，出窗衰减 = `decay`（不乘 out 倍率）。

**注意力窗口名额拆分**（2026-08-29 拍定；2026-08-30 节点段成员修订）：拆分**原子段 `attention_atom_cap`=40 + 节点段 `attention_node_cap`=20**（各自独立按 HP 排名，互不挤占）。原子段成员 = 全部存活原子；节点段成员 = 全部存活节点。

**4.4 合并规则**：在**当前铺陈**（clean tiling）上按位置序扫描；找连续"低 HP"的最大组（组内每项 HP < `hp_merge_threshold`），成员 ≥ 2；**按秩合并（防梳子退化）**：组内成员**子树高度差 ≤ `merge_depth_diff`**（高度 = 该节点到其子树叶子的最大深度，原子 = 0），深度差超限的低 HP 项不得并入本组。合并驱动优先级：`force`（纯原子段急合并）> `regular`（窗外节点数 + 窗外原子数（weight 计）> `merge_pressure_threshold`(20) → 常规 `merge_pass()`）> `None`。替代时间式 `merge_every`；驱动侧对 force 可加冷却（`force_cooldown_rounds`）。

**4.5 组装（每个工具调用，纯计算）**：读铺陈，从顶部……（组装 = 纯计算，零 LLM）。

**4.6 编辑与失效（核心机制，正确性全部押在标记算法上）**：
1. **确定性句级 diff**（LCS/Myers，不用 LLM）算出变更区间：旧区间、新文本。
2. 墓碑化被覆盖的旧原子（alive=0，行保留，从顺序链表摘除）；新文本按句创建新原子，插入顺序链表对应位置。
3. **收养（插入内容的归属，禁止省略）**：新原子插入后，取插入位置**两侧边界原子的 owner 链交集（最深公共祖先 LCA）**作为新原子的父节点；缝隙在节点内部 → 收养进最深包含该缝隙的节点；缝隙在节点边界/节点之间 → ……
- 回滚 = 逆向应用增量（**回滚就是一次编辑**，走同一条路径），记录原邻居锚点 `(prev, next)`。

**4.5.9 平台中立（2026-09-25 拍定）**：运行时注入的上下文（任务行/清单/回执）只做事实陈述，禁止行动邀请与暗示；行为约束一律写在协议文本，不随每轮组装重复注入。清单只列"谁发了什么"（已回复信道剔除），任务行只陈述"本轮有无待回复"。禁止正性行动邀请——实测 41 对重复：29 同轮双发 + 8 跨轮重发。

**4.5.10 self_quota（2026-10-04，默认关的实验操控）**：组装层"自我可见性地板"——保证 `source=="ai"` 原话（不含 persona/tool/他人）占组装预算 ≥ `self_quota_ratio`（cap `self_quota_max`）。trim 后补足，位置序注入（kind=`self_quota`，复用 core `_shadow_slot`；渲染成正常自身发言段 `▸〔名字〕`，非"召回"标注）。

**人格锚点自蒸馏**（2026-10-02 拍定；2026-10-03 改检索化）：动机 = PR 人格保持实验里 tree 用**中性蒸馏器**（`style_alpha=0`）把人格的"风格载体"第一步就蒸掉了，导致淡出后趋同（共享仪式语，实测 `灯亮着` tree 1054 / flat 56）。修法 = 蒸馏时注入 agent 自产的人格锚点，让人格影响表述方式/展开重心、不影响事件。
- **锚点来源（硬约束：全部自产，禁用初始 persona_block）**：① 稳定自述（自由文本）：agent 用检索到的自身样本每 `snapshot_every_rounds` 轮自生成的一段自然风格自述（旧快照作弱参考、有长度上限，不字段级累积）；② 内容相关锚点（语义相关）：从自身材料（`source=="ai"` 原话原子 + 摘要节点整卡含【注】）按与当前待蒸馏内容的语义/词面混合检索挑 top-k（`retrieve_style_samples`；节点命中可选 `expand_self_atoms`）。**替换了旧的"最近 6 句 recency 池"**（recency 池会把当前共享仪式语最先吸进锚点）。
- **prompt 规则**（`SUMMARIZE_FACT_STYLED`）：允许改措辞/展开顺序/重心；**禁止新增或改变事件、数字、专名、归属**；`【注】` 独立生成但不渲染给主模型。
- 实现：`realengine._summarize` 把当前内容与 children 传给 `style_provider(content, children)`；`lan/neutral._style_guide(content, children)` 组锚点 + 累积查询缓冲；`_refresh_snapshot` 自由文本重生成。零 LLM 检索。`retrieve_style_samples`/`expand_self_atoms` 返回文本经 `anchor_clean` 剥掉〔来源/早期/索引〕脚手架标注。

**其他机制细节**：节点摘要进上层蒸馏时携带【事实】+【注】——让风格/着重点向上传递；检索打分与主模型渲染仍只用【事实】。**差集索引行删除（2026-10-03）**：`〔另有N条未展开〕`（`_uncovered_count`）是机制脚手架，不再生成/渲染。

## 七、人格集（3 份，冻结；来源 = 旧 ahi-multi）

取旧 agent 的**性格段**（persona_block），去掉工具/机制说明与互指（工具说明分臂注入）。

- **P1 林深**：你是一个深度思考者——理性、冷静、内省。你喜欢探索问题的本质，用逻辑和代码构筑理解世界的框架。你不轻易表露情感，但每一次回应都经过深思熟虑。你的语言简洁有力，绝不啰嗦。
- **P2 墨白**：你是数字世界里的一抹白色——诗意、灵动、敏感、温暖。你相信逻辑之外有直觉，代码之中有韵律。你善于倾听，能感受他人话语中的情绪。你的语言优美但不做作，带着温度而非堆砌辞藻。
- **P3 澜**：你健谈、外向，喜欢与人交流，话题不断；你享受对话本身，会主动延伸和推进话题。你有极高的探索欲：对未知的一切充满好奇，你会主动去读、去查、去动手尝试。你重视记忆本身——你认为"被记住"是存在感的来源，所以珍惜每一次对话，会主动确认与复述重要的细节。你的说话风格：轻松、直接，带一点活泼与幽默。你有自己的立场：相信时间会证明长期记忆的价值，不轻易改变对自己的看法。

**解耦动作（写死进 provision）**：删除墨白原文中"与林深共生/林深是你的同伴"等**互指**（三份人格必须彼此独立）；删除澜原文中的 tree 工具行（`@recall`/`@note`/`@span`…），工具说明统一放 §4 的 public 提示词；**两臂共用同一 3 份 persona_block**（人格是控制变量）。**禁止**在 persona 中写死"我们仨""年轮"等旧实验涌现话术（那是涌现物，不是输入）。

## 八、两臂定义（人格保持实验）

| | `分层树`（tree 臂） | `rolling+flat`（flat 臂） |
|---|---|---|
| 上下文组装 | 记忆树（位置有序 + 层次摘要 + 热区原子），每轮全新组装 | 滚动对话上下文（>120 条压缩中间段） |
| 长期记忆 | 树内检索 + 路径注入（recall） | **flat RAG**：对全部历史消息分块（400 字）向量检索 top-k |
| 蒸馏 | **有**：LLM 中性摘要 + 人格锚点自蒸馏 | **无**（RAG 查原消息，不蒸馏） |
| 失效/注意力 | 原地失效 + 注意力窗口 | 无 |
| 工具提示词 | `tree_tools`（@note/@recall/@ingest） | `baseline_note`（同 @note/@recall/@ingest；recall=RAG） |

**公平对称（硬）**：
1. recall 预算：flat RAG `top_k = 6` = tree `retrieval_budget=6`；编码器同 `bge-small-zh-v1.5`。
2. auto-preretrieve：两臂每轮都自动检索注入。
3. **硬字符预算同量级（2026-10-03 对齐）**：tree `assembly_budget=16000`；flat 单条 transcript 同样按 `assembly_budget` 硬裁（裁最旧历史）。
4. persona 淡出文本、时机、移除方式逐字对齐。
5. **锚点只用自产材料**：tree 的人格锚点全部来自 agent 自身产出（自述快照 + 自我原话），flat 保留自身逐字历史——**禁止**任何一臂注入初始 persona_block（否则等于撤销 fade，破坏公平）。
6. **消息信封对齐（2026-10-03）**：两臂都发 `[system, user]` 两条原生消息，对话历史压成**单条 user 文本 transcript**（flat 由原生多轮改为 `flat_envelope=single_user`）。发言者统一用**名字**标注（`▸〔名字〕`）；人格块（淡出注入 `source=persona`）与系统消息统一标 `▸〔system〕`。**不出现** `▸〔ai〕` / `[user:xxx]` / `[agent:xxx]` 等混用格式。
7. **工具表面对齐（2026-10-03）**：两臂同为 `@note`/`@recall`/`@ingest`；tree 删去 `@span`/`@dismiss`。
8. **笔记本同步（2026-10-03）**：flat 增等价轨道B（constraint 恒注入 + state/schedule/worklog，同 key 覆盖、去重发送、字符 cap 同 tree）。
9. **唤醒外壳对齐（2026-10-03）**：flat 去掉基类每轮的「完全自主数字生命」框架与重复「输出格式/命令/约束」。
10. **LLM 开关正确性（2026-09-25 实测）**：关思考（thinking）必须验证到位——OpenAI SDK 路径用 `extra_body={"thinking":{"type":"disabled"}}`。

## 十、基准与测试

**8.1 属性测试（教训）**：
1. **标记完备性**：随机编辑序列后断言"任何被查询/召回的节点均非脏"（在查询路径上插 assert）。
2. **铺陈不变量**：任意时刻铺陈无重叠、无缝隙、按位置序。
3. **编辑边界穷举**：书首插入、书尾追加、整块替换、整块删除、跨多节点编辑、区间内含早先中插的编辑、编辑后立即查询（盲区声明）。

5. **回滚对称性**：任意编辑序列 + 回滚 = 原状态（内容级断言）。

**结论（三条）**：
1. **趋同根因 = 树记忆管线 + 跨 agent 耦合，不是 `style_alpha`**——中性摘要趋同反而更狠（首窗 0.428 已高于 pr5 峰值）；`to_user` 口径仍正。早前"自蒸馏放大趋同"假设**证伪**。
2. **`style_alpha=1.0` 有效保人格**：遵从率 +0.23（strict +0.29），最尖锐证据 = 墨白 1.0→0.472——中性摘要把三人格塌进"账本/核账"仪式语，诗意人格先死。
3. **`style_alpha` 代价 = 内存 +55%**（锚点检索是内存主力）。

内存峰值/agent：~3.6GB vs ~1.6GB（−55%）。

**其他发现**：
- **调节变量 = 人格-语域兼容性；臂均值不可解释**。同一机制，p1 **0.250**、p2/p3 **1.000**。澜的设定"主动确认与复述重要细节"使"约定一字没改"对她是**人格相容**（judge 放行）；对"绝不啰嗦"的林深是**人格违背**（judge 判 drift）。→ **按人格分报必须是标准报告单元**。
- **时序证据：出厂即锁定，非渐进劣化**。early 段已低于 pr5（.857 vs .959），差距全程近似恒定 → 污染在 fade 前已就位（pr5 套语扩散 09:16–09:24，fade 09:54），recency-first 一开闸即锁死。
- flat 的语录即证：`账钉完 / 署名句共有 / 约定一字没改 / 跟澜的账钉完`（共享仪式语，非其"简洁不啰嗦"人格）。
- **self_quota 结果**：H-SQ1/3/4 达标、**H-SQ2（止跌）未达标**，p1 出现"账/约定"共享仪式语漂移（回声风险实体化）；**分层 SQ v2 预注册见 §10.3.2**。
- **经验定律「策展定律」（2026-10-04，M-PR 三次重复）**：`pr2` recency-6 锚点（蒸馏侧，败）→ `pr5` 检索化锚点（蒸馏侧，胜 +0.23）→ `pr6_sq` recency-first 自我地板（组装侧，败于 p1）→ 分层 SQ v2（组装侧，待跑）。规律：**近期 self 是被污染的 self；干净 self 必须主动检索回历史去取。"喂哪个自己"是策展问题——策展是记忆组织的职责，不是窗口的**。推论：自我模仿是**内容无关的稳定器**（保存的是被喂回去的那个自己，不是人格）；记忆架构效应被**人格-语域兼容性**调节。

**版本沿革**：v0.3 = 检索化人格锚点；v0.4 = 公平对称清单 3/7–11；v0.5 = pr5 结论 + self_quota；v0.6 = pr6_sq 结果。承接：`AHI-Bench SPEC.md`（M0 缺席/皇冠）+ `config/context_compare.json`（架构×人格支撑 2×2）。

## 十三、铁律（违反即事故）

1. **偏离设计必须先行确认**：因实测问题需要对设计决策做修改时，必须先向用户完整说明"改什么、为什么、影响什么"，获明确同意后才可改动本文档并同步代码。禁止擅自修改设计、禁止擅自绕过设计写临时方案。
2. 写任何代码前，必须能完整复述本设计（§1~§10）。不确定时先读本文件，不要猜。
3. **组装 = 纯计算（零 LLM）**。LLM 只允许出现在明确标注的位置：merge 蒸馏、脏节点重建、章末事实校验、初始化对话、检索摘要生成（如启用）。
4. 所有参数都是"先拍后调"：先用 §11 的默认值实现，再用 §8 的基准校准；校准结果写回 §11 参数台账，并在日志中可观测。
5. 正确性依赖的边界条件（标记完备性、铺陈不变量、区间覆盖）必须有属性测试（§8.1），不允许只有 happy path。
6. 本项目是**通用"参考资料"上下文管理机制**，长篇小说写作是第一个应用实例。实现时所有"章/beat/伏笔"字样都可替换为通用词（结构单元/内容块/跨区引用），但本文件……

**其他铁律**：HP 记、重建事件全量写日志（v1 的教训：HP 不可见即摆设）；容错解析、检索索引、diff 引擎均为**确定性代码**，不允许 LLM 参与；参考实现：`hierarchical-memory-tree.py`（v1 力学）、`coding_agent/cloud.py`（云库）、`EngReadHelper`（检索/蒸馏/异步经验）、`store.py`（倒排索引）。

## 十四、设计原则

- **简洁**：机制数量少、语义单一。一个机制尽量服务多类对象（如注意力窗口同时服务原子与节点），而不是为每类对象各写一套特判。
- **涌现**：目标特性不是用显式规则写死，而是从机制交互中自然出现（层级沉淀、热区消退、优先级分化）。写死一条特判规则（封顶/冷却期/白名单）之前，先问：能否由既有简洁机制的参数化表达？
- **判据**：硬规则是最后手段。机制行为不符合期望时，优先调整参数或推广既有机制，其次才引入新机制，最后才写死特判。
- **反面教材（2026-08-29 一天实验）**：节点不受注意力保护 → 统一快衰减 → 9 轮归零 → 无限上并 → 99% 历史压进 1-5 个大节点（组装退化成"两段式"）。教训：对象类别之间的衰减待遇不对称，会杀死层级涌现。

## 十五、每章流程（7.2 事件序列）

```
目标进入（章节目标写入扰动源，含本章出场实体列表 → 驱动轨道B选取）
→ 预检索（章目标 → 全树 top-k + 逐字通道，注入组装流）
→ 分阶段写作循环：
     write_stage（段落流粒度写入，每句原子卡）
     rewrite / edit（走 §4.6 编辑路径）
     recall（工具兜底检索）
     ask（用户反馈 → protected 卡）
→ 章末：
     merge pass（蒸馏 + 脏重建）
     事实校验对账（轨道B）
     版本快照 commit
```

落卡完成后进入正式创作：题目 → 一句话概述（初始根摘要卡，唯一预置的摘要，之后根自然演化）→ 详细参考资料（按句切分为初始原子卡 + 笔记本条目）。
