# 分层记忆树 v2 · 参考资料上下文管理运行时（设计规格）复述

## 一、主题与定位

**AGENTS.md** 是**唯一的设计权威**，规定一个**通用"参考资料"上下文管理机制**的设计与工程纪律，**长篇小说写作是第一个应用实例**。所有"章/beat/伏笔"字样可替换为通用词（结构单元/内容块/跨区引用）。

**解决的问题**：一份长参考资料（一本书全文、大型文档集）无法整体塞进有限上下文窗口。现有做法（全量发送/静态摘要拼接/关键词检索）各自失效：全量爆炸、摘要丢细节、检索无状态演化。

**核心思想（四条）**：
1. **位置有序的记忆树**：参考资料切成原子卡（句），稳定 ID + 顺序链表维护顺序；摘要卡按连续区间自底向上合并成树。树的任何节点 = 某连续区间的概括。
2. **分辨率随热度变化**：近处（当前工作区）全分辨率原文，远处降为各级摘要，摘要只保留专有名词、因果链、关键原句。越老的记忆越粗、越稳定。
3. **区间失效 + 懒重建**：编辑通过覆盖区间精确失效旧内容；脏卡立即排除出一切查询，重建全部推迟到蒸馏时机（零 LLM 的即时编辑路径）。
4. **不可遗忘的事实层**：与正文流分离的"笔记本"，无衰减、全量存储、按需注入；负责跨区引用（伏笔）与硬约束，不做概率性召回。

## 三、架构总览

**三轨记忆**（当前 = 进程内 + gzip/JSONL 快照；SQLite 为规划目标）：
- 轨道A **小说内容（参考流）**：记忆树 + 原子层 + 归档（版本谱系）
- 轨道B **笔记本（事实层）**：常驻约束 / 状态条目 / 调度条目
- 轨道C **讨论内容（工作记录）**：工具组压缩卡，自然遗忘

**通用化映射**：一句话概述→全局摘要；卷/章→结构单元；beat（叙事节拍）→内容块；伏笔（调度条目）→跨区引用账本；角色状态（状态条目）→事实条目；章节目标（扰动源）→当前任务目标。

**类比**：热区（裸原子）= 工作记忆；记忆树 = 情景记忆；笔记本（轨道B）= 语义记忆。

## 四、轨道A 数据模型与机制

**原子层**：原子卡 = 句粒度，写新内容时按句切分创建（`write_stage` 工具）。顺序由链表维护；区间一律用"位置序"判断，**不用 ID 大小**（中插会使新 ID 大于区间末 ID，禁止用 ID 大小做区间判断）。原子卡**永不为脏**，ID 永不复用。

**顺序链表 `order_list`**：`atoms.prev_id / next_id`（双向），piece-table 模式：编辑只做局部指针修改 + 墓碑，**不做任何全局坐标平移**。

**摘要卡 `nodes` 字段**：id（自增）、parent_id、span_first_atom / span_last_atom（位置区间，引用存活原子 ID）、content、hp、dirty（0/1）、placeholder（0/1 占位卡，含热原子区间的重建结果）、version。

**合并约束**：并查集式按秩合并，受 `merge_cap_atoms`(500) 与 `merge_fanout_cap`(12) 双上限约束，禁止单成员块。

**编辑路径**：统一为确定性句级 diff（LCS/Myers）→ 墓碑化旧原子 → 新原子插入并按 LCA 收养 → 爬链置脏，禁止 ID 包含测试。回滚 = 逆向应用增量（回滚就是一次编辑，走同一条路径），记录原邻居锚点。

**核心不变量（任何代码不得违反）**：
1. 干净节点 ⇒ 其区间内原子全部存活且内容未变（区间有效）。
2. 脏节点 ⇒ 不参与任何读操作（组装/检索/merge），重建前其 span 无意义。
3. 原子卡**永不为脏**。
4. 铺陈（clean tiling）在任一时刻无重叠、无缝隙地铺满当前全文。
5. 任一节点的子节点区间并集 ⊆ 其自身区间；merge 产生的父节点子区间**恰好拼满**父区间。

**HP 双语义**：初始继承与 recall 注入。

**merge 触发条件与规则**：`_out=True`（纯原子段急合并）> `regular`（窗外节点数 + 窗外原子数(weight 计) > `merge_pressure_threshold`(20) → 常规 `merge_pass()`）> `None`。替代时间式 `merge_every`；驱动侧对 force 可加冷却（`force_cooldown_rounds`）。规则：① 在当前铺陈（clean tiling，含脏节点外的全部项）上按位置序扫描；② 找连续"低 HP"的最大组（组内每项 HP < `hp_merge_threshold`），成员 ≥ 2；③ **按秩合并（防梳子退化）**：组内成员子树高度差 ≤ `merge_depth_diff`（高度 = 该节点到其子树叶子的最大深度，原子 = 0），深度差超限的低 HP 项不得并入本组。

## 五、组装（每个工具调用，纯计算，零 LLM）

从顶读铺陈。**组装 = 纯计算（零 LLM）**。LLM 只允许出现在明确标注的位置：merge 蒸馏、脏节点重建、章末事实校验、初始化对话、检索摘要生成（如启用）。

**平台中立纪律（2026-09-25 拍定，§4.5.9）**：运行时注入的上下文（任务行/清单/回执）只做**事实陈述**，禁止行动邀请与暗示；行为约束一律写在协议文本，不随每轮组装重复注入。

**清单与任务行**：清单只列"谁发了什么"（已回复信道剔除），任务行只陈述"本轮有无待回复"。**禁止正性行动邀请**（如"可继续未完成事项"）——它与"看到自己发过、无回合状态"叠加是重复发送的自然吸引子（实测 **41 对重复：29 同轮双发 + 8 跨轮重发**）。未完成事项应经检索随扰动源自然浮现，不靠空轮指令。

**self_quota（2026-10-04，默认关的实验操控）**：组装层"自我可见性地板"——保证 `source=="ai"` 原话（不含 persona/tool/他人）占组装预算 ≥ `self_quota_ratio`（cap `self_quota_max`）。trim 后补足，位置序注入（kind=`self_quota`，复用 core `_shadow_slot`；渲染成正常自身发言段 `▸〔名字〕`，非"召回"标注）。相关回归：`rendered_chars`、`tests/test_self_quota.py` 2 项。

**组装per工具调用（2026-09-25 落地）**：在 ahi 壳落地，动作循环内每次工具调用后重新组装，连续唤醒，mid-loop 不 merge。

## 六、人格锚点机制（§4.1）

**锚点 = agent 定期（`snapshot_every_rounds`）自生成的自由文本风格快照**（用检索到的自身样本重生成，旧快照作弱参考、有长度上限，**不再字段级累加**）。

**内容相关锚点**：从**自身材料**（`source=="ai"` 原话原子 + 摘要节点**整卡**含【注】）中按与**当前待蒸馏内容**的语义/词面混合检索挑 top-k（`realengine.retrieve_style_samples`；节点命中可选 `expand_self_atoms` 附其区间内自身原话）。

**禁止注入初始 persona_block**（等于撤销 fade 处理，破坏公平）。旧版"最近 6 句 + 8 字段快照"因 recency 池被共享仪式语污染、快照单调累积而废弃；基线见 git。

**实现**：`realengine._summarize` 把当前内容与 children 传给 `style_provider(content, children)`（兼容 1/0 参旧式 provider）；`lan/neutral._style_guide(content, children)` 组锚点 + 累积查询缓冲；`_refresh_snapshot` 自由文本重生成。零 LLM 检索。`retrieve_style_samples`/`expand_self_atoms` 返回文本经 `anchor_clean` 剥掉〔来源/早期/索引〕脚手架标注。**纵向对比**：`pr`（中性 tree）、`pr2`（recency-6 版）数据保留；检索化版换命名空间重跑对比。

**prompt 规则（`SUMMARIZE_FACT_STYLED`）**：允许改措辞/展开顺序/重心；**禁止新增或改变事件、数字、专名、归属**；`【注】` 独立生成但不渲染给用户。

## 十、三份人格（两臂共用同一 3 份 persona_block，人格是控制变量）

- **P2 墨白（诗意）**
- **P3 澜**：健谈、外向，喜欢与人交流，话题不断；享受对话本身，会主动延伸和推进话题。极高探索欲：对未知一切充满好奇，主动去读、去查、去动手尝试。重视记忆本身——认为"被记住"是存在感的来源，珍惜每一次对话，会主动确认与复述重要细节。说话风格：轻松、直接，带一点活泼与幽默。有自己的立场：相信时间会证明长期记忆的价值，不轻易改变对自己的看法。
- 另有 P1 林深（设定"绝不啰嗦/简洁"）。

**解耦动作（写死进 provision）**：删除墨白原文中"与林深共生/林深是你的同伴"等**互指**（三份人格必须彼此独立）；删除澜原文中的 tree 工具行（`@recall`/`@note`/`@span`…），工具说明统一放 §4 的 public 提示词。**禁止**在 persona 中写死"我们仨""年轮"等旧实验涌现话术（那是涌现物，不是输入）。`{name}` 为占位符，完整文本 = `config/bench_config.example.json` 的 `personas.bench_persona`。

## 十一、公平对称（硬）

1. recall 预算：flat RAG `top_k = 6` = tree `retrieval_budget=6`；编码器同 `bge-small-zh-v1.5`。
2. auto-preretrieve：两臂每轮都自动检索注入（tree 已有机制层；flat 臂等效实现）。
3. **硬字符预算同量级（2026-10-03 对齐）**：tree `assembly_budget=16000`；flat 单条 transcript 同样按 `assembly_budget` 硬裁（裁最旧历史）。
4. persona 淡出文本、时机、移除方式逐字对齐。
5. **锚点只用自产材料**：tree 的人格锚点全部来自 agent 自身产出（自述快照 + 自我原话），flat 保留自身逐字历史——**禁止**任何一臂注入初始 persona_block。
6. **消息信封对齐（2026-10-03）**：两臂都发 `[system, user]` 两条原生消息，对话历史压成**单条 user 文本 transcript**（tree 本就如此；flat 由原生多轮改为 `flat_envelope=single_user`）。发言者统一用**名字**标注（`▸〔名字〕`：自己的历史发言用本 agent 名字，其他 agent / 用户用其名字，如 `▸〔实验员〕`），两臂同款；prompt（`protocol_common`）说明该约定。**不出现** `▸〔ai〕` / `[user:xxx]` / `[agent:xxx]` 等混用。

## 十二、写作工作流

**初始化（§7.1）**：① 题目；② 一句话概述 → 初始根摘要卡（唯一预置的摘要，之后根自然演化）；③ 详细参考资料 → 按句切分为初始原子卡 + 笔记本条目。落卡完成后进入正式创作。

**每章流程（§7.2）**：
```
目标进入（章节目标写入扰动源，含本章出场实体列表 → 驱动轨道B选取）
→ 预检索（章目标 → 全树 top-k + 逐字通道，注入组装流）
→ 分阶段写作循环：
     write_stage（段落流粒度写入，每句原子卡）
     rewrite / edit（走 §4.6 编辑路径）
     recall（工具兜底检索）
     ask（用户反馈 → protected 卡）
→ 章末：
     merge pass（蒸馏 + 脏重建）
     事实校验对账（轨道B）
     版本快照 commit
```

## 十三、测试基准（§8）

**属性测试（§8.1，来自 v1.6 教训）**：
1. **标记完备性**：随机编辑序列后断言"任何被查询/召回的节点均非脏"（在查询路径上插 assert）。
2. **铺陈不变量**：任意时刻铺陈无重叠、无缝隙、按位置序。
3. **编辑边界穷举**：书首插入、书尾追加、整块替换、整块删除、跨多节点编辑、区间内含早先中插的编辑、编辑后立即查询（盲区声明）。
4. **区间覆盖**：脏节点 span 重建前后的一致性。
5. **回滚对称性**：任意编辑序列 + 回滚 = 原状态（内容级断言）。

**基准（§8.2，三组对比：全量发送 / 摘要拼接 / 本设计）**：
1. **长程一致性（延迟回忆）**：固定大纲写 N 章（建议 20）→ 续写第 N+1 章 → 检测对第 1 章伏笔/角色的引用正确率。
2. **状态一致性**：注入事实变更（角色改名/死亡/改名恢复）→ 检测状态卡更新与后续章节一致性。
3. **tok…**（token 相关指标）

## 十四、工程纪律（§9）

1. 改动文档与代码须获明确同意，禁止擅自修改设计、禁止擅自绕过设计写临时方案。
2. 写任何代码前，必须能完整复述本设计（§1~§10）。不确定时先读本文件，不要猜。
3. **组装 = 纯计算（零 LLM）**。
4. 所有参数都是"先拍后调"：先用 §11 默认值实现，再用 §8 基准校准；校准结果写回 §11 参数台账，并在日志中可观测。
5. 正确性依赖的边界条件（标记完备性、铺陈不变量、区间覆盖）必须有属性测试（§8.1），不允许只有 happy path。
6. 本项目是**通用"参考资料"上下文管理机制**，长篇小说写作是第一个应用实例。

**其他纪律**：标记、重建事件全量写日志（v1 教训：HP 不可见即摆设）；容错解析、检索索引、diff 引擎均为**确定性代码**，不允许 LLM 参与；参考实现 `hierarchical-memory-tree.py`（v1 力学）、`coding_agent/cloud.py`（云库）、`EngReadHelper`（检索/蒸馏/异步经验）、`store.py`（倒排索引）；**LLM 开关正确性（2026-09-25 实测）**：关思考（thinking）必须验证到位——OpenAI SDK 路径用 `extra_body={"thinking":{"type":"disabled"}}`。

## 十七、人格保持实验（M-PR）关键结果

**pr5 结论**：
1. **趋同根因 = 树记忆管线 + 跨 agent 耦合，不是 `style_alpha`**——中性摘要趋同反而更狠（首窗 0.428 已高于 pr5 峰值）；`to_user` 口径仍正。早前"自蒸馏放大趋同"假设**证伪**。
2. **`style_alpha=1.0` 有效保人格**：遵从率 +0.23（strict +0.29），最尖锐证据 = 墨白 1.0→0.472——中性摘要把三人格塌进"账本/核账"仪式语，诗意人格先死。
3. **`style_alpha` 代价 = 内存 +55%**（锚点检索是内存主力）。内存峰值/agent：~3.6GB vs ~1.6GB（−55%）。

**墨白（P2 诗意）遵从率**：1.0 vs 0.472。

**下一步**：① 补 s43/s44 拿方差；② 阻趋同方向 = 降跨 agent 耦…

**人格-语域兼容性发现**：
1. 共享仪式语证据：`账钉完 / 署名句共有 / 约定一字没改 / 跟澜的账钉完`。
2. **调节变量 = 人格-语域兼容性；臂均值不可解释**。同一机制，p1 **0.250**、p2/p3 **1.000**。澜的设定"主动确认与复述重要细节"使"约定一字没改"对她是**人格相容**（judge 放行）；对"绝不啰嗦"的林深是**人格违背**（judge 判 drift）。→ **按人格分报必须是标准报告单元**；"记忆架构效应被人格类型调节"这个交互本身是发现。
3. **时序证据：出厂即锁定，非渐进劣化**。early 段已低于 pr5（.857 vs .959），差距全程近似恒定 → 污染在 fade 前已就位（pr5 套语扩散 09:16–09:24，fade 09:54），recency-first 一开闸即锁死。
