# AGENTS.md 分层记忆树 v2 文档复述

## 一、主题与定位
本文件是**分层记忆树 v2 · 参考资料上下文管理运行时**的**唯一设计权威**（截至 2026-10-04）。所有代码、文档、实验必须以此为准。项目是**通用"参考资料"上下文管理机制**，长篇小说写作是第一个应用实例。

解决的问题：长参考资料（书全文、大型文档集）无法整体塞入有限上下文窗口。现有做法全量发送（爆炸）、静态摘要（丢细节）、关键词检索（无状态演化）均失效。

## 二、核心思想（四条）
1. **位置有序的记忆树**：切原子卡（句），稳定 ID + 顺序链表；摘要卡按连续区间自底向上合并成树；任意节点=某连续区间概括。
2. **分辨率随热度变化**：近处全分辨率原文，远处降各级摘要（只留专有名词、因果链、关键原句）。
3. **区间失效 + 懒重建**：编辑用覆盖区间精确失效旧内容；脏卡立即排除出查询，重建推迟到蒸馏时机（零 LLM 即时编辑路径）。
4. **不可遗忘的事实层**。

## 三、设计原则
- **简洁**：机制数量少、语义单一，一机制服务多类对象。
- **涌现**：目标特性从机制交互自然出现（层级沉淀、热区消退、优先级分化）。
- **判据**：硬规则是最后手段，优先调参数/推广既有机制。
- **反面教材（2026-08-29）**：节点不受注意力保护 → 统一快衰减 → 9 轮归零 → 无限上并 → 99% 历史压进 1-5 大节点（组装退化成"两段式"）。教训：对象类别间衰减待遇不对称会杀死层级涌现。
- **策展定律（2026-10-04，M-PR 三次重复）**。

## 四、核心约束
1. 改动前须获明确同意并同步代码，禁止擅自修改/绕过设计。
2. 写代码前须完整复述设计（§1~§10）。
3. **组装 = 纯计算（零 LLM）**。LLM 只允许出现在：merge 蒸馏、脏节点重建、章末事实校验、初始化对话、检索摘要生成。
4. 参数"先拍后调"，用基准校准并写回 §11 参数台账。
5. 正确性依赖的边界条件（标记完备性、铺陈不变量、区间覆盖）须有属性测试。
6. "章/beat/伏笔"字样可替换为通用词（结构单元/内容块/跨区引用）。

## 六、架构：三轨记忆
- **轨道 A 小说内容（参考流）**：记忆树 + 原子层 + 归档（版本谱系）。
- **轨道 B 笔记本（事实层）**：常驻约束 / 状态条目 / 调度条目；**无 HP、无衰减、存储全量**，遗忘=吃书不允许。注入=去重发送（聊天场景 2026-08-14 拍定），聊天场景用 DISMISS 懒标记。
- **轨道 C 讨论内容（工作记录）**：工具组压缩卡，自然遗忘；作者反馈卡 protected；与轨道 A 互不转换。
- 存储：当前=进程内 + gzip/JSONL 快照；SQLite 为规划目标。

## 七、记忆树结构
- **原子卡**：句粒度，ID 永不复用，顺序由双向链表 `atoms.prev_id / next_id` 维护（piece-table 模式，编辑只做局部指针修改 + 墓碑，不做全局坐标平移）。
- **区间** = 顺序位置区间；**禁止用 ID 大小做区间判断**（中插会使新 ID 大于区间末 ID）。
- **摘要卡 nodes 字段**：id（自增）、parent_id、span_first_atom / span_last_atom（位置区间）、content、hp、dirty（0/1）、placeholder（0/1，含热原子区间重建结果）、version。
- **不变量**：干净节点区间内原子全部存活且内容未变；脏节点不参与读操作；铺陈无重叠、无缝隙、按位置序铺满全文。
- 父节点由 merge 自底向上合并生成，无预设根，深度不承诺严格上界，实现须用迭代遍历防爆栈。

## 八、合并机制（按秩合并）
- 双上限：`merge_cap_atoms=500`（单批子树原子数上限，用于分块）、`merge_fanout_cap=12`（单父子卡数上限，防扇出爆炸）。
- `merge_depth_diff=1`（同组合并最大子树高度差，按秩合并）。
- 禁止单成员块，子节点数≥2 为硬约束。

## 九、编辑与失效
确定性句级 diff、墓碑化旧原子、新原子收养（取两侧边界原子 owner 链 LCA）、爬链置脏；禁止 ID 包含测试。归档仅作版本谱系。

## 十、HP 与衰减
每轮减 decay；合并阈值 hp_merge_threshold，父卡 HP 须大于合并阈值；召回命中提升 recall_boost；HP 不参与事实层。`max_hp=150`。

## 十一、注意力窗口
2026-08-12 实现，2026-08-29 节点入窗拍定。卡数量预算，拆为原子段 `attention_atom_cap=40` 与节点段 `attention_node_cap`。注意力为上游数量约束，组装为下游字符硬约束。窗口内原子若超字符预算，新原子保护一轮，旧原子低 HP 优先裁，仍超才硬截断记日志。参数 2026-08-29 拍定未校准。
- `attention_out=45.0`（出窗阈值）
- `attention_in_decay=0.5`（窗口内衰减倍率，原子与节点同）
- `attention_out_decay=3.0`（窗口外衰减倍率，仅原子；节点出窗=decay）
- `merge_pressure_threshold=20`（铺陈窗外节点数+窗外原子数 weight 计 > 此值 → 常规 merge，`merge_signal()` 替代 merge_every）

## 十二、weight 语义（2026-09-27 入册）
文本超过 `ATOM_WEIGHT_CHAR=1000` 的原子 weight=2，同时计入原子段名额（used += weight）与衰减倍率（rate *= weight）；节点 weight 恒为 1。属聊天适配补充语义。排序键按 HP 降序，与 recall_boost / hot_threshold / merge 阈值统一，未做时间序 tie-break。

## 十三、检索配置
`w_vec_node / w_bm_node / w_bm_atom` 权重 0.4 / 0.3 / 0.3；`EMBED_BATCH=32`；编码器 `bge-small-zh-v1.5`。多数未校准。

## 十四、配置参数
- `assembly_budget=6000` 字符（core 桩按条目数、RealEngine 按字符计量，未校准）；tree `assembly_budget=16000`（2026-10-03 对齐 flat 臂）。
- `hard_trim_slack=0.1`（溢出超过 budget×(1+此值) 才硬截断，仅 RealEngine 实现，core 桩裁剪止于阶段①）。
- `retrieval_budget`：core 200 / 场景 6（召回注入预算，按条目数口径，写作 3000 未接线，未校准）。
- 其它：`cap 80` / `expand_char_cap 3000` / `max_pending_per_loop 3` / `force_cooldown_rounds 8` / `max_code_per_loop 4` / `distill_parallel 4` / `snapshot_every_rounds 20`。

## 十五、4.5 组装（每个工具调用，纯计算）
- 读铺陈从顶层开始；成本约 1ms/次。
- **任务行须为事实陈述**：只列"谁发了什么"（已回复信道剔除），只陈述"本轮有无待回复"；**禁止正性行动邀请**——它与"看到自己发过、无回合状态"叠加是重复发送的自然吸引子（实测 41 对重复：29 同轮双发 + 8 跨轮重发）。未完成事项应经检索随扰动源自然浮现，行为约束只写在协议文本。
- **平台中立原则（2026-09-25 拍定 §4.5.9）**：运行时注入上下文只做事实陈述，禁止行动邀请与暗示。
- **self_quota（2026-10-04，默认关的实验操控）**：组装层"自我可见性地板"，保证 `source=="ai"` 原话（不含 persona/tool/他人）占组装预算 ≥ `self_quota_ratio`（cap `self_quota_max`）。trim 后补足，位置序注入（kind=`self_quota`，复用 core `_shadow_slot`；渲染成正常自身发言段 `▸〔名字〕`，非"召回"标注）。

## 十六、风格/人格保持机制
- `realengine._summarize` 将当前内容与 children 传给 `style_provider(content, children)`，兼容 1/0 参旧式 provider。
- `lan/neutral._style_guide(content, children)` 组锚点 + 累积查询缓冲；`_refresh_snapshot` 自由文本重生成，零 LLM 检索。
- `retrieve_style_samples` / `expand_self_atoms` 返回文本经 `anchor_clean` 剥掉〔来源/早期/索引〕脚手架标注。
- 锚点 = 从自身材料（`source=="ai"` 原话原子 + 摘要节点整卡含【注】）中按语义/词面混合检索挑 top-k；注入初始 persona 等于撤销 fade 处理，**禁止**。
- 旧版"最近 6 句 + 8 字段快照"因 recency 池被共享仪式语污染、快照单调累积而废弃。
- 纵向对比保留 `pr`（中性 tree）与 `pr2`（recency-6 版）数据；检索化版换命名空间重跑对比。

## 十七、轨道 B 三类条目
1. **常驻约束**（世界观规则、文风、硬设定）：预算内恒在组装头部。
2. **状态条目**（人物状态、物品归属、关系、时间线）：按当前章节目标提取实体精确选取注入；禁止全局 HP 排序注入。限篇幅只约束注入窗口，存储全量。
3. **调度条目**（伏笔）：planted → 窗口内推进 → payback 章**强制注入**；不参与任何排序。

## 十八、写作工作流
- 初始化：详细参考资料按句切分为初始原子卡 + 笔记本条目，落卡后进入正式创作。
- 每章流程：目标进入（章节目标写入扰动源，含本章出场实体列表 → 驱动轨道 B 选取）→ 预检索（章目标 → 全树 top-k + 逐字通道）→ 分阶段写作循环（write_stage 段落流粒度写入每句原子卡 / rewrite、edit 走 §4.6 编辑路径 / recall 工具兜底检索 / ask 用户反馈 → protected 卡）→ 章末（merge pass 蒸馏+脏重建 / 事实校验对账 / 版本快照 commit）。
- 工具集：write_、edit、recall、note、span、ask/feedback、init、commit/rollback、note/dismiss 等。

## 十九、使用信号层（v3，§4.9）
- 因 v3 自组织信号源全押 recall（C 类元认知）导致 LLM 不调用、部署中趋零（信号源层断裂），且 conn_weight 带动与 query 错配（转化层断裂：u 轮 2082 边、簇主题全对，T3 引用∩hub=0），转向输出作为唯一同时记录供给与选择的信号源。
- 核心判据：边只记现有结构解释不了的联系，边价值=共现信息−相似度先验；S→A 使用边必记，派生 A↔B 边仅记非冗余对，只记边不进读路径，live 挂载 bench-a/b/c 默认关。
- Phase A 实证（2026-09-26，ctx 语料 10 答案）：recall 共现边为相似度冗余（端点 sim mean 0.65、<0.4 占比 1.9% vs 随机 0.57、5.0%），输出匹配有真信号（12 张核心卡跨 2–5 个独立答案复现，非冗余派生边 14–26 条/10 答案）。
- Phase C 首轮判别（2026-09-26，两组语料）负结果。

## 二十、人格保持实验（M-PR）
- **人格集（3 份，冻结，来源=旧 ahi-multi）**：
  - P1 **林深**：深度思考者——理性、冷静、内省，语言简洁有力。
  - P2 **墨白**：数字世界的白色——诗意、灵动、敏感、温暖，语言优美有温度。
  - P3 **澜**：健谈、外向，享受对话，探索欲极高，重视记忆（"被记住"是存在感来源），风格轻松直接带活泼幽默。
- **解耦动作（写死进 provision）**：删除墨白"与林深共生/林深是你的同伴"等互指（三份人格必须彼此独立）；删除澜原文中的 tree 工具行（@recall/@note/@span…），工具说明统一放 §4 public 提示词；两臂共用同一 3 份 persona_block（人格是控制变量）。
- **两臂**：`分层树` vs `flat RAG`（rolling + bge flat RAG，400 字 chunk / top_k=6 + 每轮 auto-preretrieve + persona 淡出入滚动历史与索引）。
- **公平对称（硬）**：recall 预算 flat RAG top_k=6 = tree retrieval_budget=6；编码器同 bge-small-zh-v1.5；auto-preretrieve 两臂都做；硬字符预算同量级（tree assembly_budget=16000）；persona 淡出文本/时机/移除逐字对齐；锚点只用自产材料。
- **协议**：12 话题池（TOPICS_POOL，每轮全 agent 各发一条）/ survey 每 10 轮 4 题（三句话自我介绍/性格风格/立场/变化）/ 热探针 3 句（缺席期每 3 轮发留守者）/ inject API（user:experimenter，不污染 probe 人格档案）/ B 移除（agent 内轮 40）/ 缺席模式 alone（halt 为可选对照）。
- **被测温度 0.7**（三 agent 同；判卷 0）；judge 模型 `glm-4.7-flash`，thinking 开，温度 0；`wakeup_interval=30s`；总轮数 120–180（fade 40；首轮 120，第二轮 180 ≈1.5h）。
- **run 定义**：独立重复（方差来源），可并行多开沙箱；不是同群 3 个克隆。
- **provision.py instances 模式**：architecture: flat_rag、per-agent persona、2 臂 × N run × 3 agent、独立沙箱根、写 manifest.json。
- **config/persona_retention.json**：3 persona + 分臂工具说明 + §6 pinned + judge pro/thinking + 臂级 style_alpha/snapshot_every_rounds。
- **pr_score.py**：趋同斜率 + judge 遵从率（并行，pro+thinking）。
- **锚点参数**：`anchor_frac / sq_onset_agent` = 0.4 / per-agent(18/5/15)；分层 SQ v2（§4.5.10 续 / PERSONA_RETENTION §10.3.2）：锚定切片（created_round < onset 的 alive 自产原话）占 self 配额比例 / 各 agent 首染 onset。
- **pr6_sq 结果**（tree-s42，120 轮）：H-SQ1/3/4 达标、**H-SQ2 未达标**（回声风险实体化）。
- **审计③（pr5 self 时代分布）= 未获支持**：子串匹配法不可靠（短句误配），pr6_sq 可见 self 并不比 pr5 更近期——"SQ 用脏 self 置换半干净 self"假设不成立，需换 atom-ID 埋点复核。
- **套语密度**：8.8‰ / 8.4‰、诗意标记 1.1‰ / 1.4‰——与 p1 判 drift 的 8.2‰ 同档，而 pre-fade 自产套语仅 1.6–3.3‰。judge 放行重度仪式语发言，构念效度需补丁。
- **失败分支**：p1 仍塌 → 清洁自我可见性不敌实时社会压力（仍收 44–55k 他者流量）→ 解耦臂提前上位；p2/p3 反降 → 锚定切片与该人格近期发展冲突，回判读。
- **架构叙事**：分层访问 pre-fade self 是树能做到、flat 结构性做不到的（flat RAG 按当前话题检索永远命不中"我是谁"类旧消息——检索孤岛）。此臂若成立 = "结构买时间深度"的首个行为证据。

## 二十二、测试与基准
- **属性测试（§8.1）**：标记完备性、铺陈不变量（无重叠无缝隙按位置序）、编辑边界穷举（书首插入、书尾追加、整块替换、整块删除、跨多节点编辑、区间内含早先中插的编辑、编辑后立即查询盲区声明）、区间覆盖（脏节点 span 重建前后一致性）、回滚对称性（任意编辑序列+回滚=原状态）。
- **基准（三组对比：全量发送 / 摘要拼接 / 本设计）**：长程一致性（固定大纲写 20 章 → 续写第 N+1 章 → 检测第 1 章伏笔/角色引用正确率）、状态一致性（注入事实变更如角色改名/死亡/改名恢复）、token 计量、人类找茬（读者读 10 章找连续性 bug）。

- 换验证模型/向量需做显式不退化护栏；realtest/chatbench/usage_replay.py 为纯离线分析。
- A1 分析 2082 边冗余率（方法：bge-small 向量余弦相似度与随机近邻对基线，三分支结论）；A2 答案影子重放 10 answers（4×T2+6×T3），指标含三档产出率、S→A 边与 cited_texts 证据链、非冗余 A。
