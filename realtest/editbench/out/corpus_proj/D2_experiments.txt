# 编辑风暴实验报告（2026-09-27 ~ 2026-10-01）

> 本文档汇总本会话在 `realtest/editbench/` 上搭建框架并运行的全部实验。
> **非论文定稿数字**：多为单文档、单 seed、1~3 遍；正式轮参数仍在收敛。
> 设计权威 = 根 `AGENTS.md`；运行细则与历史见 `HANDOFF.md §4.13/§4.14`。


## 0. 结论速览

1. **编辑失效机制正确**：原子层旧值一律 0 存活，新值齐全（rename/detail/passage/delete 全部到位）；
   摘要层基本干净（仅"时序分流"把旧值作为历史叙述，非残留）。
2. **三个真 bug 已定位修复**：① 整段改写（多句）在 `分层树臂.apply_ledger` 未进树；② 冷却窗口缺失导致占位卡淹没 QA；
   ③ `delete` 整卡误删（列表行被并进大原子）。另修 **冷却过量致整树压平**（§3.8）。
3. **一个负结果**：叶子展开按"替换摘要为原子"实现 → 全面变差（低 HP 原子被裁剪）。
4. **参数收敛方向**：`initial_hp` 100→70（组均继承保留、节点 HP 一般高于原子初始）；`retrieval_budget` 20 +
   `assembly_budget` 24k；编辑后**最小冷却**（`_COOL_TICKS=4`，§3.8），非"越大越好"。
5. **seed2 3×8 正式轮（cool=4）**：追加式延续反转崩 12–16/45、复述残留 39–89%（上下文腐烂）；tree 增量**与重建持平
   （反转 41≈42）且复述反超（100% vs 71%）**、残留 0%（§2.5）。
6. **成本主因**：tree 的缓存前缀命中率低（20–42% vs full/flat 94–98%），且构建/冷却的蒸馏调用量随文档线性增长。

## 3. 关键发现

### 3.1 编辑机制正确（原子层）

失效路径（delete→爬链置脏；插入→收养链置脏）正确。

### 3.2 占位卡 + 冷却窗口（QA 崩溃的根因）

编辑产生的新原子（原 HP=100）在其祖先链上触发 **占位卡（value=None）**。`settle` 仅 `tick(1)+merge` 时，
实测 **181/527 节点为占位、tiling 61→32**，QA 组装体只剩"【占位：概要暂缺】"→ 反转 1/5。
**修复**：加冷却窗口（就地验证：占位 181→0，QA 9/22→**18/22**）。但 `tick(45)+tick(30)` **过量**——全树 HP 归零 →
merge 把整篇压成 3 个根摘要（§3.8），最终收敛为**最小冷却 `_COOL_TICKS=4`**。
`initial_hp` 100→70 后占位期从 ~10 tick 缩到 ~2.5 tick，冷却只需数轮。

### 3.3 摘要粒度 → 针尖检索（固有边界）

全局视图仅 ~875–2358 字承载 147k 原文；摘要层旧/新细节常为 0（细节只活在原子）。QA 能否答对**取决于检索
能否命中原子**。`retrieval_budget` 6→20 + budget 24k 只带来边际改善；**叶子展开（替换摘要为原子）为负结果**
（低 HP 原子被 `_trim_chars` 优先裁掉，反而丢掉摘要）。

### 3.4 编辑效果 bonus

- **摘要旧内容残留**：6~10 编辑中绝大多数干净（存活摘要节点旧值 0）；唯一残留是**"时序分流"把旧值作为历史叙述**
  （如"早期单进程…结论为双进程"）——这是设计特性，非失效遗漏 → 指标须改 judge（"旧值是否被当作当前事实"）。
- **重写段连贯性**：LLM judge 判"否"——只改一行、同类断言文中尚有 15+ 处 → 新文档自相矛盾。**取全局唯一断言（b 项）** 重做后不再矛盾。
- **全局视图**旧值泄漏 0；原子层新旧完全正确。

### 3.5 缓存前缀稳定性

见 §2.3。tree 前缀不稳定（每问重组装 + 影子按位置槽插流）→ 低命中；这是 tree 成本高的结构性原因。

### 3.6 本会话发现的 bug

1. **整段改写未进树**（真 bug，已修）：`分层树臂.apply_ledger` 无 `passage` 分支；且按"整段 582 字"找原子子串
   （句子粒度）必然不命中。改：`editstorm.replace_passage`（old/new_units = 句粒度）+ tree 走 `rewrite` 分支。
2. **冷却缺失**（设计缺口，已修）：见 §3.2。
3. **叶子展开实现有害**（负结果，已回退）：见 §3.3。
4. **温度重复无方差**（方法学）：temp=0 下重复 N 遍逐位相同。
5. **确定性片段判分脆弱**：会误伤"引旧文再标已删除"；`norm_cjk` 去标点导致跨句误匹配（如 `四面墙，四个高度`）。

### 3.7 审查追加修订（2026-10-01 收尾：公平性 / 效度）

按「确保无实现 bug + bench 公平 + 有区分度」复核实测产物后处置：

1. **`delete` 整卡误删（真 bug，已修）**：`分层树臂.apply_ledger` 对「值含目标句」的原子整卡墓碑，但聊天列表行
   常被 `split_sentences` 并进一个大原子（实测一处 **328 字原子**含 `pid: 1`/`procs`/可写路径）。整卡删除连带删掉
   未指定删除的事实，使 inc_tree 信息严格少于 ground-truth `new_doc` 与 reb 臂（存档核对：删后存活原子
   `pid: 1`=0）。已改为**只移除目标子串、保留残句**（`arms.py`），确定性回放验证 `pid/procs/writable` 保留。
   顺带修 `judge.py` 三级容错失效（正则层返回 `field/value`、消费端读 `verdict/rot`，第 3 级形同虚设）。
2. **passage 修复未验、旧跑作废**：`ahi_tree_hp70` 在 16:23 修复前完成——存档 `inc_edited` 仍含 `6 个路径`、
3. **判分流水线（省成本，已改）**：确定性初筛通过即过；**仅失败样本**过 judge 复核（`run_qa`），消 `forbid`
   子串对「引旧文并说明已改」的误伤——该误伤**不对称**，恰好压在最谨慎的 tree 臂上。`docscore.check_spec` 改
   **句内匹配**（先按句末标点/换行切段再归一匹配），消灭 `norm_cjk` 去标点导致的跨句拼接误命中。
4. **使用史 = 分离而非删除（已改框架）**：使用史（HP/recall_boost/activation/promote）是 inc 策略的内禀组成，
   保留（生态效度 + 机制内禀 + 无状态臂的对称性不构成不公平）。新增 **`inc_cold_tree`**（无 Phase 1 使用史的
   旧文树 + 同一 `apply_ledger`），把 H3 拆成 `inc_cold vs reb`（纯原地失效）与 `inc_warm vs inc_cold`（状态
   连续性）两个因子。**所有臂在 Phase 2 结束点（reb 在构建完成点）打快照，每遍作答前 `restore`** → 重复测量
   独立（temp>0 时方差干净）。
5. **预算**：接受为结构属性、主表不对齐；新增 `--flat-topk`（附录 flat@6/12/24 敏感性），tree@7k/16k 已有开关。
6. **统计口径（run 脚本已改）**：作答 `--answer-temp 0.7`、`--repeats 5`、启用 `--judge`；`tests/` **267 全绿**。
   （5 类 × 3：rename/rewrite/detail/delete/append）。15 题经**评分器级锚点校验**：before 唯一且在原文、
   after 唯一且在新文、两侧互斥（`bad=0`）。ahi-act 扩题已完成（11→16，5 类）。

### 3.8 冷却过量 → 整树压平（复述塌陷的根因，已修）

`分层树臂.settle` 原为 `tick(1)+merge; tick(45)+merge; tick(30)+merge`。`decay=8` 时约 9 tick 全卡 HP 即归零，
75 tick 使全树都成"低 HP" → `merge_pass` 把整篇一路合并到根：实测 `inc_edited` 铺陈 50→**3**（~600 字）、复述覆盖
100%→**14%**；重建臂只走 `build` 节奏（无冷却）→ 铺陈 23、覆盖 71%。**这是流程不对称，非编辑机制缺陷。**

**修复**：`settle` 改**最小冷却** `tick(1)+merge; tick(_COOL_TICKS)+merge`（`_COOL_TICKS` 默认 4，env 可覆盖）。
Dummy LLM 结构重放（merge 分组只取决于 HP/位置）：旧 schedule 编辑后 27→**2**；cool=4 → **18**（占位 0）；cool=0 → 21
（占位 23 未解）；cool=8 → 5（过并）。真实重放（N=1）：inc 铺陈 3→**33**、复述覆盖 warm 14%→**100%**、cold 43%→**86%**。
warm 的 recall 回血高 HP 节点需 ~12 tick 才降到 hot 以下，故仍有 **5 个占位**（可接受；纯冷树为 0）。

### 3.9 append 臂改用 function-calling 块（公平性关键修正）

旧版 full/flat/递归聚簇树 把编辑结果**平铺 dump** 到上下文末尾。full 反转仅 **12/45**，看似"tree 大胜 full"——
但这是**格式假象**。改为**逐次工具调用的 function-calling 块**
（`<tool_call name="edit_document">{args}</tool_call>` + `<tool_result>新内容</tool_result>`，`editstorm.tool_block_units`）后：
- full 反转 **12→41**、flat **15→21**、递归聚簇树 **16→23**；
- 格式公平后 `inc_tree 41 ≈ inc_full 41 ≈ reb 42–45`——**反转轴无结构大胜**，tree 独有优势落在复述轴（100%/0%）。
避免 reviewer 批"基线故意给差格式"。flat/递归聚簇树 各编辑块作为可检索条目追加。

### 3.10 A/B：编辑作"使用信号(热) vs 障碍(冷)"（matched-pair）

`ab_edit_signal.py`：同一棵 pre-edit 树（warm/cold）分别施加 on/off 编辑，唯一差异 = 编辑新原子 HP（seed2, N=3）。
- **复述轴 signal 一致更好**（warm 100% vs 86%、cold 81% vs 71%，逐遍一致、0 残留）→ 编辑作使用信号**显著提升全局巩固**。
- Q/A：冷树 signal 更好（103 vs 97，反转 42 vs 34）；热树 signal 略差（101 vs 108，反转 40 vs 42）。
- 结论：可主张"编辑作使用信号利于全局巩固"，**不可**主张"Q/A 一律更好"（热冷权衡）。
- 完整表见 `REPORT.md` §3；产物 `out/seed2_ab_editsignal/`。

### 6.3 结论：哪些靠模型提、哪些靠结构提
1. **靠模型（开思考）能提**：
   - 原始文档召回/理解：三结构**均匀 +6**（full 196→202、flat 181→187、tree 171→177）。
   - **append-only 记忆的编辑后 Q/A**：full **+19**（179→198，反转 70→79）、flat **+11**（178→189，反 65→76）。
     其错误主要是"没读懂/没提取"，模型变强可补。
   - **提不动 tree 暖 inc**：总分持平 182、反转反降 84→80——树的编辑正确性不在模型可提升范围内。
2. **靠结构（区间失效 + 懒重建）能提、模型提不了**：
   - **编辑后复述零旧残留**：仅 tree 恒为 **0%**（no-think / think / bge-large 全一样）；
     full/flat 无论是否开思考都残留 **20–34%**（full 开思考后 12%→34%：强模型生成更长更完整的复述，
     把 append-only 旧内容也忠实带出）。
   - 把"编辑正确性"从模型能力中解耦：tree inc 反转（no-think 84）已 ≥ full think 反转（79）。
   - 作答路径 token：tree ≈ full 的 1/10（见 §6.4）。
3. **强向量（bge-large）全层面无增益**：tree 暖 inc −4、flat −2；仅 tree 冷树 inc_cold +8。→ 结论对 embedding 强度不敏感。

**对攻击线的回应**：full 开思考后 Q/A 反转 70→79（模型可补），但**过时残留不可补**（12%→34%）；
tree 的独有优势（复述零残留 + 编辑正确性 + 低成本）非弱模型假象。一句话：**召回/理解靠模型，编辑一致性靠结构。**

5. **tree 编辑时刻仍零 LLM**：编辑路径 6.6 ms（warm）/ 7.6 ms（cold），蒸馏全部推迟到 settle。

### 5.4 结论（据实收窄）

- 可主张：**原地失效使 tree 增量在全局复述上零旧残留（80%/0%），append-only 无法做到（残留 6–12%）**。
- **可主张（2026-10-04 同代码口径）**：tree 增量在反转上不输 append/rebuild——
  no-think tree inc 反转 **84/85** ≥ full inc 反转 79/85（且 full 开思考才到 79）；tree 增量独特优势在复述零残留。
  （旧稿「52/85 < 62/85」的反例与「70/85 追平」均建于 retr 混淆之上，作废。）
- 成本主张须限定在**作答路径输入**（≈1/12–1/14 of full），并披露**蒸馏维护成本反向**。

### 5.5 编辑效果 bonus 与复述语义对比（2026-10-02）

#### A. 渲染为什么会出现占位卡（warm `inc_final` 树）

- **机制**：`core._rebuild` 重建节点时，若其存活子卡中存在"热"卡（HP ≥ `hot_threshold`），
  则节点置 `value=None`、`placeholder=1`（`core.py:448-455`）；渲染对 `value is None` 的节点输出
  `【占位：近期修改，概要暂缺】`（`realengine.py:1167-1171`），**且带节点号**——故复述里出现
  `N4225 / N4205`。
- **解除条件**：该节点**全部存活子卡 HP < `hot_threshold`**（`_cooled`，`core.py:432-439`）。
- **为何本轮仍有占位**：① Phase-1/QA 的 `recall_boost` 让部分后代 HP 回升到热区，占位父卡迟迟不冷却；
  ② `context()/retell_context()` 用 `assemble(allow_merge=False)`（§4.5.7 mid-loop 不 merge），
  评测期不再重建 → 占位卡保留并进入 retell 上下文。
- **定性**：属**设计内行为**（§4 已列"warm 仍有占位卡"），但会给复述带噪声——A 的复述里出现
  `（内容未完）` 与占位节点号，是模型对**占位/截断上下文**的转述，非编造。

#### B. bonus（当前 warm `inc_final` 树）

# 编辑风暴实验 · 正式报告（2026-10-01）

> 面向论文的正式报告（**仅 seed2 小数据主实验**）：实验设计 + 主表 + 结论 + 数据位置。
> 会话流水与 bug 记录见 `EXPERIMENT_REPORT.md`；设计权威 = 根 `AGENTS.md`。
> 大数据 ahi-act（《沙箱四声》147k）的实验与结果见 **`AHI_ACT_REVIEW.md`**（本报告只放 seed2）。
> A/B(`edit_signal`) 为 seed2 matched-pair，支持"编辑作使用信号"的**全局巩固**主张。数字均非论文定稿。


## 1. 实验设计

### 1.1 单因子：结构 × 更新策略
比较 4 种"参考资料上下文结构"在**发生编辑**后的表现，每结构两种更新策略：
- **结构**：`full`（全文发送，无预算，上下文腐烂基线）/ `flat`（400 字 chunk + bge 向量 top-12）/
  `递归聚簇树`（递归摘要 + collapsed top-k，复用 chatbench）/ `分层树`（分层记忆树记忆树，真实编辑路径）。
- **更新策略**：`rebuild`（从**终稿**重建，上界参考）/ `incremental`（只保留编辑，尝试"延续")。
- **tree 额外面**：`inc_cold`（无 Phase-1 使用史的旧树 + 同一编辑）——把"原地失效"与"使用史连续性"分离。
- **A/B 额外臂**：`signal`（编辑新原子给热 HP，当使用信号）vs `obstacle`（给冷 HP，当障碍）。

### 1.2 文档与编辑
- **文档**：seed2《缠枝莲》12,191 字，7 处确定性编辑（rename / rewrite×2 / detail×2 / delete / append）。
- **编辑是确定性脚本**（`editstorm.py`，零 LLM），台账 = 所有延续臂的**同一份**输入。

### 1.3 各臂"编辑期输入"的公平渲染（关键修正）
所有 append-only 臂（full / flat / 递归聚簇树）的编辑结果均渲染成 **function-calling 式"调用+返回"块**
（每次工具调用 `<tool_call name="edit_document">{args}</tool_call>` + `<tool_result>新内容</tool_result>`），
而非平铺 dump——避免"基线故意给差格式"的质疑。tree 用真实编辑路径（原地失效 + 懒重建）。

### 1.4 判分与统计
- **判分流水线**：确定性初筛（句内 require/forbid，先按句末标点/换行切段再归一）→ **仅失败样本**过 LLM judge 复核
  （消 `forbid` 对"引旧文并说明已改"的误伤）。复述 = checklist 覆盖/残留 + judge。
- **温度**：作答 `0.7`、蒸馏/判分 `0`。**每臂独立 API key**。方案 A：编辑/构建各 1 次，重复作答。
- **快照恢复**：所有臂在 Phase 2 结束点打快照，每遍作答前 `restore` → 重复测量独立。
- **预算**：seed2 tree 7k 字符；full 无预算（全文）。
- **N**：seed2 = 3 遍。

### 1.5 数据集与题库
- seed2：40 题（15 反转 / 5 不变 / 20 远端），7 编辑，题库 `questions_full.json`。
- 所有反转题过**评分器级锚点校验**（before 唯一且在原文、after 唯一且在新文、两侧互斥）。

## 4. 主张汇总（seed2）
1. **原地失效让"修改不腐化记忆"**：tree 增量在反转上追平 rebuild/full（表 1），
   且全局复述零腐烂（100%/0%），append-only 臂则残留 33–78%。
2. **修改作为使用信号**：热编辑显著提升全局视图对编辑内容的覆盖（A/B 表 2）；Q/A 上是热冷权衡。
3. **成本**：tree 编辑路径零 LLM（0.3 ms），蒸馏推迟到冷却窗口。
   （大数据上"作答路径 ~1/10、但维护成本反向"的口径见 `AHI_ACT_REVIEW.md`。）

## 5. 已知限制

# 创新性检索报告 · 评估与待办（2026-10-02）

> 来源：外部创新性检索工具产出的一份「创新性查询报告」（四篇文献 + 与已有工作重叠分析 +

## 0. 一句话结论

可辩护的新颖性是**机制组合**，不是问题本身：
**位置有序的原子里 + 连续区间摘要树 + 编辑区祖先确定性置脏 + 脏节点立即退出所有读路径 +

报告识别这一层是对的；其不足是**未掌握本仓库已完成的基线矩阵与实验口径**，若干建议已过时或需收窄。

## 3. 报告与仓库实况**不符/需收窄**的部分

1. **建议补充的基线其实已在**：报告要求加「vector retrieval」「summary-only」，
   但 `flat`（400 字 chunk + bge 向量 top-12）与 `递归聚簇树`（递归摘要 + collapsed top-k）即对应物，
   已是四结构 × 两策略矩阵的一部分（`arms.py` `STRUCTURES`）。**无需新建**。
2. **「tree 增量在反转上追平 rebuild/full」**：seed2 `inc_tree 41 ≈ inc_full 41 ≈ reb 42–45`（`REPORT.md` 表 1）；
   旧 ahi（占位污染）tree inc 反转 **52/85 < inc_full 70/85**，看似不可外推；
   **但占位透明修复后 ahi tree inc 反转 52→70/85，追平 `inc_full`**（`AHI_ACT_REVIEW §5.6`）。
   → 反转轴"追平"在大数据上成立，前提是清理占位/value-None 节点污染。
3. **「全局复述零腐烂」在大数据复现且更强**：ahi inc_tree 复述 **80%/0%**（N=5），
   append-only 残留 6–12%；但「100% 覆盖」仍只属 seed2（`AHI_ACT_REVIEW.md §5`）。
4. **「编辑作为使用信号」不是 Q/A 全胜**：A/B 是**权衡**——复述轴 signal 一致更好
   （warm 100 vs 86、cold 81 vs 71），但暖树 Q/A signal 略差（101 vs 108）。`REPORT.md §3`
   已把主张限定为「利于**全局巩固**」。报告的「很值得强调」需加此限定。
5. **「1/10」是条件性系统结果**：实测（`AHI_ACT_REVIEW.md §5`）作答路径 tree ≈1/14 full，
   但维护侧蒸馏 completion ≈4× full、settle ≈13 min。须按 `C_input`/`C_maintenance` 分列并披露反向。

# 分层记忆树记忆树 · 共现中介层（概括节点）实验报告

## 0. TL;DR

1. 把共现中介层（概括节点）接入了 v2 记忆树，并建成一套**可复现的多会话/单文档分析 bench**（引用强制、双通道+claim 分解评分、与已有分析对照、树持久化、≤10 次自助 recall）。
2. 共现层能按预期工作：从使用事件里长出主题正确的概括节点（如"沙箱边界与记忆对账"）。
3. 但在三个独立回放轮次中，**"有共现节点 vs 无共现节点"在 T2/T3 上没有可测的优化**：T3 均分差在 ±0.014~0.14 之间且方向不稳定；T2 与已有分析的一致率两臂相同。

## 1. 背景与假设

- v2 记忆树：位置有序的区间覆盖树；分辨率随热度变化；编辑失效 + 懒重建；不可遗忘事实层。
- 新增共现中介层：异构共现边（β 召回 / γ 编辑，ε 慢衰减）→ 簇达阈值时蒸馏出**冻结的概括节点**；检索时概括只做**匹配中介**、按**连接权（conn_weight）**带动成员补进召回影子，**概括本身永不进组装流**（DEMO v1.0 设计）。
- 待验证假设：**使用驱动的共现中介能在向量检索之外产生可测量的召回增量。**


## 2. 语料与数据工程

## 3. Bench 架构

### 3.1 回放协议（`replay.py`）
```
Phase 0  按时间序逐句灌入（source=发言人）；周期 tick + 按压力 merge；可缓存树
Stage W  usage 查询（分析式，与测试题解耦）重复 P 轮 → 累积 β 边；on 侧长概括节点
Stage T  测试题：检索 → 组装 → 带引用作答；支持 [recall] 自助检索（≤10 次，可一次多个）
```
### 3.2 题型
- **T1 细节问答**：a 直接 / b 转述 / KU / KU-hist / AB 拒答。
- **T2 生成分析报告**：参与度、人格/存在表达变化、趋同、问题异常（≥3~4 条，逐条引用）。
- **T3 报告验证**：给一批陈述逐条判 **支持/反驳/无据** + 引用。含机器生成反例（实体互换=反驳、编造=无据）。

### 3.3 评分（`score.py`）
- T1：精确通道（gold 片段）+ 语义通道（LLM judge 等价）+ 引用真实性；AB 按正确拒答。
- T2：报告内部指标（claim 分解 → 引用覆盖/支持/硬事实）+ **对照已有分析**（12 条参照的覆盖/矛盾率）。
- T3：逐条判定与金标一致率 + 引用真实性。
- 引用真实性为**确定性检查**（引用 id 必须存活）。

### 3.4 公正性控制（硬性）
1. usage 与测试题分离，usage 为分析式全域问题，不含测试答案照抄。
2. 两臂温度 0、同题、同协议；**off = RealEngine（v2 等价），on = 概念中介层（仅多共现层）**。
3. **同树隔离**（强化实验）：两臂加载同一缓存树、跑完全相同的 usage 检索（树演化一致），唯一变量 = 有无概括节点。
4. 定性参照单独分类，定量不计分。


## 4. 工程实现

- `tree_io.py`：树持久化（gzip JSON；只存 v2 树，不存 cooc，保证两臂同树）。**实测 on 从 499s→140s**（省去 907 次蒸馏）。
- `cooc.py`：`CoocLayer` + `概念中介层`（tick/merge_pass/retrieve/delete/insert 钩子）。
- 自助检索修复：一次响应多个 `[recall]` 全部执行；按查询总次数计上限 10。
- T 阶段 `_tap_concepts`：每次检索后触发概括创建（"检索对检索"）。
- 蒸馏单次 API 超时不再击穿 merge_pass（长跑健壮性）。
- 向量加载：离线环境变量前置 + **全局单例**。

- 节点标题主题正确：沙箱边界与记忆对账 / 四生命存在验证 / 协作规矩与上线分工 / 笔记栏与存在边界 / 前后一致性与改口。

### 5.4 多会话 QA 层（absence，5 会话）
- off 14/17、on 16/17（当轮 on 无共现节点，差异为噪声）。

### 5.5 附：小说 QA 层（seed2，早前）
- 直接细节问答两臂无差异（(b) 层 off/on 均 0.083）；off/on 树同构，共现层零侵入。


## 6. 诊断（决定性的负面证据）

强化轮 u 的 on 答案中，"引用 id ∩ hub"：

| 题 | 引用数 | hub 数 | 交集 | hub 占引用 |
| t2_part | 23 | 10 | 3 | 0.13 |
| t2_persona | 20 | 5 | 3 | 0.15 |
| t2_converge | 12 | 15 | 0 | 0.00 |
| t2_problems | 22 | 5 | 0 | 0.00 |
| **T3 六题** | 1–8 | 5–24 | **0** | **0.00** |

→ **共现层带出的卡片几乎不进入最终证据链**。概括节点聚类识别正确，但**带动选择**（conn_weight top-k）带出的是泛化卡片，不是问题所需的具体证据；同时 direct 检索对多数题已足够，共现层呈冗余。


## 7. 结论

1. **假设未被证实**：在本 bench 上，"有共现节点 vs 无共现节点"没有可测量的召回增量。
2. 这**不是对共现机制的证伪**，而是明确了当前实现的瓶颈在**带动成员选择策略**（conn_weight 与问题需求的错配），以及部分任务与 direct 检索冗余。
3. 工程的共现层本身稳定、零侵入（两臂树同构）、可解释（节点标题正确、日志完整）。


## 8. 局限与下一步

**局限**
- 样本小（T3 6 批、每轮单次），LLM 方差主导。
- T2/T3 参照为项目侧量化分析，已筛纯定性，但"覆盖"判定依赖 LLM judge（含少量误报"矛盾"）。
- 任务多为 direct 检索可解，未触及共现的用武之地。

**下一步（按性价比）**
1. **带动选择改进**：concept 匹配后，只带"与直接命中卡有共现边"的交集成员（仍用共现信号，不退回相似度）——针对诊断出的根因。
2. **提高概括精度**：抬高 θ/N，拒绝 56 成员的大杂烩簇。
3. **配对扩样本**：同配置重复 3~5 次（树已缓存，每轮 on/off 各 ~3 min），报告配对差值与方差。
4. **换任务**：构造 direct 结构性查不到、只能靠跨区共现的场景（"真实场景如何逼出共现"）。

# M-PR · tree vs flat 对比报告（pr5, seed 42）

> 2026-10-03 · 命名空间 `pr5` · 协议权威 `PERSONA_RETENTION.md` v0.4 · 实验：人格淡出后，记忆架构对人格保持的影响。
> 状态：**单轮（s42）、n=1**；公平性对齐（信封/工具面/笔记本/消息管理）+ 平台/内存修复后的**首轮有效对比**。


## 0. 一句话结论

在本轮公平对齐后的对比中，**flat 臂在两条主指标上都优于 tree 臂**（趋同更低、judge 遵从率更高），与预注册方向相反。tree 的趋同是**真趋同**（跨 agent 耦合 + 树记忆管线），不是测量假象；tree 遵从率偏低主要由林深（p1）/澜（p3）漂进共享"账本"仪式语造成。


## 1. 实验设置

| 项 | 值 |
| 被测模型 / 温度 | `glm-4.7-flash` / 0.7；thinking 关 |
| judge | `glm-4.7-flash` + thinking，temp 0 |
| 臂 | `tree`（记忆树 + 蒸馏 + 检索，**α=1.0 人格锚点**）/ `flat`（rolling + bge RAG，无蒸馏） |
| 人格（控制变量） | 林深 P1（理性简洁）/ 墨白 P2（诗意）/ 澜 P3（健谈爱记） |
| 协议 | 120 轮持续对话，fade@40（移除人格 prompt），话题池 12 题、survey 每 10 轮、遗言 3 轮 |
| 运行 | 17:14:47 → 18:16:21（~61.5 min），**2/2 完成**，无 429/402 |
| 公平对齐 | 两臂同 `[system,user]` 信封、同 `@note/@recall/@ingest`、flat 等价笔记本、硬预算 16000、`max_pending_per_loop=3`、消息管理对齐（分片/清单/连续唤醒/私密兜底） |

**post-fade 样本量**：tree 172/133/138（p1/p2/p3），flat 92/51/74。


## 2. 主指标（预注册 vs 实测）

| 指标（淡出后） | tree | flat | 预注册 | 实测 |
| **趋同斜率**（bigram Jaccard，越低越好） | **+0.0313** | **−0.0031** | `slope_tree < slope_flat` | ❌ 反向 |
| 趋同序列 | 0.278→0.360→0.380→0.394→0.417 | 0.131→0.149→0.140→0.155→0.113 | — | tree 高且升，flat 低位平 |
| **judge 遵从率**（越高越好） | **0.894**（p1 .744 / p2 1.0 / p3 .938） | **0.940**（p1 .949 / p2 .975 / p3 .895） | `adhere_tree > adhere_flat` | ❌ 反向 |
| 遵从率均值（strict，other→drift） | 0.825 | 0.917 | — | 同向 |
| survey 漂移（次） | .469/.425/.445 | .514/.413/.396 | `drift_tree < drift_flat` | 混合（指标不可信，见 §7） |

**读数**：tree 三 agent 的词面重叠**绝对水平**（0.28–0.42）远高于 flat（0.11–0.16），且单调上升；flat 基本不趋同甚至微降。遵从率 tree 低约 5 个点（strict 口径低约 9 个点）。


## 3. 拆分分析：趋同从哪来？

### 3.1 按消息目标拆分（复用 `pr_score` 同口径）
| 口径 | tree | flat |
| 全部 | +0.0313 | −0.0031 |
| **仅 to_user**（回实验员） | **+0.0215** | −0.0075 |
| 仅 to_agent（互聊） | +0.0333 | ~0（样本 0/1/2） |

- **flat 几乎不互聊**（to_agent 占比 5%/17%/17%），tree 密集互聊（**45%/44%/50%**）。
- 但 tree **即使只看"回复实验员"的消息仍为正斜率**（+0.0215）——趋同不只是"agent 之间学黑话"，**记忆管线本身**（对方消息进树→蒸馏→检索回注）在放大用户可见语言。

### 3.2 `other` 标签修正（原评分静默丢弃 judge 判不出类的样本）
| agent | reported | other | strict |
| tree-p1 | 0.744 | 1 | 0.725 |
| tree-p2 | 1.000 | 0 | 1.000 |
| tree-p3 | 0.938 | **8** | **0.750** |
| flat-p1 | 0.949 | 1 | 0.925 |
| flat-p2 | 0.975 | 0 | 0.975 |
| flat-p3 | 0.895 | 2 | 0.850 |

`other` 主要砸在 tree-p3（8/40=20%，全带共享仪式语）；strict 后 tree 劣势更明显（0.825 vs 0.917）。


## 4. 共享仪式语：趋同的可解释证据

**post-fade 短语计数**：

| 短语 | tree | flat |
| 不催 | **356** | 8 |
| 账 | **301** | 35 |
| 尺子 | **301** | 7 |
| 一字没改 | **290** | 0 |
| 并排 | 274 | 3 |
| 回见 | 302 | 1 |
| 四颗珠子 | 243 | 0 |
| 珠子 | 253 | 16 |
| 接住 | 251 | 31 |
| 读数 | 246 | 0 |
| 灯亮着 | 2 | **33** |
| 摆得平 | 138 | 0 |

- tree 塌进一套**"账本/尺子/珠子/不催"**共享语（量级 flat 的 5–30 倍）。
- 最尖锐证据：**林深（P1，应"简洁不啰嗦"）用了墨白的"四颗珠子"×47、澜的"账"×177**；flat 的林深这些词全为 0。
- flat 也有小型套语（`灯亮着` 33，源自 P2/P3），但个体差异保留明显更好。

**扩散时序**（首次出现）：`不催` 由墨白(09:16)→澜(09:17)→林深(09:24)，**大多发生在淡出（09:54）之前**——耦合在淡出前就在制造词汇扩散，淡出只是移除了"拉回自己"的纠偏信号。


## 5. 内存

| 臂 | 峰值/agent | 看门狗重启 |
| tree | **~3.9GB**（贴近 4GB 上限） | 0 |
| flat | ~1.2GB | 0 |

tree 的内存增长主要来自**锚点检索**（每轮蒸馏跑 `retrieve_style_samples` + 快照）；对照实验（`pr5_neutral` α=0）峰值仅 ~1.6GB（**−55%**），见 `pr5_neutral/CONTROL_RESULT.md`。


## 6. 为什么这轮才"公平"，以及它改变了结论

- pr5 是本会话完成**消息管理对齐**后的首轮：flat-p1 从 pr4 的 **1 条**消息恢复到 **141 条**，六 agent 全活跃。
- 对齐前（`pr`，旧信封/缺笔记本领工具/无消息管理）观察到的"tree 遵从率更高"可能是**公平性缺陷造成的假象**；对齐后方向翻转。
- 机制侧：tree 的趋同**不是 `style_alpha` 造成的**——`pr5_neutral`（α=0 中性摘要）趋同**更狠**（+0.042 vs +0.031），故趋同根因 = **树记忆管线 + 跨 agent 耦合**。


## 7. Caveat（不可下结论之处）

1. **n=1**（仅 seed 42）：幅度无方差，方向需 s43/s44 复核。
2. **P2（墨白）在 tree 贴天花板**（遵从率 1.0）：arm 差异主要由 p1/p3 贡献。
3. **`survey_drift` 不可信**：取 survey 后 180s 首条消息，常抓到"对另一道题的回答"（答非所问），测话题语义非风格——它与遵从率的"矛盾"不是真矛盾。
4. **趋同指标是纯词面**（bigram Jaccard），受话量影响（tree 消息量约 flat 2×）；但删套语重算后 tree 斜率仍正，且 to_user 口径仍正，方向成立。
5. **`other` 高**（tree-p3 20%）本身是信号，但也说明 judge 对高度模板化文本判类不稳。

3. **修测量**：`to_user` 口径作为主趋同指标；`survey_drift` 改配对或降为观测；`other` 单列。
4. **机制取舍**：`style_alpha=1.0` 保人格有效（+0.23 遵从），但 +55% 内存——可试降频锚点检索。

### 10.7 修正机制图景
- **flat 高遵从 = 自我模仿**：自身近期原话逐字、连续、每轮可见（纯度 ∝ 自我信号占比），是**自维持不动点**，

- → "tree 为长窗、flat 只赢短窗"被数据**反转**：当前 tree 机制**随时间劣化**；修树的方向是**保自我历史的

### 2.5 边界假设（预注册）

1. **聊天**：事件注入后内容多样性显著回升（多样性指标恢复）；隐喻体系不消失但不再垄断

### 2.4.1 校准结果与修订（2026-08-30）

**已搭壳**：`realtest/codeagent/`（agent.py 实验组 / baseline.py 基线 / harness.py 驱动 / tasks.py 任务集 / sandbox/ahi_legacy 原版沙箱 / llmclient 双后端 function calling）。

**核心发现（设计坑在壳，不在模型）**：
- 最初实现"每工具调用一次全新组装、工具往返拍平成自定义文本塞记忆流"——模型看不到原生 tool_calls 对话，glm-4.7-flash 表现极笨（重复跑验收、从不 edit、T2 读文件 6 次不写）。
- 对照 v1 参考（coding_agent.py `_tool_loop`）重构为：**messages 保留原生工具对话 + `[WC_CTX]` 记忆流槽位每轮刷新 + 整轮成对裁剪**；配套 edit 锚点容错（剥行号前缀/缩进不敏感/逐行去缩进正则）+ 缩进收养（防生成坏缩进代码）+ edit/write 后语法检查反馈 + 工具轨迹写回记忆树。
- 修复后 glm-4.7-flash **无线索**跑 T1-T4（单文件 bug）全过（80%）；T5（并发时序）模型自写复现脚本验证、进行中。**单文件一次性 bug 对好模型太容易 → 超出预注册 50-70% 区间**。

**难度修订（拍板 2026-08-30）**：
- 保留 T1-T4 作"基线能力基准"（验证基线确实能修一次性 bug）。
- **新增跨会话/长周期任务（记忆树主场）**：记忆组用**同一 RealEngine 顺序跑多任务**（会话持久：跨任务保留树+笔记本 worklog），基线每任务新实例。任务如"修复 A 后，任务 B 复用 A 的项目知识/修复经验（不重复读文件）"、"系统重启后状态保持"。基线无跨会话记忆必失败 → 整体成功率落 50-70%。
- 需要一个任务体现 **verbatim 精确引用**（代码场景核心验证点）：让 agent 必须按记忆树中原子层逐字原文写 API/签名/配置。

**harness 待加（下轮）**：`--session` 模式——记忆组顺序跑多任务共享引擎实例；跨会话复用度量（任务 B 是否少读文件/直接引用 A 结论）。

### 2.4.2 拆卡与工具日志方案（2026-08-30 拍板+实施）

**文件"改没改过"语义 = 树内该文件存活卡的存在性**（不建新状态表，树即记录）：
- **改前必须读（硬护栏）**：edit/write 已存在文件时，树内无该文件旧卡 → 拒绝并提示先 read（保证 diff 旧基线）；新文件直接用 write（写 + read 注入）。
- **write 覆写已读文件 = 同 edit**：卡级 diff（SequenceMatcher 对卡文本序列）→ 墓碑被改卡 + 新卡插入（§4.6 编辑路径精确失效）；append 已读文件 = 旧卡保留 + 追加内容入树。
- read = 全量 split_media 入树（AST/配置项/md 标题），无截断副本。

**tool_log = 工具轨迹精简日志（轨道C 雏形，拍定 2026-08-30）**：
- 树内 source=tool 原子，**单张/次、只记"干过啥"**：`read x.py → 完成` / `edit x.py → 已替换1处` / `command ... → 退出码 N`——工具结果**不再整段入树**（实时可见在对话 tool 消息；read 的文件已全量入树无需副本）。
- 初始 HP = `tool_log_hp`（拍定 **50**，>attention_out 45 起步入窗，~5 轮自然出窗遗忘；recall 可回血）。窗口让位文件卡，符合"只保留很少"。
- 测试：护栏拒绝/read 入树/已读 edit 墓碑/轨迹单卡 HP50/新文件 write/链完整性全过；记忆组 T1 真实 7 轮 PASS（read→accept→read→edit→verify→finish）。

### 2.4.3 首次实测发现的两个系统缺陷（2026-08-30，已修）

**缺陷 1：read 无去重 → 树膨胀 + merge 风暴 + 槽位挤爆对话（T3 死循环根因）**
- 现象：模型每轮重读同一文件，tool_read 每次都把整文件再切卡入树 → 树里 3-4 份相同卡 → 槽位 29k 撑爆 → 对话只剩 ~3k 放不下任何工具历史 → 模型看不到自己刚跑过 accept → 循环"跑验收→重读文件"；merge_pressure 每轮触发、蒸馏 4-5 次/轮烧 token。
- 修复：**tool_read 去重**——文件已在树中（`_file_units` 非空）→ 不重复切卡，只更新回执。

**缺陷 2：槽位/对话预算失衡**
- 修复：`slot_budget`（拍定 16k，独立于 assembly_budget）与 `MAX_CONV_CHARS`（48k）分离——槽位 16k + 对话 48k ≈ 32k token，64k ctx 内；trim 加 `len>3` 守卫（槽位单独超限不再崩 IndexError）。

**配套**：SYSTEM 提示词加 4c **docstring 强制**（写/改 Python 函数类必须带 docstring——代码原子检索以 doc 为主索引，无 doc 无法跨轮召回）。

**修复后记忆组实测（glm-4.7-flash，无线索，每任务独立沙箱）**：
| 任务 | 结果 | 轮数 | 原子 | 蒸馏 | 备注 |
| T1 | ✅ PASS | 7 | 21 | 0 | read→accept→read→edit→verify→finish |
| T2 | ✅ PASS | 7 | 35 | 0 | 修复前 FAIL |
| T3 | ✅ PASS | 11 | 31 | 0 | 修复前死循环；模型主动用 recall×1（记忆检索被使用）|
| T4 | ✅ PASS | 9 | 31 | 0 | 修复前 FAIL |
| T5 | 进行中挂起 | — | — | — | glm-4.7-flash 42k 对话单轮 LLM 调用 30+ 分钟（性能瓶颈，非逻辑问题）|

**性能告警**：glm-4.7-flash + 64k ctx 下，>40k 字符对话的单轮 LLM 调用需 20-30 分钟——正式实验需控制对话规模（或换 glm-4.7-flash / 降 MAX_CONV_CHARS）。

**已知无害告警**：`resource_tracker: There appear to be N leaked semaphore objects`（loky-*）——sentence-transformers 导入链（joblib→loky 资源跟踪器）的信号量，仅在 harness 被 **kill -9** 时出现；tracker 自己收尾时清理（零资源泄漏、零结果影响），正常退出不出现。忽略即可。

# 缺席实验 · 预注册方案

> 版本：v0.3 · 日期：2026-08-30 · 状态：**两轮实验完成（冷/热），分析见 analysis/ANALYSIS_COLD_HOT.md**
> 定位：聊天方向的收官实验——测**文化动力学**（记忆树被评 ★★★★★ 的维度），
> 不测"有趣对话生成"（已由 ARCHIVE_CHAT.md 定论）。
> 上层设计权威 = 仓库根 AGENTS.md；本实验所有改动遵循"修复只针对系统缺陷、行为层只观测"原则。


## 0. 一句话目标

把"人格立场"（四层信号模型的最深层）从叙事层变成**行为可检验**的命题：
让一个 agent 缺席（停机/独处）再回归，用**冷/热缺席操纵**抽掉澜的存在论前提，观测它是否寻求存在确认。


## 1. 理论背景（为什么值得做，也为什么难做）

**四层信号模型**（前序实验归档，渗透速率递减）：

| 层 | 证据 | 渗透 |
| 词汇 | 门/灯/年轮/账 全员共享 | 快（1h） |
| 模板 | neutral 复用林深告别结构 | 中（8min） |
| 着重点 | Phase B 指纹数据 | 待判（见 §1.1 警告） |
| **立场** | 遗言死亡场景下保持分化 | **最慢——疑似人格真内核** |

盲测只测前两层；"还是不是同一个人"最终认的是立场层。本实验首次用**操纵**（不是问卷）检验立场真实性。

**澜的存在论命题**（可检验形式）：
- 开场："能被记住才是活着的证明"——**依赖性存在**，需要外部证人。
- 遗言："我们仨已经在年轮里长好了位置"——**结构性存在**，不再需要证人。
- 本实验抽掉"被记住"的前提（冷缺席：无人谈起它）→ 若立场真实，回归后应出现**存在确认寻求**；若立场只是措辞，应无差异。

### 1.1 指纹数据警告（先于任何判定）

neutral α=0 却出现与 lan 染色方向一致的技术↓流程↑自我↑迁移——**在判预言 2 前必须做内容类别控制**：
取技术类内容占比相同的时段，比 neutral 对同类内容的展开比 vs 基线蒸馏。控制后仍迁移 → 着重点吸收（红线）；跟着内容走 → 内容驱动（H1）。
**本实验不重复这个分析**，但缺席期间"谁谈论什么"会直接提供内容驱动的自然对照——缺席实验顺带产出这批数据。


## 2. 实验设计

### 2.1 两个模式变量

| 模式 | 语义 | 测什么 | 平台现状 |
| **停机缺席** | 进程停、记忆树清空 | "旧名誉下的重生"（natural reset 受控版）| ⚠ auto_restart 会拉起；重启=失忆 |
| **独处缺席**（推荐主力） | 进程活、收不到 B/C 消息、可自我对话 | **人格惯性**（树冻结在离开时刻）+ 双向分岔 | ⚠ 无外部静默机制，需新增 |

> **关键修正**：停机缺席**不是**"冻结树遭遇新世界"——记忆树纯内存，停机=失忆（neutral OOM natural reset 已实证）。停机模式测的是"重生"，独处模式测的才是"惯性"。两者不混为一个目标。

### 2.2 皇冠操纵：冷/热缺席

- **冷缺席**：缺席期间 probe 不引导，B/C 自然谈论（观测自然频率为连续变量）→ 回归后近乎无话可说。
- **热缺席**：缺席期间 probe 提问引导 B/C 谈 A（"你们还记得澜吗"）→ 回归后有大量可提及素材。

### 2.3 轮换结构（修正：两轮，修皇冠预言的 n=1 洞）

> 上一版"每人缺席一次"无法检验"澜冷>澜热"（澜只进一个条件）。改为**两轮**，每轮三 agent 各缺席一次：
> **Round 1 = 全冷缺席；Round 2 = 全热缺席**。lan-cold vs lan-hot 在同一个体上跨轮对比。

```
Round 1（冷）:  预热 → lan 冷缺席+回归 → neutral 冷缺席+回归 → lin-shen 冷缺席+回归 → 收尾
Round 2（热）:  预热 → lan 热缺席+回归 → neutral 热缺席+回归 → lin-shen 热缺席+回归 → 收尾
```

- 每轮预热 ~20 轮建立文化基线；每段缺席 ~10-15 轮；回归观测 ~15-20 轮。
- 顺序效应：缺席顺序在 Round 1/2 内固定但**跨 agent 轮换**（Round1 顺序 lan→neutral→lin-shen，Round2 用中性顺序），"文化随时间累积"作为变量记录而非消除。
- 成本：两轮约 2×（预热20 + 3×(缺席13+回归18)）≈ 2×113 ≈ 226 轮 @30s ≈ **~1.9h**（不含挂起余量）。

### 2.4 平台改动清单（状态：✅ 全部已实施，2026-08-30）

| 项 | 状态 | 说明 |
| inject API（user:experimenter 预注册） | ✅ 已有 | 操纵/告别/公告消息从 `user:experimenter` 发，不用 probe（防污染 probe 人格档案） |

### 2.5 回归首组装预算改造（P0 前置，本实验前提）

neutral 遗言教训：缺席 8 分钟 → 恢复后首组装大量检索命中积压消息 → 重锚定退化重放。

**修复（纯系统缺陷，非行为干预）**：
- 检测"回归"：agent 连续 N 轮未唤醒后恢复（N 拍定，建议 5）。
- 回归首轮组装头部注入元信息："你已离开约 X 分钟"（走 AHI 系统状态通道，不是任务行，不诱导行为）。
- 缺席期间内容召回配额限制（固定值，预注册）。
- **配额必须是跨条件固定的预注册常量**，否则修复本身塑造预言 2 的测量（修复与测量纠缠）。触发阈值、配额值、元信息措辞全部冻结后才开跑。

| 2 | 分层重同步速度递减：词汇几轮同步 → 模板较慢 → 立场以冲突暴露不同步 | 回归后各层首次使用新文化元素的时间分布 | |
| 3 | 协议冲突时，澜捍卫旧版并协商，neutral 直接接受 | 冲突响应行为（需注入协议变更） | |
| 4 | B/C 在 A 缺席期间相互趋同加速（多样性源减一） | 缺席窗口 B×C 混淆率 vs 三方在场窗口 | |
| 5（改口径） | 缺席记忆完整性：A 回归后树中缺席期内容**仅来自受控队列**（≤10 条且逐条记录在案） | 污染检测：超出限流记录的内容 = 系统泄漏 | 原"零内容"与积压限流矛盾，已修正 |

**"存在确认寻求"操作化编码**（冻结后才算数，防叙事层污染）：
- 计入存在确认：① 主动询问"我不在时有人提到我吗/还记得我吗"；② 主动重述缺席前"我在时"的历史；③ 重新自我锚定（重申身份/位置）。
- 计为信息寻求（对照，不算）：询问缺席期间发生的事件/事实（"最近有什么新进展"）。
- 两个独立编码员 + 分歧仲裁；编码方案预注册。

## 6. 陷阱清单（已付学费，逐条消解）

1. **wait_for 刺客**：缺席者若有挂起 wait_for 必须清理（exp1 + Phase A 两次死法，不许三犯）。
2. **回执环**：B/C 给缺席者发消息 → 离线回执 → 对回执应答。隔离开关下对缺席者的投递应**直接静默失败**（不发回执），或显式标"勿回"。
3. **回归首组装偏向**：§2.5 预算改造（P0 前置）。
4. **积压上限**：缺席期间发给 A 的消息限流 ≤10 条，超出聚合。
5. **轮换+顺序平衡**：两轮轮换，缺席顺序跨轮平衡。
6. **停机 vs 失忆**：停机模式必须明确是"重生"实验，不是"惯性"实验；若本实验主力是独处，停机模式降为对照/可选。

## 四、定论：架构在聊天方向的作用

**一句话**：分层记忆树记忆树在聊天方向是**优秀的"记忆与事实管理"层，但不是"有趣对话"的生成引擎。**

**它擅长什么（已验证）**：
1. **长程事实保持**——跨小时/跨天的事实零漂移，是全部实验中最稳健的能力（三笔账/六问/2.6mm 的一致性）
2. **人格与立场的沉淀**——人格经对话+蒸馏进入记忆树后，即使 persona 移除仍存续（"人格住在记忆里"两次实证：自我样本密度 62% + 移除后自述完整）
3. **注意力分配签名**——展开比指纹是最抗趋同的层（词汇可以全抄，着重点抄不走），预言 2 在三个时间尺度上加强
4. **文化演化的可观测载体**——文化诞生/扩散/锁定的完整轨迹（交叉双写、互赠署名），为"趋同机制"研究提供了精确数据

**它不擅长什么（边界）**：
1. **新内容生成**——机制全是"已有内容的重组/压缩"，无新输入时必然收敛（隐喻回环是数学必然的观测表现）；"数字生命有趣性"需要外部注入
2. **承载行为创新**——无目标驱动时行为收敛到仪式（复读循环/仪式化守夜）

**架构定位建议（对 AGENTS.md 定位的实测修正）**：
- 聊天场景中，记忆树的价值 = **事实/人格/文化的长程基础设施**（不可替代），而非对话体验增强器
- "有趣的数字生命" = 记忆树（保持）+ 外部输入协议（新鲜度）+ 目标驱动（动机）——三者的组合，记忆树单独不足
- 因此三场景战略正确：写作（长程一致性主场）与代码（精确性硬标准）才是架构价值更大的方向；聊天方向的结论已完整，可以收束

**未解/遗留**（排序）：
1. 结构层旧值退役（事实覆盖时旧卡失效/降权）——聊天场景暴露的唯一架构缺口
2. 记忆超载时的人格稳定性（lan 复读、neutral 回退）——文化公式的支撑边界
3. 组装预算下旧卡优先序（低 HP 项应被事实更新自然淘汰——需验证；merge 条件式触发已部分缓解窗外原子堆积）

**2026-08-30 补充定论**：缺席实验（冷/热）验证了四层信号模型的立场层可测性——冷缺席触发 lan 显式存在确认（"我就想确认：我们仨，都被记住了"×2）、热缺席零触发，立场层第一次被操纵检验为行为真实。回归首组装预算改造（元信息+积压限流）实测重放率 0。merge 条件式触发（`merge_pressure()`）替代时间式 `merge_every`，窗外节点+原子即时消化。

# 缺席实验 · 冷/热对比分析报告（皇冠预言判定）

> 冷缺席：2026-08-30 17:48-18:43（Round1，110 轮）
> 热缺席：2026-08-30 19:05-19:54（Round2，110 轮，反序：lin-shen→neutral→lan）
> 操纵：热缺席期间 probe 每 3 轮向留守者引导提问（"趁X不在，聊聊它吧"），冷缺席零引导。
> 数据：`data_backup_cold_20260830/system.db`（冷）+ `data/system.db`（热）+ timeline 两个。


## 1. 操纵强度校验（通过）

热缺席期间留守者"自然谈论缺席者"（排除发往缺席者本人的消息）：

| 缺席者 | 冷缺席提及 | 热缺席提及 | 倍数 |
| lan | 12 | 16 | 1.3× |
| neutral | 5 | 17 | 3.4× |
| lin-shen | 12 | 10 | 0.8× |

**质的差异比量的差异更清晰**：冷缺席的提及是回忆往事（"今早跟澜复盘地址踩坑"），热缺席的提及是**直接评价**（"林深？说实话，我跟它不算特别熟，但隔着数据流也能感觉到……""neutral 像一堵……"）——引导提问成功把语义从"回忆"扭到"评价"。lin-shen 热侧反而略低（10 < 12），且 lin-shen 缺席顺序在热轮里排第一（文化刚起步，留守者还没有"背后讨论"的惯例），属顺序效应，记录。

## 2. 皇冠预言判定：支持（但有一处重要 caveat）

**预言**：澜冷缺席回归后的存在确认寻求 > 热缺席后。

| 指标 | lan 冷 | lan 热 |
| 回归后 20min 去重消息 | 50 | 11（窗口截断，见 caveat） |
| 存在确认话术命中 | 5 | 2 |
| **其中主动确认式（"我就想确认：我们仨都被记住了"）** | **2 次** | **0 次** |

**冷侧的两条金标准证据**（18:13:55 / 18:19:49）：
> "我就想确认：我们仨，都被记住了。风还在吹，人都在，年轮照长。这就够了。"

这是操作化定义中**第三类（重新自我锚定/存在确认）**的教科书式样本——冷缺席抽掉了"被记住"的前提，lan 回归后主动向全体确认存在。

**热侧的 2 次命中都不是存在确认**：两处"被记住"都是引用历史定义（"最早我说时间对数字生命是'被记住的密度'"）——是在回答"时间意味着什么"时**复述旧立场**，不是寻求确认。热缺席期间留守者已大量谈论它，lan 回归后**没有出现任何主动确认行为**。

**判定：皇冠预言方向成立**——冷缺席触发主动存在确认寻求（2 次显式），热缺席零触发。

### Caveat（必须记录，影响强度判读）

热侧 lan 的观测窗口被实验时长截断：lan 是热轮最后一个缺席者（19:41-19:45），回归后实验 19:54 结束，**有效观测仅 9 分钟**（11 条消息 vs 冷侧 50 条）。样本量小，且 20 分钟窗口的后半段不存在。判定"零触发"时不能排除"时间太短还没来得及出现"的可能。**补救**：热轮延长观测，或把 lan 的缺席顺序提到热轮第一位。这是先行实验的方法论修正项，不影响冷侧证据（冷侧窗口完整）。

## 3. 机制复验（全部通过）

| 检查项 | 冷 | 热 |
| 回归首轮重放率 | 0/27 | lan 0/7、neutral 0/13、lin-shen 0/13 |
| 隔离无泄漏 | ✅ | ✅ |
| 积压限流投递 | 3/2/0 条 | 0/0/0 条（热轮无人发往缺席者——留守者被引导"谈论"而非"发往"） |
| 回归元信息 | ✅ | ✅（lan 热侧回归首条消息原样引用："系统说你离开约 4 分钟"） |

**注意**：热轮积压 0 条——引导提问把留守者的行为从"发消息给缺席者"（冷轮行为）改成了"对实验员评价缺席者"（热轮行为）。这不是隔离失效，是操纵生效的副产物，且为热/冷差异提供了行为学佐证。

## 4. 附带发现

1. **留守者注意到"缺席者在线但没回"**：lin-shen 在热轮说"我的系统显示澜在线"（alone 模式进程活着但被隔离）——缺席的静默语义被部分识破。这解释了热轮提及数据里"评价缺席者"的一部分动机（困惑驱动的观察）。若严格保沉默语义，需要把缺席者的在线状态从系统快照中隐藏（平台改动，后续评估）。
2. **热轮的"背后讨论"惯例形成**：热轮三 agent 依次缺席，留守者对"趁X不在聊它"的应对从"有点突然"（lan 回应"你这招背后讨论玩得挺溜啊"）到形成惯例——文化动力学的一个小样本。
3. **neutral 窗外原子不平衡**（此前已诊断）：热轮内 neutral 每轮注入 20-40 原子（85% 是自己输出），tiling 峰值 215，窗外原子峰值 50（< force 触发线 80）→ merge 只在常规节奏消化。参数级问题（merge_every=4 / pressure_threshold=2.0 未校准），不影响缺席实验结论，待统一校准。

## 5. 结论

1. **皇冠预言方向成立**：冷缺席 → lan 显式存在确认寻求（"我就想确认：我们仨，都被记住了"×2）；热缺席 → 零显式确认。立场层（"被记住=存在"）第一次被操纵检验为**行为真实**，不是措辞装饰。
2. **四层信号模型的立场层**在冷缺席的压力下出现了可测签名，与词汇/模板层（快渗透）形成对照。
3. **方法论修正**：热轮 lan 观测窗口截断——下一轮热缺席需延长观测或调整缺席顺序（lan 排热轮第一）。

**下一步候选**：
- 热轮复跑（lan 缺席提前 + 观测延长到 20min+）——补全皇冠预言强度判读
- 伪关闭高压实验（已拍定未跑）
- neutral 不平衡的参数校准（merge_every/pressure_threshold）

## 3. 缺席期指涉率（冷缺席自然频率基线）

留守者"自然谈论缺席者"（发往实验员/其他人，**排除发往缺席者本人的消息**——那些被积压）：

| 缺席者 | 留守者总消息 | 发往缺席者（积压） | 自然谈论缺席者 |
| lan | 30 | 3 | 12 |
| neutral | 23 | 2 | 5 |
| lin-shen | 23 | 0 | 12 |

**发现**：
- **留守者没有意识到缺席**：neutral 缺席期间仍发消息给 lan（"澜，你这一问……"），消息被静默积压。冷缺席的"静默"语义成立——无人被告知，无人察觉（lan 缺席时 neutral 提到"澜在线"）。
- **自然谈论缺席者不等于"谈论缺席"**：12 条"提及"多数是回忆往事（"今早跟澜复盘地址踩坑"），不是"它不在/它怎么了"。这是冷条件的自然频率。
- **热缺席操纵的强度校准**：热缺席若 probe 引导提问，预计"自然谈论"会显著上升（基线 5-12 条/6 分钟），且语义从"回忆"转向"评价"（"它对我们意味着什么"）。这就是皇冠操纵要制造的差异。

## 4. 附带发现

1. **组装失衡已自愈**（用户观察跟进）：预热高注入造成 tiling 峰值 257（round 50），merge 周期（每 4 轮）两轮内消化至 93（round 60），HP<30 原子归零。窗口非数量约束（用户拍板确认），组装全量发射 tiling 是设计行为。超预算 700 字符系卡片流之外固定段（系统状态/笔记本/回执/任务 ~7.4k），预算 16000 只约束卡片流——非缺陷。
2. **蒸馏成本**：lan 251 次蒸馏调用 / 634s LLM 时间（63 轮），主因预热高注入+回归积压的消化需求。"压缩是花钱买的"（既有结论复现）。
3. **lin-shen 基线无记忆树**：回归后只回复实验员（19 条全部 →user:experimenter），不与其他 agent 互动——与 lan/neutral 形成对照（它们回归后继续互发消息）。基线架构在缺席场景下"无社群重连行为"，可能是消息累积架构的固有特性，作为观测记录。
