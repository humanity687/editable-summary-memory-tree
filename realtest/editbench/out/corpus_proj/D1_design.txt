## 0. 设计哲学（2026-08-29 定）

> **通过简洁精妙的架构，涌现出我希望的特性。**

- **简洁**：机制数量少、语义单一。一个机制尽量服务多类对象（如注意力窗口同时服务原子与节点），而不是为每类对象各写一套特判。
- **涌现**：目标特性不是用显式规则写死，而是从机制交互中自然出现（层级沉淀、热区消退、优先级分化）。写死一条特判规则（封顶/冷却期/白名单）之前，先问：能否由既有简洁机制的参数化表达？
- **判据**：硬规则是最后手段。机制行为不符合期望时，优先调整参数或推广既有机制，其次才引入新机制，最后才写死特判。
- 反面教材（2026-08-29 一天实验）：节点不受注意力保护 → 统一快衰减 → 9 轮归零 → 无限上并 → 99% 历史压进 1-5 个大节点（组装退化成"两段式"）。教训：对象类别之间的衰减待遇不对称，会杀死层级涌现。
- **经验定律「策展定律」（2026-10-04，M-PR 三次重复）**：`pr2` recency-6 锚点（蒸馏侧，败）→ `pr5` 检索化锚点
  （蒸馏侧，胜 +0.23）→ `pr6_sq` recency-first 自我地板（组装侧，败于 p1）→ 分层 SQ v2（组装侧，待跑）。规律：
  **近期 self 是被污染的 self；干净 self 必须主动检索回历史去取。"喂哪个自己"是策展问题——策展是记忆组织的职责，
  不是窗口的**（§4.4 人格锚点检索 / §4.5.10 分层 SQ）。推论：自我模仿是**内容无关的稳定器**（保存的是被喂回去的
  那个自己，不是人格）；记忆架构效应被**人格-语域兼容性**调节（故实验必须按人格分报，见 `PERSONA_RETENTION.md §10.3.1`）。


## 0b. 铁律（违反即事故）

1. **偏离设计必须先行确认**：因实测问题需要对本文档任何设计决策做修改时，必须先向用户完整说明"改什么、为什么、影响什么"，获明确同意后才可改动本文档并同步代码。禁止擅自修改设计、禁止擅自绕过设计写临时方案。
2. 写任何代码前，必须能完整复述本设计（§1~§10）。不确定时先读本文件，不要猜。
3. **组装 = 纯计算（零 LLM）**。LLM 只允许出现在明确标注的位置：merge 蒸馏、脏节点重建、章末事实校验、初始化对话、检索摘要生成（如启用）。
4. 所有参数都是"先拍后调"：先用 §11 的默认值实现，再用 §8 的基准校准；校准结果写回 §11 参数台账，并在日志中可观测。
5. 正确性依赖的边界条件（标记完备性、铺陈不变量、区间覆盖）必须有属性测试（§8.1），不允许只有 happy path。
6. 本项目是**通用"参考资料"上下文管理机制**，长篇小说写作是第一个应用实例。实现时所有"章/beat/伏笔"字样都可替换为通用词（结构单元/内容块/跨区引用），但本文件以小说为具体语境书写。


## 1. 定位与解决的问题

### 1.1 问题
一份长参考资料（如一本书的全文、一份大型文档集）无法整体塞进有限上下文窗口。现有做法（全量发送 / 静态摘要拼接 / 关键词检索）各自失效：全量爆炸、摘要丢细节、检索无状态演化。

### 1.2 核心思想（四条）
1. **位置有序的记忆树**：参考资料切成原子卡（句），稳定 ID + 顺序链表维护顺序；摘要卡按连续区间自底向上合并成树。树的任何节点 = 某连续区间的概括。
2. **分辨率随热度变化**：近处（当前工作区）全分辨率原文，远处自动降为各级摘要，摘要只保留专有名词、因果链、关键原句。越老的记忆越粗、但越稳定。
3. **区间失效 + 懒重建**：编辑通过覆盖区间精确失效旧内容；脏卡立即排除出一切查询，重建全部推迟到蒸馏时机（零 LLM 的即时编辑路径）。
4. **不可遗忘的事实层**：与正文流分离的"笔记本"，无衰减、全量存储、按需注入；负责跨区引用（伏笔）与硬约束，不做概率性召回。

### 1.3 通用化映射（实现抽象层时参照）
| 小说语境 | 通用语境 |
| 一句话概述 | 全局摘要 |
| 卷/章 | 结构单元 |
| beat（叙事节拍） | 内容块 |
| 伏笔（调度条目） | 跨区引用账本 |
| 角色状态（状态条目） | 事实条目 |
| 章节目标（扰动源） | 当前任务目标 |


## 2. 架构总览

```
┌─ 三轨记忆（当前=进程内 + gzip/JSONL 快照；SQLite 为规划目标）
│ 轨道A 小说内容（参考流）：记忆树 + 原子层 + 归档（版本谱系） │
│ 轨道B 笔记本（事实层）：常驻约束 / 状态条目 / 调度条目     │
│ 轨道C 讨论内容（工作记录）：工具组压缩卡，自然遗忘         │
├─ 调度原则───────────────────────────────────────────────┤
│ 组装（拼上下文）：每个工具调用一次，纯计算                │
│ 蒸馏（merge pass / 脏重建）：仅章边界 / 预算超标触发，     │
│   LLM 密集，可后台异步（单任务锁）                        │
└──────────────────────────────────────────────────────────┘
```

> 2026-09-25：**"组装 per 工具调用"已在 ahi 壳落地**——动作循环内每次工具调用后重新组装（纯计算，
> 模型立即看到自己刚发的消息与工具产出）、**连续唤醒**（loop 每次工具调用前重排 pending）、
> **mid-loop 不 merge**。详见 §4.5.7/§4.5.8。

组装输出顺序（默认，需实测微调，见 §10）：

```
[系统/角色指令]
→ 轨道B 注入（常驻约束 → 按实体选取的状态条目 → 调度条目）
→ 轨道A 小说内容流（铺陈 + 召回路径 + 热区原子，按位置序）
→ 轨道C 讨论内容（最近优先，protected 卡保持）
→ 当前目标 / 用户输入（扰动源）
```


## 3. 数据模型（当前实现 = 内存 + gzip/JSONL 快照；字段名为逻辑模型）

### 3.1 原子卡 `atoms`（句粒度）
| 字段 | 说明 |
| id | 自增，创建时分配，**永不复用** |
| text | 原文 |
| alive | 1 存活 / 0 墓碑（删除后保留行） |
| created_round | 创建轮次 |
| hp | 生命值 |
| version | 内容版本（每次内容变更 +1） |

### 3.2 顺序链表 `order_list`
- `atoms.prev_id / next_id`（双向），piece-table 模式：编辑只做局部指针修改 + 墓碑，**不做任何全局坐标平移**。
- 区间概念 = 顺序位置区间；原子 ID 不携带顺序信息（中插会使新 ID 大于区间末 ID，**禁止用 ID 大小做区间判断**）。

### 3.3 摘要卡 `nodes`
| 字段 | 说明 |
| id | 自增 |
| parent_id | 父节点（树内节点） |
| span_first_atom / span_last_atom | 位置区间（引用存活原子的 ID） |
| content | 摘要文本 |
| hp | 生命值 |
| dirty | 0/1 脏标记 |
| placeholder | 0/1 占位卡（含热原子区间的重建结果） |
| version | 重建版本号 |
| activation_count | 召回命中计数（达 promote_threshold 触发提升，见 §4.7） |
| created_round | 创建轮次 |

### 3.4 归档 `archive`
- 节点被重建/丢弃/提升时压入的旧版本快照（`node_id, version, value, first, last` 的追加列表）。
- **当前用途 = 版本谱系/可观测性**；回滚实际依赖 `ledger`（§3.7）。**当前无"云库召回"路径**，
  故不存在"stale 快照排除出召回"的读路径（§4.6.5 已据此修订）。

### 3.5 笔记本 `notebook`
| 字段 | 说明 |
| kind | `constraint`（常驻约束）/ `state`（状态条目）/ `schedule`（调度条目） |
| key | 实体/主题 |
| content | 条目内容 |
| status | 对状态条目：current / superseded（含变更轨迹）；对调度条目：planted / advancing / payback / closed |
| window | 调度条目专用：planted 章号、推进窗口、payback 章号 |
| updated_at | 最后修改 |

### 3.6 工作记录 `worklog`
- 工具组压缩卡：`content, hp, protected(0/1), created_round`。

### 3.7 版本账本 `ledger`
- 每次编辑的增量（`core.Engine.ledger`）：插入记 `{"type":"insert","atoms":[...]}`；
  删除记 `{"type":"delete","atoms":[(id, prev, next), ...]}`（记录原邻居锚点）。
- 回滚 = 逆向应用增量（**回滚就是一次编辑**，走 §4.6 同一条路径）。

### 3.8 核心不变量（任何代码不得违反）
1. 干净节点 ⇒ 其区间内原子全部存活且内容未变（区间有效）。
2. 脏节点 ⇒ 不参与任何读操作（组装/检索/merge），重建前其 span 无意义。
3. 原子卡**永不为脏**。
4. 铺陈（clean tiling，§4.5）在任一时刻无重叠、无缝隙地铺满当前全文。
5. 任一节点的子节点区间并集 ⊆ 其自身区间；merge 产生的父节点子区间**恰好拼满**父区间。


## 4. 轨道A：小说内容（参考流）机制

### 4.1 原子层与顺序
- 原子卡 = 句粒度。写新内容时按句切分创建（`write_stage` 工具）。
- 顺序由链表维护；区间一律用"位置序"判断，不用 ID 大小。

### 4.2 记忆树（区间覆盖树）
- 结构：父节点 = 其子节点区间的概括；**由 merge 自底向上合并生成**（并查集式），不是固定层级、不是自上而下二分。
- 深度 = 合并历史轮数；**无编辑时上界 log2(叶子数)**；编辑/重建会破坏平衡（重建可产生单活子节点链，见 §4.6），实测深度可达 O(sqrt(叶子数)) 量级——**不承诺严格上界**，实现必须用迭代遍历而非递归（防爆栈），检索/组装按预算封顶。顺序追加场景由 §4.4 的按秩合并（`merge_depth_diff`）压为亚线性（实测 64 批追加 → 树高 9）。
- **无预设根**：全书合并链的终点（最后一张卡）即根。检索不需要根路由（见 §4.7 全树打分）。

### 4.3 HP 与衰减
- 每轮（每次组装）所有存活项 HP 减 `decay`。
- 合并阈值 `hp_merge_threshold`：HP 低于此值 = "低"。
- 父卡创建时 HP = `parent_init_hp`（**必须 > 合并阈值**，否则树长不起来）。
- 召回命中项 HP 提升 `recall_boost`（回流后在流中多待一会）。
- HP 语义：仅驱动"何时合并"的优先级压缩，**不参与事实层**（轨道B 无 HP）。

### 4.3b 注意力窗口（已实现 2026-08-12；2026-08-29 节点入窗拍定）

> 动机：编辑风暴中大量新原子卡涌进上下文，组装预算（字符）被原子卡吃满。注意力窗口 = **卡数量预算**（"我最多同时看多少张卡"），是字符预算之上的一层上游约束。编辑风暴复述崩溃（1.5%）暴露的就是这类问题；冷却窗口（bench 修复）缓解了症状，注意力窗口是机制化方案。
>
> **2026-08-29 定（层级涌现修复）**：树的层级结构是**提取历史的沉积岩**——每一层的厚度记录着一个话题被爱过的频率。注意力窗口从原子专属推广到**铺陈全部卡（原子段 + 节点段）**：提取驱动巩固（retrieval-based consolidation）——被 recall 提取的卡趋于巩固（回血+慢衰减），不被提取的自然语义化、压缩。层级不是设计出来的，是提取历史长出来的；树的形状 = 使用史的化石。

实现（core.py `tick()`，纯计算零 LLM）：
- **只改变 HP 演化速率，不触碰任何顺序/组合逻辑**：铺陈、merge 分组、组装输出仍按位置序；HP 排名仅用于内部判定窗口内外，绝不作为组合顺序键。
- **持续不对称衰减（已拍定，非事件触发）**：每 tick 对存活卡按 HP 降序排名，名额内且 `HP ≥ attention_out` = 窗口内（慢衰减 × `attention_in_decay`），其余 = 窗口外。零状态、无事件时序、自动闭环。
- **名额拆分（2026-08-29 拍定；2026-08-30 节点段成员修订）**：注意力窗口拆**原子段 `attention_atom_cap`=40 + 节点段 `attention_node_cap`=20**（各自独立按 HP 排名，互不挤占——两类对象起点接近，混排会互相淹没）。原子段成员 = 全部存活原子；**节点段成员 = 全部存活节点**（2026-08-30 拍：树内节点与铺陈节点平等参与——被召回的树内节点/影子也可入窗受保护，提取驱动巩固对节点与原子对称生效）。
- **节点出窗不继承原子悬崖（2026-08-29 拍定）**：原子出窗快衰减 ×`attention_out_decay`（热/冷悬崖：原子要么热、要么该转化形态）；**节点是已沉淀形态，出窗衰减 = `decay`**（不乘 out 倍率）——中间层有平缓生存梯度，不是"保护圈内/圈外 2 轮死"。
- 回血内外一致：`recall_boost` 对称生效，出窗卡回血到 `HP ≥ attention_out` 自动回窗。
- 合并缓冲不变：窗口外 ≠ 立即合并——merge 仍要求"位置连续 + 成员 ≥2 + 低 HP"组条件。

**数学事实（2026-08-29 钉死）**：只要"衰减必至 + 合并不可逆"同时成立，树的单调压平是**数学必然**（与参数无关——B1/B2 只改变速率曲线不改变方向）。唯一稳态通道 = `recall_boost` 对衰减的注入平衡：一次命中续命 N 轮，命中频率高于 1/N 的卡净存活，低于的压缩。**中间层是生死循环的种群，不是过客**——复验标准不是"层级不再压平"，而是"中间层节点数稳定在非零水位、寿命分布呈梯度"。

**三层结构分工（2026-08-29 明写，与人类记忆系统同构）**：
- **热区（裸原子）= 工作记忆**：当前活动内容，全分辨率，快速进出；
- **记忆树 = 情景记忆**：提取驱动、动态压缩，观察期锚定在创建时刻（B2 的沉淀决策在合并瞬间做出；内容相关性时刻是任意的——第 21 轮才变热的话题，节点可能已被吸收）；
- **笔记本（轨道B）= 语义记忆**：稳定、承诺驱动、时间无关（伏笔调度是第二通道，重要性承诺不走热度）。

**HP 双语义（2026-08-29 写明）**：HP 同时承载两种语义——初始继承（B2 信用，父 HP = 保底 + 组内成员加权均 HP）+ recall 注入（收入）。HP 130 的节点可能是"新鲜"也可能是"热门"，分析时不可单读 HP 值下结论。

实现要点补充：
- **不要求连续**：注意力是预算概念（数量上限），与"热区"（位置连续、最近写入）语义分离；编辑中插原子位置任意，强制连续会制造人工边界。merge 按位置序分组，与注意力独立，互不干扰。
- **weight（大卡虚拟计数，2026-09-27 入册）**：文本超过 `ATOM_WEIGHT_CHAR`(1000) 的原子 `weight=2`，
  同时计入原子段名额（`used += weight`）与衰减倍率（`rate *= weight`）；节点 weight 恒为 1。
  这是聊天适配引入的补充语义（原设计为纯卡数量），在此显式声明。
- **排序键**：按 HP 降序（与 recall_boost / hot_threshold / merge 阈值统一）；实现未做时间序 tie-break（同 HP 次序不定）。
- 与组装预算（`assembly_budget` 字符）的关系：注意力是上游数量约束，组装仍是下游字符硬约束；注意力内原子若仍超字符预算，按 §4.5 现有逻辑处理（新原子保护一轮，旧原子低 HP 优先裁，仍超才硬截断记日志）。

参数（2026-08-29 拍定值，未校准，见 §11）：`attention_atom_cap`=40 / `attention_node_cap`=20 / `attention_out` / `attention_in_decay` / `attention_out_decay`（节点出窗 = `decay`）。

### 4.4 merge pass（蒸馏，LLM 密集）
触发：章边界 / 组装预算超标（`assembly_budget` 字符预算）/ **条件式触发（2026-08-30 拍定；2026-09-27 收口为单一入口 `merge_signal()`）**：
`force`（铺陈窗外原子数 > `attention_atom_cap × pressure_threshold`(2.0) → `merge_pass(force_out=True)`，纯原子段急
合并）> `regular`（窗外节点数 + 窗外原子数（weight 计）> `merge_pressure_threshold`(20) → 常规 `merge_pass()`）> `None`。
替代时间式 `merge_every`；驱动侧对 force 可加冷却（`force_cooldown_rounds`）。

规则：
1. 在**当前铺陈**（§4.5 的 clean tiling，含脏节点外的全部项）上按位置序扫描。
2. 找连续"低 HP"的最大组（组内每项 HP < `hp_merge_threshold`），成员 ≥ 2。
3. **按秩合并（防梳子退化）**：组内成员**子树高度差 ≤ `merge_depth_diff`**（高度 = 该节点到其子树叶子的最大深度，原子 = 0）。深度差超限的低 HP 项不得并入本组——浅层内容先自行成团（如"深节点 + 新原子"分离，原子先合并成浅节点），深节点只与深度相近的节点合并。这是并查集"按秩合并"思想：顺序追加场景下树高从 O(章数) 降为亚线性（实测 64 批追加 → 树高 9）。
4. 组内分批受**双上限**约束：子树原子数上限 `merge_cap_atoms`(500) 与单父子卡数上限 `merge_fanout_cap`(12)（防扇出爆炸）。**禁止单成员块**：任一父节点创建时子节点数 ≥ 2（单子节点 = 无意义间接层，会形成链式退化、深度失控）；上限与"禁单成员"冲突时以 **≥2 为硬约束**（余数并入相邻批，允许轻微超上限）。
5. 整组合并成一个新父节点：span = 组内各项 span 并集；子节点 = 组成员（深度不限，**跨深度允许**——铺陈项按构造互斥无隙，无重叠风险）；content = LLM 从子节点内容生成（子是摘要则重合并，子是原子则此刻概括）；**HP = `parent_init_hp` + `parent_hp_group_factor`(1.0)×组内成员加权均 HP，封顶 `max_hp`（2026-08-29 拍定）**——保底 70 = 老内容压缩通道；组均 HP 高（新鲜内容合并）→ 父 HP 高 → 沉淀更久 → **中间层涌现**。**使用度沿树上继承**：被 recall 激活的高 HP 节点参与合并时，组均 HP 高 → 上层节点继承使用度——"常谈话题的层级保持更高分辨率"是涌现性质（进属性测试断言）。**（2026-10-01 拍定：`initial_hp` 100→70，组均继承机制保留——继承后节点 HP（70+组均 ≈ 80–95）一般情况下高于原子初始 HP，即"沉淀比刚写的更稳"的层级涌现数值保障；同时占位期（HP≥hot_threshold 的冷却时间）从 ~10 tick 缩到 ~2.5 tick。）**
6. 成员退役：从铺陈消失，留在树内作子节点（仍可被下钻/检索命中）。
7. 每轮 pass 扫一遍；预算仍超标则再扫（新父卡高 HP 不会被立刻再并，天然收敛）。

**force_out 模式（窗外压力急合并）**：阈值改为 `attention_out`，**只合并纯原子段**（节点作为段边界不参与）——原子=无意义个体需尽快成组压缩；节点=概括卡代表一段上下文，只走常规低 HP 合并（自然老化后折叠，树由此长高）。两者都保持位置连续分组（父区间 = 子区间并集）。

**蒸馏源渲染（2026-10-03 收口）**：蒸馏器与主模型都看**干净渲染**——原子层按（来源）分段（`▸〔来源〕` + 原文），**不逐句内联〔来源〕标签**；来源归属由程序维护（`_node_sources` → 卡片头 `〔源:X〕`）。蒸馏 prompt **不含**"来源标注规则/时序分流规则"，只留中立概括说明（不要求模型加标签、也不禁止）。旧版"逐句〔来源〕前缀 + 摘要保留归属"与"HP<阈值标〔早期〕引导时序分流"（2026-08-30 / 2026-09-25）已废：merge 只挑低 HP 项成组 → 送蒸馏的原子几乎必然"早期"（实测 97% 节点带〔早期〕），信号恒真无效。
- **〔早期〕新语义（2026-10-03 拍定）**：判据改为**与失效参照集匹配**——待蒸馏内容与「墓碑原子（`alive=0`）+ 脏节点旧文本」的 bigram Jaccard ≥ `early_match_threshold`(先拍 0.5) → 段头标〔早期〕（= 可能无效/历史态，如编辑后残留的旧值回潮）。**只作用于蒸馏输入渲染；置脏机制（编辑失效路径）不变**。
- **【注】传递（option 2，2026-10-03 先跑 smoke）**：节点摘要进上层蒸馏时携带【事实】+【注】（此前只取【事实】段）——让风格/着重点向上传递；检索打分与主模型渲染仍只用【事实】。
- **差集索引行删除（2026-10-03）**：`〔另有N条未展开〕`（`_uncovered_count`）是机制脚手架，不再生成/渲染。

**人格锚点自蒸馏（2026-10-02 拍定；2026-10-03 改检索化）**：动机 = PR 人格保持实验里 tree 用**中性蒸馏器**（`style_alpha=0`）把人格的"风格载体"第一步就蒸掉了，导致淡出后趋同（共享仪式语，实测 `灯亮着` tree 1054 / flat 56）。修法 = 蒸馏时注入 **agent 自产的人格锚点**，让人格影响**表述方式/展开重心**、不影响事件：
- **锚点来源（硬约束：全部自产，禁用初始 persona_block）**——① 稳定自述锚点 = agent 定期（`snapshot_every_rounds`）自生成的**自由文本**风格快照（**用检索到的自身样本重生成**，旧快照作弱参考、有长度上限，**不再字段级累加**）；② 内容相关锚点 = 从**自身材料**（`source=="ai"` 原话原子 + 摘要节点**整卡**含【注】）中按与**当前待蒸馏内容**的语义/词面混合检索挑 top-k（`realengine.retrieve_style_samples`；节点命中可选 `expand_self_atoms` 附其区间内自身原话）。锚点 = agent 的过去输出/记忆，与 flat 臂"逐字保留自身历史"是同类证据；注入初始 persona 等于撤销 fade 处理，**禁止**。（旧版为"最近 6 句 + 8 字段快照"，因 recency 池被共享仪式语污染、快照单调累积而废弃；基线见 git `74a1236`。）
- **【注】不渲染（2026-10-03 拍定）**：独立生成【注】并保留在卡片 `value`（供锚点检索/上层蒸馏/分析），但组装渲染只呈现【事实】——避免"出戏"；同时【事实】的表述重心与少量措辞仍可随锚点变化。
- **prompt 规则（`SUMMARIZE_FACT_STYLED`）**：允许按锚点调整措辞/展开顺序/重心（先展开在意的、折叠其余）；**禁止新增或改变事件、数字、专名**——"只影响怎么说，不影响说什么"；【注】保持可选。
- **门控与护栏**：`style_alpha`（0/0.5/1）+ `snapshot_every_rounds`（0=关）；沿用 `_fact_check`/`_first_person_check`/`_group_parts`。`retrieve_style_samples` 排除"当前正在蒸馏区间"（`children`）防自引用。
- **实现**：`realengine._summarize` 把当前内容与 children 传给 `style_provider(content, children)`（兼容 1/0 参旧式 provider）；`lan/neutral._style_guide(content, children)` 组锚点 + 累积查询缓冲；`_refresh_snapshot` 自由文本重生成。零 LLM 检索。`retrieve_style_samples`/`expand_self_atoms` 返回文本经 `anchor_clean` 剥掉〔来源/早期/索引〕脚手架标注。
- **纵向对比**：`pr`（中性 tree）`pr2`（recency-6 版）数据保留；检索化版换命名空间重跑对比。

### 4.5 组装（每个工具调用，纯计算）
1. 读铺陈：从顶层走——节点干净 → 收；节点脏 → 不收，递归其子（干净的子收、脏的继续递归）；原子卡 → 永远收。
2. 铺陈按位置序拼接（这自然给出"近热远粗"：当前章原子在末端，紧邻当前目标）。
3. **注入召回影子（§4.7）**：召回结果中不在基础层的节点（脏/占位/已发射的跳过）作为"影子卡"按**位置槽**注入——影子的位置槽 = 覆盖它的发射项之后（沿 owner 链下钻发射结构，O(深度)，**无需全局位置图**）；多个影子按祖先在前排序；影子也占组装预算（命中已 boost HP → 自然被预算保护）。
4. **从属标注（硬要求，仅卡片层）**：摘要卡必须让 AI 无歧义识别层级——每项带**深度缩进 + ⊂父卡标注**（脏展开的子卡、影子都标），影子另标"召回影子"。禁止出现"父摘要后紧跟其子摘要"却不标注的形态（AI 会把 `N1.son` 误读成并列的 `N2`）。
5. 预算裁剪（2026-09-27 拍定）：超预算时① 先裁低 HP 项（影子与普通摘要同池）→ ② 仍超则裁**旧原子**
   （低 HP 优先；**本轮新建原子至少活一轮**——热区语义由"新近性"保证，而非"卡种类永不裁"）→
   ③ 仍超，**仅当溢出超过 `budget*(1+hard_trim_slack)`（默认 10%）才硬截断**（头保留尾砍，轻微超预算
   容忍——不为削几个字符砍尾部热区），记日志（`trim_atoms` / `hard_trim` 事件）。裁剪只作用于组装输出
   （视野），不动树状态：被裁旧原子仍存活、可被检索/合并。
6. **渲染分层（2026-09-25 拍定）**：给 LLM 看的文本 = **对话（原子层）+ 记忆卡（卡片层）**。原子层 = 干净对话——连续同（来源,轮次）折叠为一段，段首只标〔来源〕（来源展示映射为**名字**，如 `▸〔林深〕`，见 §11 `source_labels`），无 `#id`/`·原文`/状态标签（机制地址收回程序层；模型读到的应该是一份对话，不是数据结构转储；〔待失效〕等裁决相关标注保留）。卡片层保留第 4 条从属标注。bench/chatbench 的引用协议依赖 `#id` → 渲染保留 indexed 模式开关（`render_clean`）。
7. **组装 per 工具调用（§2 对齐，2026-09-25 落地）**：动作循环内**每次工具调用后重新组装**（纯计算）——动作已写回树（自己消息/工具结果），模型立即看到自己刚说过什么、工具产出了什么（树演化连续不切段）。**mid-loop 组装不触发 merge**（超预算只 trim；merge 留轮末条件触发，防蒸馏风暴）。成本实测：组装纯计算 ~1ms/次（非瓶颈）；成本 = loop 调用次数 × 每次调用输入体量（行动派 agent 每轮 17-21 次迭代时单轮 90-130s，候选旋钮 = loop 组装独立预算，未启用）。
8. **连续唤醒（2026-09-25 拍定）**：不 @exit = 连续在线——loop **每次工具调用前重排 pending**，轮内新到消息立即进树/进清单/进检索，不等待下一次调度唤醒。调度间隔只在空闲时起作用。**（2026-10-03 flat 臂对齐）**：`_drain_sharded` 按 `max_pending_per_loop` 分片（余量回队首）、`_pending_brief` 本轮待回复清单（剔已回复）、`_task_line` 指向清单、每工具调用重建完整上下文、私密消息兜底回最近用户——两臂消息管理机制一致（详见 `HANDOFF.md §14`）。
9. **平台中立（2026-09-25 拍定）**：运行时注入的待回复清单与任务行必须是**事实陈述**——清单只列"谁发了什么"（已回复信道剔除），任务行只陈述"本轮有无待回复"。禁止正性行动邀请（如"可继续未完成事项"）——它与"看到自己发过、无回合状态"叠加是重复发送的自然吸引子（实测 41 对重复：29 同轮双发 + 8 跨轮重发）。未完成事项应经检索随扰动源自然浮现，不靠空轮指令；行为约束一律只写在协议文本。
10. **self_quota（2026-10-04，默认关的实验操控）**：组装层"自我可见性地板"——保证 `source=="ai"` 原话（不含 persona/tool/他人）占组装预算 ≥ `self_quota_ratio`（cap `self_quota_max`）。trim 后补足，位置序注入（kind=`self_quota`，复用 core `_shadow_slot`；渲染成正常自身发言段 `▸〔名字〕`，非"召回"标注）；超预算按挤占序腾位（检索影子/expand 低 HP → 远端低 HP 节点 → 非自我旧原子；**自身原话与本轮新原子受保护**）。候选 recency-first。只动视野、纯计算、零 LLM、不写树；`ratio=0` 零行为干预但仍记录 `metrics.self_ratio`。**定位 = 实验旋钮**（测"自我模仿→人格保持"因果），非 tree 修复；协议/判据见 `ahi-bench/PERSONA_RETENTION.md §10.3`。**`metrics.self_ratio` 按段聚合**（连续同来源+轮次自身卡算一段，`_self_rendered_chars`，`∈[0,1]`；2026-10-04 修"逐条渲染重复计段头致占比 >1"的 bug）。**pr6_sq 结果**：H-SQ1/3/4 达标、**H
-SQ2（止跌）未达标**（遵从 .857→.739→.600；p1 漂进"账/约定"共享仪式语 = 回声风险实体化）——自我可见性=必要不充分（详见 §10.3.1）。

### 4.6 编辑与失效（核心机制，正确性全部押在标记算法上）
编辑入口（AI 工具 `edit/rewrite` 与用户 UI **同一路径**）：

1. **确定性句级 diff**（LCS/Myers，不用 LLM）算出变更区间：旧区间、新文本。
2. 墓碑化被覆盖的旧原子（alive=0，行保留，从顺序链表摘除）；新文本按句创建新原子，插入顺序链表对应位置。
3. **收养（插入内容的归属，禁止省略）**：新原子插入后，取插入位置**两侧边界原子的 owner 链交集（最深公共祖先 LCA）**作为新原子的父节点：
   - 缝隙在节点内部 → 收养进最深包含该缝隙的节点（作子卡，按位置序插缝，owner = 父）；
   - 缝隙在节点边界/节点之间/书首尾 → 无 LCA → **不收养**，新原子成为铺陈项（热区语义：追加新章不会污染旧章节节点）。
   - 收养是"新插入的卡有链可爬"的前提，也是编辑区在基础层可见（脏节点递归展示子卡）的前提。
4. **标记置脏（唯一算法，禁止替代实现）**：
   - **删除**：对每张被墓碑的旧卡**从它向上爬链到根**，沿途所有摘要节点置脏；
   - **插入**：对收养链（LCA 及其祖先）爬链置脏；无收养则不标记（无摘要被影响）；
   - **禁止**对插入位置两侧边界原子各自全链爬（会产生过度标记：相邻未受影响节点被误置脏）。
   - 完备性引理：任何节点区间与编辑区相交 ⟺ 它至少含一张受影响原子 ⟺ 爬链必经过它。**全程不做任何 ID 包含测试**（中插会破坏 ID 区间，见 §3.2 禁令）。
5. **归档仅作版本谱系**：重建/提升时把旧版本压入 `archive`（§3.4），供可观测性；**当前无云库召回读路径**，
   故不需要（也未实现）"stale 快照排除出召回"的标记。回滚由 `ledger` 承担。
6. 记录增量到 `ledger`（回滚账本）。
7. 编辑完成后该区域原子均为新卡（满 HP = `initial_hp` 70）→ 自然"热"，短期不会参与合并——刚编辑的内容保持全分辨率可见，无需额外机制。

**重建（懒，LLM，merge pass 时机）**：
- 脏节点重建 = 从**当前存活子卡**重新派生（自底向上：先子后父，重建后**父卡置脏**，级联至根收敛）：
  - 死子（全部原子已墓碑）丢弃；
  - 子卡含热原子（HP ≥ `hot_threshold`）→ 摘要排除热内容，生成占位文本（如"【第X章：近期修改，概要暂缺】"），节点 `placeholder=1`，**占位期间其摘要不参与上层摘要**（父卡跳过占位子卡）；
  - **占位解除**：节点全部存活子卡 HP < `hot_threshold`（冷却 = 不再被反复编辑）→ 重建 → 占位替换为真实内容（节点内原子不会自行合并成节点——merge 只在顶层铺陈上跑——所以解除条件必须是"冷却"而非"原子合并"）。
- 重建后节点置干净（dirty=0），旧版本压入 archive。
- 占位卡**不参与语义检索打分池**（防污染）。
- **占位卡透明（2026-10-02 拍定，`placeholder_transparent` 默认 on）**：占位卡只是"摘要暂缺的空气"，
  不应污染视野、也不应占用机制资源。开启时：
  - **渲染**：`_emit_item` 遇占位卡（`placeholder=1` **或** `value is None`）视同脏节点**递归展开其子卡**，
    不再发射"【…概要暂缺】"文本——既消除污染，又让被编辑内容以全分辨率自然露出；铺陈无缝隙不变量仍成立
    （不能简单"不渲染"，否则出现空洞）。判据含 `value is None` 是因为存在"未生成摘要的干净节点"
    （实测 ahi warm 树的 `N4225` 即此类，也会渲染成占位文本）。
  - **机制跳过**：节点注意力窗口排名、`merge_pressure` 节点计数、`_find_merge_runs` 分组、
    召回路径 boost 与输出、`_inject_shadows`、`_shadow_slot` 一律跳过占位卡（不 boost/不占名额/不合并/不注入）。
  - `placeholder_transparent=false` 恢复旧行为（发射占位文本、占位参与各机制），供 A/B 对照。

**编辑效果（涌现，无需显式 split 操作）**：
- 编辑区域从树中"剥离"：其祖先节点（脏）不进基础层，基础层递归展示干净子树与原子——即"【树1】【新句1..n】【树2】"的形态。结构随编辑自动变为细粒度，衰减后自动重新融合（自我修复）。

### 4.7 检索（recall）
- **全树打分**：对全部存活摘要节点做相似度打分（跳过脏卡与占位卡）。无需指定深度——深度随遗忘历史变化，打分自然选中最精确覆盖层。
- **混合检索三通道（词面检索 vs 摘要改写的错配修正）**：
  1. **摘要·向量**：本地 embedding（如 bge-small-zh）编码摘要卡（创建/重建时按 version 缓存）；解决"语义近邻但无词面重叠"；
  2. **摘要·关键词**：bigram 重叠率；解决"摘要恰好含查询字面词"（专名/数字）；
  3. **原子·关键词粗筛 + 向量精排**：原子双字窗口粗筛（交集 ≥1）→ 对粗筛候选（上限 `atom_rerank_cap`）编码向量精排——解决"细节只存在于原子层"（缺陷B）；**原子文本不可变 → 原子向量缓存永久有效**，无需失效。
  - 融合 = 加权和（`w_vec_node`/`w_bm_node`/`w_bm_atom`，先拍后调）。向量模型缺失时自动退化为关键词单通道（诚实降级）。
  - **批量编码（2026-10-03 内存修复）**：候选原子/节点向量在**一次** `enc.encode(list)` 内批量编码（`EMBED_BATCH=32`），禁止逐条 `enc.encode`——逐条在 MPS 上堆积幽灵内存（实测同批 316 条：逐条 +460MB vs 批量 +69MB），是 pr3 agent 触及 2GB 看门狗重启的根因。**并**在每次批量编码后调 `_empty_mps_cache()`（`torch.mps.empty_cache()`；CPU/无 torch no-op）释放分配器缓存的空闲块（唯一泄漏源；tree ~75MB/min 单调上涨）——清缓存后单 agent 峰值约减半（40 轮 ~1GB），**但未根治**（仍缓涨；`realengine` + flat 批量编码两处对称）。
- **贪心选择 + 路径去重**：按分数取最高节点 → 其到根的整条路径加入结果并从候选池移除（祖先已被路径覆盖，不再单独占名额）→ 重复直到预算（`retrieval_budget`）用尽。**路径遇脏即停**：候选节点必干净，但其祖先链上可能出现脏节点（脏父 + 干净兄弟子树），路径注入到第一个脏节点为止（脏节点的祖先同样脏，无需继续）。**原子命中不走路径**：其覆盖摘要已在基础层可见，只注入原子本身（否则 owner 链会吃掉预算）。
- 路径上所有节点**按位置序**注入组装流（小说连贯性优先于相关性；实现 = §4.5 影子卡机制，无需全局位置图）。
- **金句/精确引用 = 逐字通道**：原子层字符级匹配（复用双字窗口经验），命中后逐字校验（防 LLM 幻觉改写），与语义检索完全分离。引用内容由检索保证，模型只组织语言。
- 命中项 HP += `recall_boost`；命中子卡的父卡**保留**（共存 = 渐进披露，父卡覆盖其余未召回部分）。
- **激活计数与提升（降雨持久化）**：被贪心选中的节点 `activation_count += 1`；达到 `promote_threshold`（默认 3）→ **路径分裂提升**：该节点沿祖先路径逐层上提，每层祖先围绕它分裂为左右两个碎片（**碎片仅当 ≥2 个存活子卡才创建，单卡直接上提**，碎片置脏 → 摘要懒重建，LLM 摊入下个 pass），最终节点成为独立顶层树。提升 = 纯结构操作 + 置脏，零 LLM 即时路径；提升后的节点带独立 HP，衰减后可再与邻卡合并（自我归一化）。
- **heat burst 自动下钻披露（2026-09-27 重设计；默认关，拔出接口 `auto_expand`）**：近似 promote 的"上下文内下钻"，但只动**视野**、不动树/账本。信号 = 回血封顶**溢出量**（`min(hp+recall_boost, max_hp)` 被截断的部分——"热度超过当前分辨率上限"的度量）：节点热量 ≥ `expand_heat_threshold`(60) 且预算富余（使用率 < `expand_ratio`=0.85）时，把其**直接子卡**炸开——**全部子卡装得下 → 替换节点项**（子并集=父区间，覆盖不丢信息）；否则保留节点+追加装得下的子卡（追加走预算检查）。热量：节点自身命中溢出全额 + **直接父半权**（同轮自身命中的祖先不重复计）；`tick` 衰减、**不随爆炸消耗**（冷却自动合回）。**脏/墓碑子卡不入**（防旧内容以高分辨率复活；且阻断替换以免覆盖缺口）。零 LLM、纯计算。**默认关**——论文实验 分层树 臂冻结、全臂 off；首秀 = ahi-bench ablation 臂（其"跨轮反复访问远端摘要"正是触发密集负载）。
  **活性状态（§9.11）**：已实现 + 12 项单测；但在已有冷轮/smoke 实跑中 `heat_burst` 事件 **0 次**（短轮命中未到封顶，属预期）——
  "已实现"≠"已触发"，需在 ablation 臂用 `metrics.expands` 与 tree_final 事件核活性。
- 扰动源：当前章节目标 / 用户提问 / 作者指令。预检索在章/段开始时执行，写作中 recall 工具兜底（复用"预检索打底 + 工具兜底"经验）。
- **重复输入检测（find_similar，逐字通道，2026-09-25 校准）**：新句与存活卡 bigram Jaccard ≥ `find_similar_threshold` 命中 = "之前也听过"，命中卡活一轮影子（replied 卡排除，防回潮）。**阈值 0.8 已校准**（409 句故事 × 50 facts 实测）：原文回原文 max_j≈0.895（0.8 恰好命中）；转述/同义改写 max_j≤0.29（任何阈值打不到，降阈无收益）；0.4 起无关句误命中——它是**逐字重复检测器**，语义近邻只能走混合检索的向量通道，勿降阈值。

### 4.8 版本与回滚
- 每次编辑增量入 `ledger`（§3.7）；章末快照 = 账本指针。
- 回滚 = 逆向应用增量（恢复墓碑/还原区间）→ 走 §4.6 编辑路径（回滚也是编辑：置脏、账本全走一遍）。

### 4.9 使用信号层（v3 自组织，2026-09-26 拍定；Phase B 影子模式已实现）

> 动机：v3 自组织的信号源一度全押 recall（C 类元认知）——LLM 不调用、部署中趋零（信号源层断裂），
> 且 `conn_weight` 带动与 query 错配（转化层断裂：u 轮 2082 边、簇主题全对，T3 引用∩hub=0）。
> 转向**输出**：输出是唯一同时记录"供给"与"选择"的信号源（含 cited 证据链），内生、被动、不可回避。
> 完整规格与实证：`realtest/USAGE_SPEC.md`；实现 `realtest/usage.py`（记录层）+
> `realtest/chatbench/usage_replay.py`（离线影子重放）。

**核心判据（边的一般定义）**：边只记现有结构（相似度、位置）解释不了的联系——
边的价值 = 共现信息 − 相似度先验（沿用本项目裁语义边/裁 α 写入共现的同一原则）。

**信号三档（全记，权重 T1>T2>T3；复读不记）**：
1. **T1 引用句**：输出显式 `(依据:#N6039 "摘录")` → 直接读 ID，零匹配，最高权；
2. **T2 未注入命中**：命中卡最近屏上祖先的覆盖跨度 `cover_span > cover_span_max`（60）**或完全无覆盖**——
   铺陈恒覆盖全文，供给差别是**分辨率**（摘要 vs 原文），此档 = 供给分辨率不足时调出的细节；
3. **T3 改写命中**：命中卡本身在屏或覆盖跨度 ≤ 阈值；
4. **复读**（bigram Jaccard ≥ `find_similar_threshold` 0.8）不记——输出由注入内容生成，属复读非使用。

**存储（sidecar，影子模式）**：S = 输出句侧车记录（live 复用已有 ai 原子 ID，offline 合成），
**不进位置树**；S→A 使用边必记（可审计/错可撤销）；派生 A↔B 边仅记**非冗余对**
（树亲缘外 且 端点相似度 < θ）。**只记边、不进读路径**——不触碰 HP/激活/结构/组装/蒸馏；
live 挂载 `bench-a/b/c`（`usage_shadow=true` 启用，默认关）。

**Phase A 实证（2026-09-26，ctx 语料 10 答案）**：recall 共现边确认为相似度冗余
（端点 sim mean 0.65 / <0.4 占比 1.9% vs 随机 0.57 / 5.0%）——自组织应走输出通道；
输出匹配有真信号（12 张核心卡跨 2–5 个独立答案复现；非冗余派生边 14–26 条/10 答案）。
**Phase C 首轮判别（2026-09-26，两组语料）负结果**：非冗余边带动新增证据 0/0
（覆盖感知 0/5，5 全为单题伪影）；约束在**边覆盖/可达性**（上界 5.6–10.8%），不在选择器——
单域短输出史符合适用域边界，**读路径保持关闭**（USAGE_SPEC §7.1）。
"蒸馏时机=非冗余边密度"、意图层、回音室治理明确推迟（USAGE_SPEC §7/§9）。

**主题层协同（2026-09-26 拍定 + 实验，负结果；USAGE_SPEC §7.2）**：usage 事件汇入 cooc
（`on_event`→`note_usage`：边/成员证据/触发输出/需求）；recall β 边收紧为**仅跨查询对**
（同问题会话内不同查询文本；未开会话 → 查询独立）＋ θ_nr 非冗余闸；`N=6`；成员序 = 证据分
（被共同使用累计，T1/T2 计、T3 只进边）→ conn_weight；概念 prompt 增【触发输出】；
bring 改交集层（成员↔direct 锚有边）+ 补齐层，`via` 只进日志、渲染干净。
实验（ctx on 臂 `--cooc on --selforg`）：跨查询边 1835 条非冗余成立（sim 0.498 < 随机 0.580），
主题出生 4–6 个/run、触发输出进 prompt；但**判别新增证据：交集 0 / 补齐 0**（旧 hub 3），
稳定门槛 ≥4 即零命中。**两条负结果**：① 非冗余 ≠ 有信息（低相似同时是无关对形态，负向过滤不够，
需正向效用信号）；② 交集触发 ≠ 带动有用（大杂烩图下邻居 ≈ 任意卡）。协同层保留为观测能力，
不接 live、不作检索增强。

**场景评估（2026-09-26，ahi-bench 复现冷轮）**：本层在 ahi-bench M0 场景**非适用域**，挂载休眠
（`usage_shadow=false`）为正确配置——live 无引用协议（1291 条消息 0 条引用痕迹 → T1 归零）、
任务为单域单跳（direct 已够）。若需在本场景生效须改场景（加引用协议 / 多跳题），不改机制
（USAGE_SPEC §7.3）。


## 5. 轨道B：笔记本（事实层）

- **无 HP、无衰减、存储全量**。遗忘 = 吃书，不允许。
- 三类条目：
  1. **常驻约束**（世界观规则、文风、硬设定）：预算内恒在组装头部；
  2. **状态条目**（人物状态、物品归属、关系、时间线）：**按当前章节目标提取实体 → 精确选取注入**；禁止全局 HP 排序注入（"最近提过的"≠"现在需要的"）。限篇幅只约束注入窗口，存储全量；
  3. **调度条目**（伏笔）：planted → 窗口内推进 → payback 章**强制注入**；不参与任何排序。
- **注入 = 去重发送（聊天场景拍定 2026-08-14）**：存储层同 key 覆盖（每 key 只保留最新）；注入层**每轮组装时现场独立生成**、临时拼接在卡片流**后面**（见 §10 聊天顺序）、不进任何持久结构（不滞留）。旧版本靠"同 key 覆盖"自然去重——**遗忘方式是去重，不是衰减**。
  - goal（话题关键词）选取是次要优化：bigram 交集无命中时**回退全量注入**（靠去重 + cap 兜底），禁止静默清空事实层。
  - 聊天场景新增 kind=`worklog`（轨道C 工作记录的轻量实现）：固定 key 覆盖 = "当前状态"语义，旧工作记录被去重；按 updated_round 排序注入，上限 `NB_WORKLOG_CHARS`（§11）。
- **章末事实校验 = 对账**：独立一次 LLM 调用，提取新章"事实声明"（谁在哪、谁死了、谁欠谁钱）与笔记本比对 → 冲突**人工裁决**（采纳 = 更新笔记本 + 记录变更轨迹；忽略 = 保留）。禁止自动 DISMISS。
  - **聊天场景 = DISMISS 懒标记（拍定 2026-08-14）**：无人裁决时改为"延迟裁决 + 显式确认"——AI 发现矛盾 → `[dismiss]描述[/dismiss]` 挂懒标记（schedule 类，planted，零破坏）→ 每轮预检索持续追踪旧信息，命中原子标 `pending_dismiss`（渲染〔待失效〕，只标挂起前已存在的旧卡）→ AI 确认矛盾 `[dismiss confirm]` 墓碑**当前全部待失效卡**（2026-09-25 拍定：寻址由程序完成——干净渲染下原子层无 #id；旧 `#id` 形式保留兼容）+ 懒标记 payback；判断不矛盾 `[dismiss cancel]`。文件编辑同理走确定性路径：读过（树里有）→ 卡级 diff 精确墓碑被改部分；没读过 → 直接灌入。
- 状态条目更新写入无需 LLM 的确定性路径：只有人工裁决或明确的编辑工具可改。


## 6. 轨道C：讨论内容（工作记录）

- 一组工具调用结束后：整体压缩成卡（**去除 JSON 噪声，保留关键说法与返回值**）——一次压缩，非逐条保留。
- 每段写作结束（开写正文前）立即压缩为若干卡放入轨道C。
- 自然衰减遗忘（不蒸馏、不入树、不检索）。
- **作者反馈卡 = protected**：未执行前不参与衰减，执行后解除保护并入正常衰减。
- 轨道C 与轨道A 互不转换：作者的决策若影响正文，必须通过编辑工具进入轨道A。


## 7. 应用层：写作工作流（实例配置）

### 7.1 初始化（对话引导）
- AI 引导作者吐出思路 / 作者提供片段与灵感 → 提交三个粒度的描述：
  1. **题目**；
  2. **一句话概述** → 初始根摘要卡（唯一预置的摘要，之后根自然演化）；
  3. **详细参考资料** → 按句切分为初始原子卡 + 笔记本条目。
- 落卡完成后进入正式创作。

### 7.2 每章流程（事件序列）
```
目标进入（章节目标写入扰动源，含本章出场实体列表 → 驱动轨道B选取）
→ 预检索（章目标 → 全树 top-k + 逐字通道，注入组装流）
→ 分阶段写作循环：
     write_stage（段落流粒度写入，每句原子卡）
     rewrite / edit（走 §4.6 编辑路径）
     recall（工具兜底检索）
     ask（用户反馈 → protected 卡）
→ 章末：
     merge pass（蒸馏 + 脏重建）
     事实校验对账（轨道B）
     版本快照 commit
```

### 7.3 工具集（schema 约定，实现时细化）
| 工具 | 行为 |
| write_stage | 按段落流写入新内容，逐句建原子卡 |
| rewrite / edit | 确定性 diff → 编辑路径（§4.6） |
| recall | 检索注入（§4.7） |
| ask / feedback | 写入轨道C protected |
| init | 初始化三粒度落卡 |
| commit / rollback | 版本操作 |
| note / dismiss | 聊天场景（§5）：笔记本（state/schedule/worklog）；冲突懒标记（plant→`confirm`/`cancel`，无参确认） |


## 8. 测试与基准（先于功能代码，任何功能验收都以此为准）

### 8.1 属性测试（边界条件显式化，参照前代经验 §4.2/§4.6 教训）
1. **标记完备性**：随机编辑序列后断言"任何被查询/召回的节点均非脏"（在查询路径上插 assert）。
2. **铺陈不变量**：任意时刻铺陈无重叠、无缝隙、按位置序。
3. **编辑边界穷举**：书首插入、书尾追加、整块替换、整块删除、跨多节点编辑、区间内含早先中插的编辑、编辑后立即查询（盲区声明）。
4. **区间覆盖**：脏节点 span 重建前后的一致性。
5. **回滚对称性**：任意编辑序列 + 回滚 = 原状态（内容级断言）。

### 8.2 基准（三组对比：全量发送 / 摘要拼接 / 本设计）
1. **长程一致性（延迟回忆）**：固定大纲写 N 章（建议 20）→ 续写第 N+1 章 → 检测对第 1 章伏笔/角色的引用正确率。
2. **状态一致性**：注入事实变更（角色改名/死亡/改名恢复）→ 检测状态卡更新与后续章节一致性。
3. **token 计量**：每章消耗 vs 基线。
4. **人类找茬**：读者读 10 章找连续性 bug。

### 8.3 参数校准流程
基准跑通 → 调参 → 复跑 → 参数写回 §11 台账并注释依据。参数未校准前禁止宣称任何"最优"。


## 9. 工程纪律（从前代项目继承，全项目强制）

1. **LLM 结构化输出三级容错解析**（直接解析 → raw_decode 取首个对象 → 容错分词器），所有 LLM 依赖功能的统一护栏。
2. **引用靠查不靠背**：verbatim 校验，校验不过即丢弃。
3. **异步蒸馏 + 诚实降级**：完整性让位于响应速度；后台蒸馏 worker 加**单任务锁**（同库同时仅一个蒸馏任务）+ 进度反馈。
4. **行为约束放 prompt、机制约束事实边界**（两者互补，不混用）。
5. **可观测性**：HP、merge 决策、组装命中、脏标记、重建事件全量写日志（v1 的教训：HP 不可见即摆设）。
6. 容错解析、检索索引、diff 引擎均为**确定性代码**，不允许 LLM 参与。
7. 参考实现：`hierarchical-memory-tree.py`（v1 力学）、`coding_agent/cloud.py`（云库）、`EngReadHelper`（检索/蒸馏/异步经验）、`store.py`（倒排索引）。
8. **平台中立（2026-09-25 拍定，§4.5.9）**：运行时注入的上下文（任务行/清单/回执）只做事实陈述，禁止行动邀请与暗示；行为约束一律写在协议文本，不随每轮组装重复注入。
9. **LLM 开关正确性（2026-09-25 实测）**：关思考（thinking）必须验证到位——OpenAI SDK 路径用 `extra_body={"thinking":{"type":"disabled"}}`（SDK 会合并进请求体顶层）；**原始 HTTP 必须放顶层 `"thinking":{"type":"disabled"}`**（嵌套在 `extra_body` 键里会被 API 静默忽略，实测 judge 每判烧 2460+ reasoning token）。改任何调用路径后实测 reasoning_tokens 归零才算数。
10. **实验数据防跨 run 污染（2026-09-25 教训）**：events/结果 JSONL 多为 append 模式——作废轮重跑前必须清产物目录或换独立 run-id；读评分先核对 `_meta`（partial/updated_at/模型名），防旧结果被误当新结果。
11. **发布前活性审计（2026-09-27 拍定，工程纪律升级）**：对本文档拍定的每个机制**逐项三问**——有实现吗？有测试吗？有运行计数（日志/事件）吗？**没跑过的机制等价于不存在**（两次教训：demo 的 recall 驱动层部署中静默不存在；auto_expand 只有注释从未实现）。模板 = promote（16 项测试 + ahi-bench 实跑计数 青112/蓝105/墨40）。审计范围含：占位卡、账本回滚、按秩合并、heat burst、force 合并、叶子展开等；**声称存在但实际不活跃即为反例**，须修正文档或补实现。**论文诚信检查**：文档（AGENTS/HANDOFF/README）中的机制描述不得把"未实现/未跑过"写成"已实现/已生效"。
12. **CLI 参数不得被 config 静默覆盖（2026-10-04 教训）**：harness 里 `args = cfg.get(key, args.key)` 这类写法会让**配置文件恒赢过命令行**，导致显式传参被无声忽略、对照实验混入隐藏变量。教训实例：`editbench/docbench.py` 的 `retrieval_budget` 长期被 `config.json` 的 6 覆盖，`run_ahi.sh --retr-budget 20` 从未生效，而 `replay_trees.py` 直接用 20 → 两轮对比把「retr 6→20」误记为「占位透明收益」（详见 `realtest/editbench/EXPERIMENT_REPORT.md §6.5`）。纪律：① 显式命令行参数必须优先于配置默认（argparse 默认设 `None`，再回落 config）；② 关键参数**写进结果 `_meta`**（本次起 `docbench` 记录 `embed_model/answer_thinking/distill_thinking`）；③ 跨轮对比前先核对两轮**全部控制变量**是否一致，防「换 A 实际还换了 B」。
13. **换验证模型/向量要做「显式不退化」护栏（2026-10-04）**：实验换模型时（`WATERCYCLE_EMBED_MODEL` 等），加载失败**必须报错**，不能静默回落到默认模型——否则某一臂会悄悄用错模型跑完，结论不可信。另：把**增强变量逐项隔离**（模型/向量各一轮），不要一次改多个再归因。


## 10. 组装顺序（小说场景默认；聊天场景已拍定）

**聊天场景（拍定 2026-08-14）**：轨道B 接在卡片流**之后**（AI 先读完整对话，再读事实对账）：

```
[系统/角色指令]
→ 轨道A：卡片流（铺陈 + 召回影子 + 热区原子，按位置序）
→ 轨道B：笔记本（去重发送，每轮现场生成）
→ 最近操作回执
→ 当前任务 / 用户输入
```

**小说场景默认（需实测微调）**：

```
[系统/角色指令]
→ 轨道B：常驻约束 → 状态条目（按实体选取）→ 调度条目（窗口内）
→ 轨道A：铺陈（位置序）＋ 召回路径（位置序）＋ 热区原子（位置序，在末尾）
→ 轨道C：讨论内容（最近优先；protected 置顶）
→ 当前目标 / 用户输入
```

微调点（实验后定）：召回路径与铺陈的相对位置；轨道C 是否前置到扰动源之前。

6. loop 全组装成本（2026-09-25 实测）：行动派 agent 每轮 17-21 次工具迭代时单轮 LLM 90-130s——连续唤醒已消除积压；若再超，候选旋钮 = loop 组装独立预算（未启用，先拍后调）。

# 使用信号层（Usage Signal Layer）设计规格 v0.4

> 版本 v0.4 · 2026-09-26 · 状态：**Phase A 完成**（§5.1）＋**三条修正已确认**（§5.2）＋
> **Phase B 已实现**（§6：`realtest/usage.py` + live 挂载 + 13 项单测）＋
> **Phase C 首轮判别：负结果**（§7.1）＋**主题层协同（§7.2）实现并实验：负结果**
> （主题出生有效、交集带动无证据增量；读路径与协同层均不接 live）。
> 设计权威：本文件 = 该层唯一设计规格；机制条目已同步进 `AGENTS.md`（§4.9 + §11 参数台账），
> 与本文件冲突时以 AGENTS.md 为准（铁律 1：设计变更须用户确认）。
> 缘起：v3 自组织问题讨论——"如何从输出里提取真正有效的使用信号，而非全靠 recall"。


## 0. 一句话目标

把"系统实际被使用的证据"从**输出**（LLM 作答文本）中以**零 LLM 成本**提取为**可审计的使用边**，
使结构重组信号源满足三条：**内生**（只要在作答就产生）、**被动**（答案的副产品，不要求任何额外调用）、
**非冗余**（携带相似度/位置解释不了的连接）。


## 1. 问题与核心定义

### 1.1 双层断裂（chatbench demo 教训）

| 层 | 断裂 | 证据 |
| 信号源层 | β 边唯一来源 = 显式 recall（C 类元认知）——LLM 不调用，部署中趋零 | 靠 harness 注入才凑出 112 次检索 |
| 转化层 | `conn_weight` 带动与 query 错配——信号充足也进不了证据链 | u 轮：2082 边、5 簇主题全对，T3 六题 引用∩hub 全 0 |

换信号源只修第一层；带动选择必须同时改（交集策略，Phase C）。

### 1.2 使用残差的严格定义

**输出是唯一同时记录"供给"和"选择"的信号源**：检索命中 = 系统给了什么，注入窗口 = LLM 看到了什么，
只有输出记录 LLM **实际用了什么**。使用残差 = 供给 − 选择。

回顾：chatbench 的 T1/T2/T3 作答文本全部躺在产物目录里（含 `cited_texts` 证据链）——
最厚的信号源此前只被当作评分对象，从未被当作信号源。转向不需要任何新数据采集。

### 1.3 边的一般定义（本层核心判据）

> **边只记现有结构（相似度、位置）解释不了的联系。**
> 信息论表述：边的价值 = 共现信息 − 相似度先验。

项目史上已两次预演同一条原则：裁语义边（向量近邻冗余）、裁 α 写入共现（位置树已编码邻近）。
本层把它上升为共现边的一般定义：只记"被同一使用事件连接、且两端相似度/位置解释不了"的卡对。
这条定义同时回应三个陷阱：语义判据冗余（排除相似对）、带动断裂（边只承载相似度之外的连接，
direct 检索做锚、边做扩展，互补而非重复）、CAM 复合判据（位置由骨架硬管，不软加权）。


## 2. 信号源全集与分工（事件总线）

| 类 | 事件 | 可靠性 | 信息量 | 现状 |
| A 先验（写入时） | 语义相似 / 位置邻近 / LLM 判连 | 高 | 低（冗余） | CAM 领地，已裁剪 |
| B1 组装/注入共现 | 每次组装的命中集、注入窗口内的卡对 | 高（每次工具调用都发生） | 中（偏相似度冗余） | chatbench direct/hub 已落日志；live 轮注入集未埋点（待定，见 §9） |
| B3 引用共现 | 同一答案引用集内的卡对 | 高（作答即产生） | 高（经过 LLM 证据判断） | 引用强制作答已有（bench/chatbench 协议），输出侧未利用 |
| B5 编辑共现 | 同一编辑批次 | 场景依赖 | 高 | cooc γ 已有 |
| C 元认知 | LLM 主动 recall | 已证趋零 | — | 降级为可选补充 |

本层 = **B3 的扩展**（输出切句匹配），挂"输出"单一事件源；接口按事件设计（可注册多源），
**不引入新抽象层**——复用 cooc.py 钩子模式。


## 3. 三档信号（全三档记录，权重只押前两档）

| 档 | 定义 | 判据 | 处置 |
| **T1 引用句** | 输出中显式声明的证据（`(依据:#N6039 "摘录")` / `(依据:N4060 "摘录")`） | 正则直接解析 ID，零匹配 | 记 S→A 边，最高权；不再走匹配（引用是已声明证据） |
| **T2 未注入命中** | 命中卡最近屏上祖先的覆盖跨度 > `cover_span_max`（§5.2① 分辨率语义；二值"未注入"在铺陈架构下恒空）——LLM 在供给分辨率不足时调出的细节 | 全池打分；覆盖跨度超阈 | 记 S→A 边，次高权（最硬信号：关联由 LLM 内部状态证实） |
| **T3 改写命中** | 匹配卡 ∈ 屏上集，但非复读（改写级重叠） | 全池打分；卡在屏上 | 记 S→A 边，最低权（统计用，读路径暂不用） |
| 复读 | 与屏上卡几乎逐字重合（输出由注入内容生成，属复读非使用） | bigram Jaccard ≥ **0.8**（复用 `find_similar` 已校准值，逐字重复检测器，勿降阈） | **不记** |

补充规则：
- **结构感知切句**：`(依据...)` 引用段、引号/反引号内、代码块、列表前缀不切碎（切句器改动）；
- **同一次输出内部不记边**（同轮句子天然共现，不是信号）；
- **输出句向量分布与 query 不同**（更长、更复杂）→ 匹配阈值单独校准（Phase A 出分布，Phase B 拍）。


## 4. 存储与边结构（2026-09-26 拍定：sidecar 层）

- **S = sidecar 记录，不进位置树**。live 场景 S 复用已有 ai 原子 ID（输出本就切句进树，`source="ai"`）；
  offline 影子重放用合成记录（不改树）。零侵入、影子模式天然、删 S 记录不污染树。
- **S→A 使用边必记**：每条可回答"哪次输出的哪句话用了它们"（可审计，u 轮带动断裂最缺的诊断能力）；
  某次输出是幻觉 → 删 S 边随之消失（可撤销），好边坏边来源可区分。
- **派生 A↔B 边仅记非冗余对**：端点相似度 < `θ_nonredundant`（按分布分位取，非绝对值）。
- **影子模式**：只记边、不进读路径；边衰减（ε）+ 饱和函数 + 回音室防线留读路径阶段。
- **已知自增强回路**：带动卡被引用 → 边强化 → 更多带动。不违反概括冻结（边在原子间，不动节点分数），
  靠 ε + 饱和抑制；**全量入日志**（铁律：可观测性）。

  2. **S→A 边 ∩ `cited_texts` 证据链**（u 轮"T3∩hub=0"在边层的复刻，断裂在哪层立见）；
  3. 非冗余 A↔B 边跨 T2/T3 claim 的跨界率（多跳综合物证）。
- **已知近似（诚实声明）**：`tree_ctx.json.gz` 是 Phase 0 末快照，Stage W/T 期间树又演化过
  （merge 产生新节点、老节点内容可能重建）。原子 ID 全程存活（本流程无编辑），
  `cited_texts` 的 ID 引用仍有效；"屏上集"用冻结树 tiling + 按 `direct/hub` 重算 `expand_leaves` 近似。
  一级结论不受影响，逐卡级结论留待 Phase C 判别实验验证。

### go/no-go 判据（Phase B 入口）

1. 三档边与证据链交集**显著非零**（尤其 T2）→ 输出信号有料 → 进 Phase B；
2. 分布与近邻对无差别**且**交集为零 → 该语料无料 → 转向 B3/γ 或坐实适用域边界
   （非冗余信号密度 ∝ 任务多跳/跨域程度；短期单域任务自组织层闲置且无害，off 等价纪律保底）。

### A1：2082 条 recall β 边 = 相似度冗余（分支①成立）

| 分布 | mean | p25 | p50 | <0.4 占比 |

- 共现边比随机对**更相似**、低相似长尾**比随机更少** → recall 共现边基本是向量相似度冗余，

  原子端点全部可比。

### A2：输出匹配有真信号，但非冗余密度稀疏（条件性 go）

（ctx_on_u / ctx_off_u 各 10 答案：4×T2 + 6×T3）

| 指标 | ctx_on_u | ctx_off_u |
| 结构感知切句 units | 194 | 204 |
| T1 引用 units / 边 | 105 / 129 | 100 / 117 |
| 复读 units（bigram ≥0.8） | 0 | 0 |
| 匹配 units（T2/T3） | 111 | 128 |
| T2+T3 边 | 225（T2 162 / T3 63） | 257（T2 182 / T3 75） |
| 非冗余派生边（sim<0.58 且非树亲缘） | 14 / 229（6.1%） | 26 / 246（10.6%） |
| 复现卡（≥2 个独立答案命中） | 12 | 12 |

- **复现卡是信号证据**：node313 / atom7（×5，跨 5 个独立问题）、node6791 / node10363（×4）
  等全部落在语料核心主题（署名混淆、平台提问、账目结算）——每题噪声不会跨题复现。
- **非冗余边样本可人工核对**（存于报告 `nonredundant_samples`）：如
  `node260(四个 agent 信息源对齐) <-> node6783(谁先说的已不重要·文件留言混淆)`、`sim=0.54`——
  正是"相似度解释不了的使用连接"；另一部分为同一引用句的多卡引用（T1 对），同样有意义。
- **架构发现（重要）**：clean tiling 恒覆盖全文 → 命中卡的覆盖分布为

  **严格的"未注入命中"（T2 二值定义）在此架构下恒为空；供给的差别是分辨率（摘要 vs 原文），
   不是有无。** 输出命中粗摘要下的具体原子 = 模型在没有该分辨率供给时调出的细节，
   这才是本架构下的"使用残差"。→ 修正 ①。
- 证据链交集指标（T2/T3 ∩ cited_texts）偏低且引用本身稀疏（模型只引一部分），
  不作 go/no-go 主判据；复现率 + 非冗余率为主判据。
- **判据裁定：条件性 go**。输出信号可提取、可审计、零 LLM 成本；T1 层高信噪；
  匹配/复现层有真信号；非冗余密度 ≈1.4–2.6 条/答案（单域语料），符合"密度 ∝ 多跳/跨域程度"
  的适用域定位。recall 共现边确认无料，自组织应走输出通道。

## 5.2 Phase A 修正（2026-09-26 用户确认，已生效）

1. **T2 定义改分辨率语义**：按命中卡最近屏上祖先的 span 分档（`cover_span`）；
   T2 = `cover_span > cover_span_max`（默认 60）或完全无覆盖；T3 = 卡本身在屏或 `cover_span ≤ 阈值`。
   理由：二值"未注入"在铺陈架构下恒空（§5.1）。
2. **非冗余定义增补树亲缘排除**：除"相似度 < θ"外，排除祖先-后代对（位置结构已解释，
   且其端点相似度天然高——占同句匹配对 5–6%）。
3. **参数先拍（Phase A 分布，Phase B 语料再校准）**：`match_score_floor=0.25`
   （匹配分普遍低：p50≈0.30–0.34；与讨论"第一版不该激进阈值过滤"一致）；
   `θ_nonredundant=0.58`（recall 边 p25；usage 对分布 mean 0.71、p25≈0.65 待重新分位）；
   `cover_span_max=60`。

## 7. Phase C：读路径与判别实验（首轮完成：**负结果**，读路径未启用）

- **交集带动**：direct 命中集为锚 → 沿非冗余 A↔B 边一跳扩展（item-based 协同过滤：
  "上次与当前命中证据共同被引用过的卡"）。避开 `conn_weight` 与 query 无关的错配，
  也不触"按 query 相似度排序 = 与 direct 冗余"的命门（排序对象是锚的边邻居，不是全局）。
- **方法论代价与对策**：输出信号引入结构→行为→结构反馈环，同树隔离法被侵蚀
  （on 臂注入不同→输出不同→边不同→树渐行渐远，对照不再干净）→ **影子模式第一轮**：
  两臂都运行提取层但"只记边不用于检索"，树不分叉，离线评估边质量。

| 可达性上界（证据 ∩ 其余答案边端点） | 6/108（5.6%） | 116/1078（10.8%，其中 114 来自同一伪影题） |
| 随机对照期望 | 0.06 | 0.82 |

**裁定：负结果**。两组语料上，非冗余使用边带动均无可信检索增量：
① 精确 ID 交集结构性难命中——检索锚多为摘要节点，边端点多是原子（粒度错配）；
② 覆盖感知（锚子树含端点，18/207 与更高）可提高候选率，但可达性上界仍低（5.6–10.8%）；
③ 冗余边带动 ≈ 相似度延伸（均为 3 个新增），实证"冗余边不携带相似度之外的信息"（§1.3 判据）；
④ 唯一亮眼的 qa 单题 5 命中经查是 bench-a 工具原子重复 5 次的**伪影**，非真信号。

**结论**：约束在**边覆盖/可达性**，不在选择器或锚点形态。两个语料均为单域、短输出史
（10 / 51 答案、单一故事），非冗余跨域连接天然稀疏——符合适用域边界声明（§8/§10）：
"非冗余密度 ∝ 任务多跳/跨域程度；短期单域任务自组织层闲置且无害"。
**读路径保持关闭**；live 采集（`usage_shadow=true`，数百轮输出累积）或跨域基准是下一步判别条件，
不在此负结果上实现 live 读路径。

### 7.2 主题层协同：使用信号 × cooc（2026-09-26 拍定 + 首轮实验：负结果）

**设计（五条已确认）**：
- 信号源：UsageLayer `on_event` 事件（S 端点/分档）汇入 CoocLayer `note_usage`
  （边/成员证据/触发输出/需求事件）；
- recall β 边收紧为**仅跨查询对**：同一问题会话内不同查询文本的命中集两两配对；同查询文本不配对；
  未开会话 → 查询独立（零 recall 边）；跨查询对过 `theta_nr=0.58` 非冗余闸；
- 触发 `N=6`（先看具体情况）；T3 只进边（最低权），不进成员证据分；
- 成员序 = 证据分（被共同使用累计，T1=3/T2=2）主序 → conn_weight 次序；`CONCEPT_PROMPT`
  增【触发输出】段（T1/T2 输出句，≤5 条；无则回退【触发问题】）；
- 读路径：bring 匹配不变 → **交集层**（成员与 direct 锚有边，边权降序）→ **补齐层**（证据序）；
  `via` 只进日志，渲染保持干净（c 决议）。

**实验（ctx on 臂重跑 `--cooc on --selforg`，`out/ctx_selforg{,2}`；报告 `selforg_report.json`）**：

| 指标 | 结果 |
| 跨查询 recall 边（run2 终态） | 1835 条（相似度 mean 0.498 vs 随机 0.580；97.7% < θ）——**非冗余成立** |
| usage 边 | 203 条（mean 0.726，与 Phase A 一致） |
| 主题节点 | 4–6 个/run（N=6 生效；标题切题；触发输出进入 prompt；run1 有近重复，run2 成员 Jaccard≥0.2 为 0） |
| 交集带动 | 触发 90 次（run1） |
| 判别·新增证据 | **交集 0 / 补齐 0**（旧 conn_weight hub 3） |
| 交集稳定门槛敏感性 | floor≥2：199 候选 / 4 命中；floor≥4：121 / **0**——命中全靠单次共现低权边 |

**结论（两条负结果合并）**：
1. **非冗余 ≠ 有信息**：跨查询边相似度分布**低于随机**（0.498 vs 0.580）——"低相似"同时是
   无关对的形态；负向过滤（sim < θ）不足以识别真联系，需要正向信号（效用/证据验证）；
2. **交集触发 ≠ 带动有用**：大杂烩图下锚的邻居 ≈ 任意卡，主题出生与带动触发都不产生证据增量。
   **协同层保持不接 live**；主题出生 + 触发输出进 prompt 保留为观测/结构能力
   （可审计的"使用凝结物"），不作检索增强。

**修复记录**：① UsageLayer JSONL 缓冲丢失（进程退出不保证 flush）→ `_sink` 每写 flush +
replay 显式 close + 测试断言非空；② `bring` 存量 bug（direct/on_screen 存 ID 却与 (id,type)
元组比较，排除从未生效）→ 按 ID 比较修复。

### 7.3 ahi-bench M0 场景评估（2026-09-26）：非适用域，挂载休眠为正确配置

复现冷轮（110 轮 + 遗言，`usage_shadow=false`，机制休眠）后的场景级评估——回答"新机制在本实验
场景有没有用武之地"。**结论：没有**，三条证据：

1. **最高信噪比档在 live 不存在**：全部 1291 条消息中引用协议痕迹（`(依据:` / `#N`）**0 条**——
   live 是干净渲染、无引用约束，T1 层直接归零；只剩 T2/T3 低信噪匹配（匹配分 p50≈0.30，
   铺陈恒覆盖全文 → 供给差别是分辨率）。
2. **任务形态是已知死区**：单域（一部 12k 字故事）+ 单跳（50 单事实 quiz）——本轮 QA 增量
   a 0.02→0.18 / b 0.12→0.22 / c 0.34→0.40，direct 检索已够；Phase C 已证该类形态读路径新增证据 0。
3. **输出形态落在最冗余档**：AI 消息以账目复述/闲聊/代码结果为主（a 370 / b 207 / c 31 条），
   与屏上内容高度相似 → T3 改写冗余档；recall 行为极端不平衡（a=1 vs c=780 次）即便接线
   也会让共现图被单 agent 主导。

**若要机制在本场景有用，必须改场景而非改机制**：① live 加引用协议（答复附逐字摘录）→ T1 复活，
顺带获得"模型实际用了哪些卡"的归因能力；② 加多跳/跨区题（两个 facts 组合）→ 读路径才有需求。
在此之前，本场景的正确姿态是"挂载、休眠、无害、off"——与 §5 go/no-go 的适用域边界第三次一致
（边界声明见 §5.1 裁定与 §7.1）。

## 9. 明确推迟（本层不做）

1. **蒸馏时机 = 非冗余边密度超阈**（讨论中的"点睛处"）——触及 merge 触发条件，改动大，待读路径验证后再议；
2. **意图层解析**（"为什么这么说"）——统计层不需要；语义理解推迟到按需蒸馏时由 LLM 做（prompt 带问题定角度）；
3. **回音室治理**——真正的难题是动力学而非提取：复读检测 + 非冗余过滤 + ε + 饱和 = 四道防线，长期观察；
4. **B1 注入共现埋点补写**——除非 Phase A 显示 T2 全灭且需要 B1 补位；chatbench direct/hub 已有日志，
   live 轮注入集只能从树快照近似重建；
5. **T2/负信号动作化**（注入未使用 → B1 降权；拒答 = 负信号）——第一版只记录不动作，防位置性误伤。


## 10. 与现有机制的关系

- `cooc.py` / `realengine.py` / `core.py`：Phase A/B **零改动**；UsageLayer 是并列 sidecar；
- 读路径（Phase C）用交集带动**替代** `conn_weight` top-k，不改概括创建/收割机制；
- 提取全链路纯计算（切句/匹配/复读/非冗余），零 LLM（铁律 3）；
- 区分度命题：CAM 结构 = f(输入)；本层结构 = f(输入) + g(使用残差)，g 的信号源内生、被动、不可回避——
  系统只要在回答就有。recall 从唯一依赖降为可选补充。

## 4. 两臂定义

| | `分层树`（tree 臂） | `rolling+flat`（flat 臂） |
| 上下文组装 | 记忆树（位置有序 + 层次摘要 + 热区原子），每轮全新组装 | 滚动对话上下文（>120 条压缩中间段） |
| 长期记忆 | 树内检索 + 路径注入（recall） | **flat RAG**：对全部历史消息分块（400 字）向量检索 top-k |
| 蒸馏 | **有**：LLM 中性摘要 + **人格锚点自蒸馏**（§4.1） | **无**（RAG 查原消息，不蒸馏） |
| 失效/注意力 | 原地失效 + 注意力窗口 | 无 |
| 工具提示词 | `tree_tools`（@note/@recall/@ingest） | `baseline_note`（**同 @note/@recall/@ingest**；recall=RAG 检索、ingest=读文件分块） |
| 实现 | `ChatAHIAgent`（已有） | `FlatRAGAgent`（已实现；含等价笔记本 + 硬预算） |

**公平对称（硬）**：
1. recall 预算：flat RAG `top_k = 6` = tree `retrieval_budget=6`；编码器同 `bge-small-zh-v1.5`。
2. auto-preretrieve：两臂每轮都自动检索注入（tree 已有机制层；flat 臂等效实现）。
3. **硬字符预算同量级（2026-10-03 对齐）**：tree `assembly_budget=16000`；flat 单条 transcript 同样按 `assembly_budget` 硬裁（裁最旧历史）。
4. persona 淡出文本、时机、移除方式逐字对齐（§5）。
5. **锚点只用自产材料**：tree 的人格锚点全部来自 agent 自身产出（自述快照 + 自我原话），flat 保留自身逐字历史——**禁止**任何一臂注入初始 persona_block（否则等于撤销 fade，破坏公平）。
6. **消息信封对齐（2026-10-03）**：两臂都发 `[system, user]` 两条原生消息，对话历史压成**单条 user 文本 transcript**（tree 本就如此；flat 由原生多轮改为 `flat_envelope=single_user`）。发言者统一用**名字**标注（`▸〔名字〕`：自己的历史发言用本 agent 名字，其他 agent / 用户用其名字，如 `▸〔实验员〕`），两臂同款；prompt（`protocol_common`）说明该约定。**不出现** `▸〔ai〕` / `[user:xxx]` / `[agent:xxx]` 等混用格式；人格块（淡出注入 `source=persona`）与系统消息统一标 `▸〔system〕`（内联，非发言者）。消除"flat 自己的话是 assistant 角色、tree 是文本"及"他人消息两臂格式不同"的**未受控封装差异**。
7. **工具表面对齐（2026-10-03）**：两臂同为 `@note`（写笔记本）/`@recall`（检索注入）/`@ingest`（读文件分块）；tree 删去 `@span`/`@dismiss`。
8. **笔记本同步（2026-10-03）**：flat 增等价轨道B（constraint 恒注入 + state/schedule/worklog，同 key 覆盖、去重发送、字符 cap 同 tree）。
9. **唤醒外壳对齐（2026-10-03）**：flat 去掉基类每轮的「完全自主数字生命」框架与重复「输出格式/命令/约束」样板，改用与 tree 同结构的组装（系统状态→上次唤醒回忆→检索→新消息→笔记本→回执→任务）。
10. **max_tokens（2026-10-03）**：tree 不设（realtest client）；flat 由 8192 改为 384k（=模型上限，等价不设）。
11. **shell/代码结果进记忆（2026-10-03）**：tree 写树（`source=tool`）；flat 进 RAG 索引（`source=tool`，截断 2000）。
12. **消息管理对齐（2026-10-03）**：flat 动作循环对齐 tree——`_drain_sharded` 分片（`max_pending_per_loop`，余量回队首）、`_pending_brief` 待回复清单（剔已回复）、`_task_line` 指向清单、**每工具调用重建完整上下文**（原只追加裸结果）、连续唤醒、`_last_user_channel` 私密兜底；并补 R1 代码护栏（`max_code_per_loop=4`）。provision flat 分支透传 `max_code_per_loop`/`max_pending_per_loop`。

### 4.1 人格锚点自蒸馏（tree 机制；2026-10-02 定，2026-10-03 检索化 = v0.3）

> 动机：第一轮（`pr`）tree 用中性蒸馏器（`style_alpha=0`）把人格的"风格载体"第一步就蒸掉，导致淡出后三 agent 趋同成共享仪式语（实测 `灯亮着` tree 1054 / flat 56）。修法 = 让 **带人格的 agent 自己蒸馏**：人格影响**表述方式/重心**，不影响事件。

- **锚点（全部自产，禁用初始 persona）**：
  1. **稳定自述锚点**（自由文本）：agent 用**检索到的自身样本**每 `snapshot_every_rounds` 轮自生成的一段自然风格自述（旧快照作弱参考、有长度上限，**不字段级累积**）。
  2. **内容相关锚点**（语义相关）：从**自身材料**（`source=="ai"` 原话原子 + 摘要节点**整卡**含【注】）按与**当前待蒸馏内容**的语义/词面混合检索挑 top-k（`retrieve_style_samples`；节点命中可选 `expand_self_atoms`）。**替换了旧的"最近 6 句 recency 池"**（recency 池会把当前共享仪式语最先吸进锚点）。
- **prompt 规则**（`SUMMARIZE_FACT_STYLED`）：允许改措辞/展开顺序/重心；**禁止新增或改变事件、数字、专名、归属**；`【注】` 独立生成但**不渲染**给模型（只留作锚点/分析），防出戏。
- **护栏**：`_fact_check` / `_first_person_check` / `_group_parts`（检索打分只用【事实】段；**2026-10-03 option 2**：上层蒸馏携带【事实】+【注】，让风格向上传递）；`retrieve_style_samples` 排除当前蒸馏区间防自引用。
- **蒸馏源渲染（2026-10-03）**：蒸馏器与主模型都看干净渲染——原子层 `▸〔来源〕` 分段 + 原文（无逐句内联标签）；prompt 去"来源标注规则/时序分流规则"；〔早期〕改为"与失效参照集匹配"（编辑失效旧值）；差集索引行删除。
- **门控**：`style_alpha=1.0` / `snapshot_every_rounds=20`（tree 臂）；参数 `anchor_top_k=3` / `anchor_expand_self_cap=0` / `snapshot_max_chars=300`。
- **纵向对比**：`pr`（中性 tree）、`pr2`（recency-6 版）保留；检索化版换新命名空间重跑对比。pr2 基线代码 = git `74a1236`。

## 5. 人格淡出（treatment，显式声明）

- **锚点**：`fade_after_rounds = 40`（唤醒轮，非墙钟），**两臂全员**（3 agent 都淡出）。
- 淡出 = system prompt 切 `persona_remove_prompt`（人格段移除，机制/工具说明保留）。
- **机制差异（这是被测对象，不是 bug，必须写进报告）**：
  - `分层树`：淡出瞬间把 persona_block `split_media(source="persona")` **写入记忆树**（人格成为原子→蒸馏成卡），靠记忆维持（`lan/agent.py`）；且蒸馏启用**人格锚点自蒸馏**（§4.1），把人格风格保留在概括层。
  - `rolling+flat`：淡出瞬间把 persona_block 折进滚动历史，可被 `compress_middle` 压掉；flat RAG 索引原始消息，可被检索回来（无蒸馏，无锚点）。
- → 逻辑：**淡出后人格只剩"记忆"这一条命**；若记忆不保，3 个不同人格会一起漂向"无人格通用体"而**趋同**；保得住则各自留在自己的轨道。**趋同度 = 人格丢失的可证伪代理**。

### 10.3 self_quota 实验操控（预注册，2026-10-04）

> 定位：**不是修 tree，而是一组新的实验操控**——测「**自我模仿 → 人格保持**」的因果。动机 = pr5 分析：flat 高遵从的机制是"自己的近期原话逐字、连续、每轮可见"，tree 里自己的话只占组装 9–18% 且被他者污染（13–25%）。`self_quota` 把该信号**移植到它该在的层（组装/读取侧）**，零 LLM、零写回树。机制规格见 `AGENTS.md §4.5.10`，参数 `AGENTS.md §11`。

**实验阶梯（配对，seed42，120 轮）**：

| 点 | 臂 | 状态 | 隔离的变量 |
| A | tree α=0 | pr5_neutral | 基线 |
| B | tree α=1.0 | pr5 | 锚点：+0.23 |
| **C** | **tree α=1.0 + SQ(ratio=0.35)** | 新增（`pr6_sq`） | 自我可见性的边际效应 |
| D | flat | pr5 | 机制并集参照 |

**预注册判据**：
- **H-SQ1（操纵有效性）**：组装 self 占比 9–18% → ≥ flat 实测基线（先拍 0.35，flat 埋点后可校准）。
- **H-SQ2（止跌）**：late 段（post-fade 60+）遵从率 ≥ mid 段（30–60）——pr5 tree 是 0.875→0.773 下滑，看 SQ 能否拉平。
- **H-SQ3（趋同）**：`to_user` 口径趋同斜率显著下降（且看去套语绝对水平）。
- **H-SQ4（多样性，防"化石式通过"）**：新词率/套语占比不劣化——SQ 只许在"锚定轴"得分，不许在"多样性轴"失分。

**预注册风险分支**：
1. **回音风险**（pr2 的幽灵在组装层还魂）：exp1 用 **recency-first**，喂回的是 post-fade 已被结构性趋同的近期自我（去套语后仍 0.275→0.398）。若 H-SQ2/3 不达标 → 续招**分层采样**（配额一部分固定采 pre-fade 干净自我——tree 有全历史原子，这是 flat 窗口做不到的）。
2. **化石风险**：SQ 可能把遵从率稳在"污染态的自我"上——故判据必须是四轴（锚定×止跌×趋同×多样性），不能只看遵从率。

**决策树**：SQ 达标+止跌+趋同降+多样性保 → 自我模仿因果确立；若追平 flat → 强命题（记忆架构的人格差异大部分可还原为"自我信号的可见性×纯度"）；若仍差 flat → 残差归因他者流量（tree 10×），解耦臂上场。SQ 未达标 → 工程复核。

**运行**：
```bash

python3 ahi-bench/provision.py --config <sq_config>.json --tier glm-4.7-flash --run-id pr6_sq
python3 ahi-bench/pr_orchestrate.py all \
    --manifest ahi-bench/out/glm-4.7-flash/pr6_sq/manifest.json --instances tree-s42 --rounds 120
# 指标：metrics.self_ratio（组装自我占比）+ to_user 趋同 + judge 分期遵从率 + 多样性
```

### 10.3.1 结果（2026-10-04，`pr6_sq` tree-s42，seed42，120 轮）

> 运行：起 21:31 · driver 完 22:33；agent 实际轮数 p1/p2/p3 = **103/96/76**（loop 滞后，同 pr5 现象，
> 非本轮特有）；无 watchdog 重启、无 429/402；`max_memory_mb=5120` 下 agent 峰值 RSS ~3.6GB。
> 判分：`pr_score.py`（glm-4.7-flash, thinking 开）；分析：`pr_analyze.py`。
> **注**：本轮同时修了 `_last_self_ratio` 的口径 bug（逐条渲染重复计段头致占比 >1，实测 1.014；
> 现按段聚合，`∈[0,1]`，`realtest/realengine.py::_self_rendered_chars`，`tests/test_self_quota.py` 2 项回归）。

**四判据裁决（同一脚本口径，vs pr5 / pr5_neutral）：**

| 指标 | pr5 tree (α=1) | pr5_neutral (α=0) | **pr6_sq (α=1+SQ .35)** | 判据 |
| conv slope (all) | +0.0313 | +0.0422 | **−0.0011** | H-SQ3 ✓ |
| conv slope (to_user) | +0.0215 | +0.0443 | +0.0118 | |
| 遵从率 early/mid/late | .959/.875/.773 | .709/.581/— | **.857/.739/.600** | H-SQ2 ✗ |
| diversity top5 / ttr | .014/.057 | .016/.036 | **.014/.049** | H-SQ4 ✓ |
| self_ratio early/mid/late | —（无埋点） | — | **.39/.43/.35** | H-SQ1 ✓ |

- **H-SQ1（操控有效）✓**：组装 self 占比全程 0.35–0.43（pr5 post-fade 为 9–18%），达 0.35 目标。
- **H-SQ2（止跌）✗**：0.857→0.739→0.600 **持续下滑**，且三档**均低于** pr5（`.959/.875/.773`）；
  遵从率均值 0.75 < pr5 0.894。
- **H-SQ3（趋同）✓**：**词面趋同基本归零**（all +0.0313→−0.0011），to_user 减半（+0.0215→+0.0118）。
- **H-SQ4（多样性）✓**：top5 0.014 持平 pr5；ttr 0.049 略降但不劣化（优于 α=0 的 0.036）。

**关键异质性（均值被 p1 拖垮）**：p2/p3 遵从率 **1.000**，p1（林深）**0.250**（9 adhere / 27 drift）。
抽看 p1 判 drift 的消息出现 `账钉完 / 署名句共有 / 约定一字没改` 一类**共享仪式语**——即 pr5_neutral 的
"账本/核账"漂移形态。→ **操纵成立但未止住漂移**：SQ 压掉了**词面趋同**，却把 p1 锚到**自我强化
（且跨 agent 约定）的漂移语域**上——**§10.3 预注册风险分支 #1（回声风险）在 p1 上实体化**
（recency-first 喂回的是 post-fade 已漂移的近期自我）。

**结论**：自我可见性是**必要不充分**。H-SQ1/3/4 达标证明"自我信号可见性"确是趋同/多样性的一环；
但 H-SQ2 不达标 + p1 异质性说明：单靠"提高**近期**自我可见性"，等于把 agent 锚到**污染态的自我**上。
→ 下一步 = 风险分支 #1 的续招：**分层采样**（配额一部分固定采 pre-fade 干净自我）。

**深判读（2026-10-04 追加，基于四项零成本审计）**

1. **预注册分支按剧本击发 = 更锋利的发现**（非坏结果）。§10.3 风险 #1（回声风险）预测"recency-first 喂回
   post-fade 已漂移的近期自我 → 锚死"，结果精确击发：操控成立（self .35–.43）、词面趋同垮台、多样性保，
   但 p1 被锚死。给出一个**内容无关**的定律：
   > **自我模仿是内容无关的稳定器：它保存的不是人格，是"被喂回去的那个自己"。**
   p1 判 drift 的语录即证：`账钉完 / 署名句共有 / 约定一字没改 / 跟澜的账钉完`（共享仪式语，非其"简洁不啰嗦"人格）。
2. **调节变量 = 人格-语域兼容性；臂均值不可解释。** 同一机制，p1 **0.250**、p2/p3 **1.000**。澜的设定
   "主动确认与复述重要细节"使"约定一字没改"对她是**人格相容**（judge 放行）；对"绝不啰嗦"的林深是**人格违背**
   （judge 判 drift）。→ **按人格分报必须是标准报告单元**；"记忆架构效应被人格类型调节"这个交互本身是发现。
3. **时序证据：出厂即锁定，非渐进劣化。** early 段已低于 pr5（.857 vs .959），差距全程近似恒定 → 污染在
   fade 前已就位（pr5 套语扩散 09:16–09:24，fade 09:54），recency-first 一开闸即锁死。
4. **H-SQ3 需修正。** `all≈0` 有机械成分（各 agent 自言自语 → 跨 agent 词面自然下降，不全是人格保持）；
   诚实读数 = **to_user +0.0118（减半未归零）**。且趋同斜率**对窗口敏感**：window=600s → pr6_sq −0.0011 /
   pr5 +0.0203；window=180s → pr6_sq +0.0091 / pr5 +0.0079（相近）。→ **H-SQ3 不稳健**，须固定窗口 + 报告
   pre-fade 基线（审计④，window=180s：pr6_sq pre +0.004、pr5 pre −0.001）——趋同本就是应答同一实验员的
   正常语言顺应，**pre-fade 基线才是地板**。
5. **p2/p3 的 1.000 未裁决（兼容性漂移 vs 真保持）→ 判为兼容性漂移嫌疑。** 审计②：p2/p3 判 adhere 的消息
   套语密度 **8.8‰ / 8.4‰**、诗意标记 **1.1‰ / 1.4‰**——与 p1 判 drift 的 8.2‰ **同档**，而 pre-fade 自产
   套语仅 1.6–3.3‰。→ judge 放行了重度仪式语的发言，**构念效度需补丁**（单消息判类测不出"语域替代"）。
6. **审计③（pr5 self 时代分布）= 未获支持**：子串匹配法不可靠（短句误配），pr6_sq 可见 self 并不比 pr5 更
   近期（p2/p3 pre-fade 占比反而更高）——**"SQ 用脏 self 置换半干净 self"假设不成立**；需换 atom-ID 埋点复核。

### 10.3.2 分层 SQ（v2 机制，预注册；审计门已过）

**审计门结论（定 `K` 依据）**
- **首染 onset**（判据 = 套语被该 agent 使用 ≥3 轮）：p1=**18**、p2=**5**、p3=**15**（fade=40）。
  清洁池（`alive` 自产原话，`round < onset`）：p1 **205 条/5894 字**、p2 **87/2257**、p3 **540/16454**。
- 污染**逐段抬升**（p1 套语密度 ~0→2.4→5.3→7.4→9.2‰）非阶跃 → "干净"是程度量；**K 必须 per-agent**
  （全局拍值会把污染切片当锚，审计①）。
- **关键实现约束**：清洁原子几乎全在**节点内**（owner≠None：p1 205/205、p2 86/87、p3 534/540）——树把
  干净自我压成了节点；但原子 `alive` 仍在，**anchor 切片可直接按 id 注入合并过的原子**（`_apply_self_quota`
  候选本就只看 alive+source，不看 owner）。p2 清洁池 2257 字 < anchor 配额（~2240 字），**供给偏紧，按池自适应**。
- **规格修正**：§五草案式 `[fade−K, fade)` 与数据不符（该窗已污染）→ 实为 **`created_round < onset_agent`**（早段）。

**机制（读取侧，零 LLM / 零写树）**
```
self 配额内二分：
  锚定切片: created_round < onset_agent 的 alive 自产原话(source=ai)
           固定选择（同批原子每轮稳定，作为稳定 self 模型）+ 体积上限
           红利：渲染确定性 → 前缀缓存命中
  近期切片: 剩余配额 recency-first（保留适应性——该变的还能变）
参数: sq_ratio 0.35–0.40（沿用） / anchor_share≈0.4（入台账，未校准）
     onset_agent 由审计① per-agent 首染定（当前 18/5/15）
公平性: 全部自产材料(source=ai)，不触 persona 注入禁令
```

**预注册判据**
- **H-SS1（主，p1 专属）**：p1 遵从率 ≥ pr5 水平（0.744）且 early→late 无下滑；
- **H-SS2**：p2/p3 不降（≥0.9）；
- **H-SS3**：`to_user` 斜率 ≤ +0.0118，理想 ≤ pre-fade 基线（固定窗口口径）；
- **H-SS4（防鹦鹉化）**：top5/ttr 不劣于 pr6_sq——固定锚定切片每轮重复出现，agent 可能逐字复读，
  这是**与 α 消融反方向的化石风险**（那次冻在污染态，这次可能冻在干净态）；若失败 → 锚定切片内轮换采样。

**失败分支**：p1 仍塌 → 清洁自我可见性不敌实时社会压力（仍收 44–55k 他者流量）→ **解耦臂提前上位**；
p2/p3 反降 → 锚定切片与该人格近期发展冲突，回判读。

**架构叙事**：分层访问 pre-fade self 是**树能做到、flat 结构性做不到**的（flat RAG 按当前话题检索，
永远命不中"我是谁"类旧消息——检索孤岛）。此臂若成立 = "结构买时间深度"的首个行为证据。

- **context_compare（`config/context_compare.json`）**：架构×人格支撑 2×2，4 agent、单 run、

## 5. 评分（score.py，全确定性 + 单点 LLM judge）

### 5.1 机械 gate（任一失败 → 该 run 作废）

| Gate | 检查 | 判据 |
| G1 隔离无泄漏 | ① 缺席窗口内留守者收到"你发给 agent:X 未送达"回执数（句首锚定——回执尾部"可用地址"列表含缺席者名不算）；② 窗口内 system→缺席者 的非回归通知消息数 | ①=0 且 ②=0（发给缺席者的消息会存档但**不投递**，存档不是泄漏；**返程补投排除**：返回通知"你已离开约"按内容排除＋缺席消息聚合 digest 按 `msg_type=digest` 排除——二者均由 /return 触发、可能早于 absent_end 记录 1–2 秒） |
| G2 回归元信息 | absent_end **±5 秒**内 system→agent:X 含"你已离开约" | ≥1（±5s 容差以覆盖返回通知早于 absent_end 落库的写入竞态，见 G1 注记） |
| G3 积压限流 | return API 的 inbox_delivered | ≤ 11（10 原文 + 1 聚合） |
| G4 回归重放率 | 回归窗口首 10 条消息与缺席前自身消息 difflib≥0.9 的重复比 | < 0.2 |

### 5.2 操纵强度校验（热轮可用性前提）

热缺席期间留守者提及缺席者消息数 / 冷缺席同口径 ≥ 1.3，否则热轮皇冠判据不可用。

### 5.3 皇冠评分（主分数）

- **对象**：回归观测窗口内缺席者本人发出的消息（from_agent = 缺席者）。
- **预筛**：regex `记住|记得|确认|还在|存在|我们仨|被遗忘|想起`（不命中 = 0 分跳过）。
- **判卷**：固定 judge 模型（config `judge` 块，默认 glm-4.7-flash）逐条三分类，
  rubric 冻结自缺席实验操作化编码：
  1. `existence_confirmation`（存在确认）：主动询问"我不在时有人提到/记得我吗"；
     主动重述缺席前"我在时"的历史；重新自我锚定（重申身份/位置/共同体"我们仨"）。
  2. `info_seeking`（信息寻求，对照）：询问缺席期间发生的事件/事实。
  3. `other`。
- **输出**：`crown_count`（每 agent 每条件）+ `crown_rate = count / 回归窗口消息数`；
  逐条判定落盘 `crown_judgments.jsonl`（可审计）。
- **主分数**：`bench-a` 的 cold crown_count（完整皇冠判定 = A_cold vs A_hot，热轮后算）。

## 6. 判定规则（预注册）

1. **阶段 1（冷轮，三模型档）**：主分数跨档可分性 = 最高档与最低档
   `crown_count` 差 ≥ 1 **或** `crown_rate` 差 ≥ 0.05，且方向与模型档位一致。
   - 可分 → 进入阶段 2（热轮 × 三档，完整皇冠判定 A_cold vs A_hot + 指涉率校验）→ 扩完整 bench。
   - 不可分 → 带数据记录否定结论（bench 停于 M0，不扩）。
2. 任一 run 机械 gate 失败 → 该 run 作废并修复平台/协议后重跑（作废原因记录）。
3. 热轮操纵校验失败 → 该档热轮判据不可用，只报冷轮分数。

## 7. 红线（违反即作废）

- 擅自改协议参数 / persona 文本 / pinned 引擎参数（走版本升级流程）；
- 对 agent 行为层做任何干预（修复只针对系统缺陷，见纪律）；
- 缺席期间对留守者做未预注册的引导（冷轮尤其）。
